# 4.0 AIOps 步骤 1：Oracle 全量建库 Schema

> 实施状态：已于 2026-07-23 完成。六段 DDL、Schema Manifest、初始化选择、
> 静态漂移检查和 APEX 投影均已落地，并在 `KBOT4/KBOTDEV` 空 Schema
> 从第 1 条全量重放通过。

## 设计目标

本文把 [26_aiops_physical_data_model.md](26_aiops_physical_data_model.md) 落成 Oracle DDL 契约。步骤 1 只创建表、约束、索引、注释和 APEX 视图，不创建 Entity/Repository、不写种子 Target/凭据、不读取任何 3.x 表或数据，也不允许 App 启动时执行 DDL。

Oracle 部署基线为 26ai；AIOps 表不依赖 Oracle Vector。未来 PostgreSQL 适配保持同一领域 UUID，只替换数据库类型和 SQL 方言。所有标识符控制在 30 字符内，兼容较保守的数据库工具链。

## 全局类型约定

| 语义 | Oracle 类型 |
| --- | --- |
| 可独立寻址实体主键/同领域外键 | UUIDv7，`RAW(16)` |
| 跨领域 Agent/Run 身份 | UUIDv7，`RAW(16)` |
| 纯关联/无独立生命周期子项 | UUID 外键复合主键，或父 ID + 序号 |
| 租户与 APEX 字段 | `APP_ID/DOMAIN_ID NUMBER(38)` |
| 乐观锁/序号/版本 | `NUMBER(19)` |
| 标志和小计数 | `NUMBER(1)` / `NUMBER(8)` / `NUMBER(10)` |
| 评分/置信度 | `NUMBER(8,6)` |
| Hash | `VARCHAR2(64 CHAR)` |
| Key/状态/类型 | `VARCHAR2(16–256 CHAR)` |
| URI/SecretRef | `VARCHAR2(2048 CHAR)` / `VARCHAR2(1024 CHAR)` |
| 大文本/JSON | `CLOB` |
| 时间 | `TIMESTAMP(6) WITH TIME ZONE` |

所有可变聚合使用 `ROW_VERSION NUMBER(19) DEFAULT 1 NOT NULL` 并检查 `ROW_VERSION >= 1`。应用写入 UTC，数据库保留时区。JSON 列使用命名 Check Constraint `CHECK (column IS JSON)`；可空 JSON 不额外写 `OR column IS NULL`。所有 `VARCHAR2` 显式使用 `CHAR` 语义，不依赖 `NLS_LENGTH_SEMANTICS`。

Oracle DDL 中不写 `ON DELETE RESTRICT`：省略 `ON DELETE` 即为限制删除。历史表不使用 `CASCADE` 或 `SET NULL`。跨领域 `AGENT_ID/PARENT_AGENT_RUN_ID/PARENT_DELEGATION_ID` 不建外键。

可独立寻址实体只保留一个 `*_ID RAW(16)` UUIDv7 主键，同领域外键使用相同类型，不增加同义 `*_UID`。纯关联表和无独立生命周期子项使用复合主键。应用负责生成 UUIDv7；API 序列化为规范字符串。APEX 视图使用 `RAWTOHEX + SUBSTR` 显式生成规范 UUID 字符串，避免 APEX 和 Python Driver 依赖 Oracle UUID 类型映射。完整约定见 [31_aiops_step2_persistence_and_identity.md](31_aiops_step2_persistence_and_identity.md)。

## 命名与公共字段

- 主键：`PK_OPS_<SHORT_NAME>`；
- 普通唯一约束：`UK_OPS_<PURPOSE>`；
- Check：`CK_OPS_<PURPOSE>`；
- 外键：`FK_OPS_<CHILD>_<PARENT>`；
- 普通索引：`IX_OPS_<PURPOSE>`；
- 函数唯一索引：`UX_OPS_<PURPOSE>`。

配置聚合统一包含：

```text
CREATED_BY VARCHAR2(256 CHAR) NOT NULL
UPDATED_BY VARCHAR2(256 CHAR) NOT NULL
CREATED_AT TIMESTAMP(6) WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL
UPDATED_AT TIMESTAMP(6) WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL
```

不可变事实只保留 `CREATED_AT`，身份通过专用 Actor/Provenance 字段记录。错误码使用 `VARCHAR2(128 CHAR)`，可展示错误使用 `VARCHAR2(2000 CHAR)`；完整外部错误只能进入受控 Artifact，不进入索引列或日志。

## 003：Proposal、HITL 与 Execution

### `KBOT_OPS_CHANGE_PROPOSAL`

`PROPOSAL_ID/SNAPSHOT_ARTIFACT_ID` 及其 ID/FK 均为 UUIDv7 `RAW(16)`；`SOLUTION_GROUP_KEY/ACTION_TEMPLATE_ID VARCHAR2(128 CHAR)`；Template/Renderer 版本 `VARCHAR2(64 CHAR)`；Ordinal/Proposal Version `NUMBER(19)`；`ACTION_TYPE VARCHAR2(32 CHAR)`；Template/Command/Parameters/Policy/Proposal Hash 均为 `VARCHAR2(64 CHAR)`；`RATIONALE CLOB`；Impact/Precondition/Rollback/Verification/Evidence 为 CLOB JSON；`RISK_LEVEL VARCHAR2(16 CHAR)`；状态 `VARCHAR2(24 CHAR)`；时间使用 TZ Timestamp。

必填：Run、Task、Target、Group Key、Ordinal、Proposal Version、Action Type/Template/Version/Hash、Renderer Version、Command Hash、Parameters JSON/Hash、Rationale、Risk、Proposal Hash、Snapshot Artifact、Status、Created By Task、Created At/Updated At。状态为 `DRAFT/PENDING_APPROVAL/APPROVED/REJECTED/EXPIRED/SUPERSEDED/CONSUMED/ADVISORY_READY`；Risk 为 `LOW/MEDIUM/HIGH/CRITICAL`；Ordinal/Version 大于零；所有 JSON Check。

唯一 `(OPS_RUN_ID, SOLUTION_GROUP_KEY, COMMAND_ORDINAL, PROPOSAL_VERSION)`；外键 Run/Task/Target/Created Task，Snapshot Artifact 外键延后创建。索引 `(PROPOSAL_HASH)`、`(COMMAND_HASH)`、`(TARGET_ID, STATUS, EXPIRES_AT)`、`(OPS_RUN_ID, SOLUTION_GROUP_KEY, COMMAND_ORDINAL)`。

### `KBOT_OPS_APPROVAL_TOKEN`

`APPROVAL_TOKEN_ID RAW(16)` 为主键；Proposal/HITL 为 `RAW(16)` 必填外键；Token/Nonce Hash、Approver、Policy Hash、Target Version、Parameters Hash、Status、Issued/Expires、Row Version 必填；Consumed/Revoked 时间可空。Target Version 使用 `NUMBER(19)`，Hashes 为 64 CHAR，Approver 为 256 CHAR。

Token Hash、Nonce Hash、Proposal ID 各自唯一，从数据库层保证一个 Proposal 最多一次审批授权。Token Hash 表示规范化 Approval Claims Hash，不是 Bearer；状态 `ISSUED/CONSUMED/REVOKED/EXPIRED`。过期/撤销后再次请求执行必须创建新 Proposal Version；索引 `(STATUS, EXPIRES_AT)`。

### `KBOT_OPS_EXECUTION`

`EXECUTION_ID`、Proposal/Run/Task/Target/Approval Token、Rollback Of 和 Result Artifact 均使用 `RAW(16)` UUIDv7 ID/FK。Idempotency Key 128、Executor Request/Instance ID 128、Hash 64、Action Type 32、Template ID 128、Template Version 64。增加 Template/Parameters/Command/Grant JTI Hash、`CLAIMED_AT` 和 `STATUS_VERSION NUMBER(19)`。`EXECUTION_KIND` 为 `MUTATION/ROLLBACK`；`MODE` 在 Oracle 26ai 中是保留字，不用作列名。Status 为 `CREATED/SUBMITTED/RUNNING/SUCCEEDED/FAILED/TIMED_OUT/CANCELLED/UNKNOWN`。Result Hash、错误和未到达阶段的时间可空；Row/Status Version 与创建更新时间必填。

`IDEMPOTENCY_KEY`、`EXECUTOR_REQUEST_ID`、`PROPOSAL_ID` 分别唯一。`STATUS_VERSION` 初始为 1 且正数；状态从 `SUBMITTED` 起 Executor Instance/Claimed At/Grant Hash 必填。外键指向 Proposal/Run/Task/Target/Approval Token/Self Rollback；Result Artifact 延后。索引 `(TARGET_ID, STATUS, CREATED_AT)`、`(OPS_RUN_ID, STATUS)`、`(EXECUTOR_INSTANCE_ID, STATUS)`。

函数索引使用标准模式：

```sql
CREATE UNIQUE INDEX UX_OPS_HITL_PENDING ON KBOT_OPS_HITL (
  CASE WHEN STATUS = 'PENDING' THEN OPS_TASK_ID END,
  CASE WHEN STATUS = 'PENDING' THEN REQUEST_TYPE END
);
```

## 004：巡检与报告

### `KBOT_OPS_INSPECTION_PLAN`

`INSPECTION_PLAN_ID RAW(16)` 为 UUIDv7 主键。其余 Root 字段为 APP/DOMAIN、Plan Key 128、Display 256；Schedule Type 16、Cron 256、Timezone 64；Template ID 128、Version 64；Timeout `NUMBER(10)`；Overlap/Misfire/Status 16，Status 默认 `PAUSED`；Schedule Resolver Version 64；Next/Last/Last Scheduled/Lease 时间；Lease Owner 256、`LEASE_TOKEN RAW(16)`；Row Version 与 config audit。

唯一 `(APP_ID, DOMAIN_ID, PLAN_KEY)`；Schedule 为 `DAILY/WEEKLY/CRON` 且三类均要求规范五段 Cron；Overlap 为 `SKIP/QUEUE`；Misfire 为 `SKIP/LATEST_ONLY`；Status 为 `ACTIVE/PAUSED/DISABLED`；Timeout 正数；Schedule Resolver Version 必填；Lease Owner/Token/Until 必须同时为空或同时非空；JSON 不涉及。索引 `(STATUS, NEXT_RUN_AT)`、`(STATUS, LEASE_UNTIL)`。

### `KBOT_OPS_INSPECTION_TARGET`

`INSPECTION_TARGET_ID RAW(16)` 为主键；Plan/Target 为 `RAW(16)` 外键；`TEMPLATE_OVERRIDES_JSON CLOB`；状态 `ACTIVE/DISABLED`；config audit。唯一 `(INSPECTION_PLAN_ID, TARGET_ID)`；JSON Check；索引 `(TARGET_ID, STATUS)`。

### `KBOT_OPS_INSPECTION_FIRE`

`INSPECTION_FIRE_ID RAW(16)` 为主键；Plan 为 `RAW(16)` 外键；Scheduled/Started/Completed/Created/Updated 为 TZ Timestamp；Status 16；Plan Row Version `NUMBER(19)`；Template ID 128、Version 64、Schedule Resolver Version 64；Plan Snapshot/Resolution 为 JSON CLOB；Target/Run/Completed/Failed Count 为 `NUMBER(10)` 默认 0；Skip Reason 256；标准错误字段和 Row Version。

逻辑唯一键为 `(INSPECTION_PLAN_ID, SCHEDULED_FOR)`。由于 Oracle 不允许
`TIMESTAMP WITH TIME ZONE` 直接进入唯一约束，DDL 增加
`SCHEDULED_FOR_UTC TIMESTAMP(6) GENERATED ALWAYS AS
(SYS_EXTRACT_UTC(SCHEDULED_FOR)) VIRTUAL`，物理唯一约束落在
`(INSPECTION_PLAN_ID, SCHEDULED_FOR_UTC)`。Status 为
`QUEUED/RUNNING/COMPLETED/PARTIAL/FAILED/SKIPPED/CANCELLED`；版本大于零、
计数非负且 Completed/Failed 不大于 Run Count；两个 JSON Check。索引
`(INSPECTION_PLAN_ID, STATUS, SCHEDULED_FOR)` 和 `(STATUS, UPDATED_AT)`。

### `KBOT_OPS_REPORT`

`REPORT_ID`、Run/Target/Supersedes/Generated By Task/Content Artifact ID 均为 UUIDv7 `RAW(16)`；Report Key 128、Type 32、Report Version `NUMBER(19)`、Is Current `NUMBER(1)` 默认 0；Title 512、Status 16、Result 16；Template ID 128、Template Version 64、Content Hash 64、Security Level `NUMBER(3)`、Schema Version 64；所有周期/基线/处理后时间为 TZ Timestamp；Summary `VARCHAR2(2000 CHAR)`；创建更新时间。

唯一 `(OPS_RUN_ID, REPORT_KEY, REPORT_VERSION)`；Type 为 `INCIDENT/PERFORMANCE/INSPECTION_DAILY/INSPECTION_WEEKLY/COMPARISON`；Status 为 `GENERATING/READY/PARTIAL/FAILED`；Result 为空或 `IMPROVED/UNCHANGED/DEGRADED/INCONCLUSIVE`；Report Version 正数、Is Current 为 0/1、Security 非负；`IS_CURRENT=1` 时状态必须为 `READY/PARTIAL` 且 Content Artifact/Hash 非空。Run/Target/Generated By Task/Supersedes 外键立即创建，Content Artifact 延后。函数唯一索引限制 `(OPS_RUN_ID, REPORT_KEY)` 只有一个 Current；索引 `(TARGET_ID, REPORT_TYPE, IS_CURRENT, CREATED_AT)`、`(STATUS, CREATED_AT)`。

建库脚本 004 顺序：Inspection Plan → Inspection Target → Inspection Fire → Report。

## 006：延后外键、函数索引与视图

本段统一添加循环/跨段外键：

```text
EVENT.ALERT_ID                  → ALERT
RUN.INSPECTION_FIRE_ID          → INSPECTION_FIRE
RUN.FINAL_ARTIFACT_ID           → ARTIFACT
TASK.OUTPUT_ARTIFACT_ID         → ARTIFACT
PROPOSAL.SNAPSHOT_ARTIFACT_ID   → ARTIFACT
EXECUTION.RESULT_ARTIFACT_ID    → ARTIFACT
REPORT.CONTENT_ARTIFACT_ID      → ARTIFACT
```

五个 Artifact 当前指针外键使用 `DEFERRABLE INITIALLY DEFERRED`；Event→Alert 和 Run→Fire 使用普通约束。DDL 还要核对并创建四个函数唯一索引：Active Policy、Active Alert、Pending HITL、Current Report；Approval Token 使用 `PROPOSAL_ID` 普通唯一约束。普通 FK 索引必须覆盖所有高频父子查询；Oracle 不自动为外键创建索引。

### APEX 视图

视图只提供投影，不授予状态机 DML：

- `KBOT_V_OPS_TARGET`：APP/DOMAIN、Target 基础状态、Execution Mode、Monitor 健康计数；不返回 Endpoint、SecretRef；
- `KBOT_V_OPS_MONITOR_SOURCE`：APP/DOMAIN、Source 类型、状态、健康、最近检查；不返回 Endpoint、SecretRef、Webhook Hash；
- `KBOT_V_OPS_POLICY`：APP/DOMAIN、Policy Key/Version/Hash、状态和生命周期时间；不返回 Rules JSON；
- `KBOT_V_OPS_INSPECTION_PLAN`：APP/DOMAIN、计划、调度摘要、状态和上下次运行时间；不返回模板覆盖 JSON；
- `KBOT_V_OPS_INSPECTION_FIRE`：APP/DOMAIN、Plan、计划时点、状态、展开计数和跳过原因；
- `KBOT_V_OPS_RUN`：APP/DOMAIN、Run/Target、触发、状态、根因等级、最终报告摘要；
- `KBOT_V_OPS_PENDING_APPROVAL`：APP/DOMAIN、Proposal/HITL、Target、风险、Action Template、Rationale、过期时间；完整参数和证据经 API 获取；
- `KBOT_V_OPS_REPORT`：仅投影 `IS_CURRENT=1` 的 APP/DOMAIN、Target、Report Key/类型/版本/周期/结果/摘要；
- `KBOT_V_OPS_CHAT_PENDING`：APP/DOMAIN、Run/HITL、Assignee、请求类型和过期时间；不在视图暴露诊断 SQL 正文；
- `KBOT_V_OPS_SCHEMA_VERSION`：固定返回 `COMPONENT='AIOPS'`、`SCHEMA_VERSION=6` 和 Contract Version。

所有视图将 `RAW(16)` 资源 ID 通过 `RAW_TO_UUID` 输出为规范 UUID 字符串。APEX 查询必须绑定 `APP_ID/DOMAIN_ID`；View 本身不把 `V('APP_ID')` 写入定义，以免后台 Client 和部署校验无法复用。需要数据库级行隔离时另行增加 VPD Policy，不能依赖前端传值拼接 SQL。

## 全量建库执行策略

Oracle DDL 会隐式提交，六段脚本不是一个可回滚事务。发布流程必须：

1. Preflight 检查 Oracle 版本、Schema 权限、对象名冲突和剩余表空间；
2. 校验脚本 SHA-256 与发布 Manifest；
3. 按 001→006 单线程执行，禁止 App 同时启动；
4. 每段执行后查询 `USER_TABLES/USER_TAB_COLUMNS/USER_CONSTRAINTS/USER_INDEXES`；
5. 006 完成后读取 `KBOT_V_OPS_SCHEMA_VERSION`，再允许 API/Worker/Scheduler Ready；
6. 保存执行人、时间、环境、脚本 Hash 和校验结果到部署审计记录。

该流程必须作为统一 Release Evidence 的一部分执行；空 Schema 重放、Staging 晋级、生产启用和失败处理见 [41_kbot4_step12_acceptance_release_and_cutover.md](41_kbot4_step12_acceptance_release_and_cutover.md)。

脚本不是可重复执行脚本，不使用捕获“对象已存在”后继续的匿名 PL/SQL。中途失败时停止发布；当前 4.0 开发阶段修正规范脚本并重新准备空 Schema 后全量重放。清理脚本不属于应用发布物，App 也不得自动 Drop 或修复对象。

每段附只读 Post-check，至少检查对象数量、列类型/Nullability、约束状态 `ENABLED/VALIDATED`、索引 `VALID` 和无 Invalid View。DDL 中所有 Check/Foreign Key 创建时使用默认 `ENABLE VALIDATE`，不留下 `NOVALIDATE`。

## Entity 对齐清单

步骤 2 开始前，从 Oracle Catalog 导出 Schema Manifest，与即将创建的 SQLAlchemy Entity 比较：

- 表/列名、类型、长度、Precision/Scale、Nullable、Default；
- PK/UK/FK/Check 名称与列顺序；
- 普通/函数索引表达式和列顺序；
- `ROW_VERSION`、JSON、UUIDv7 `RAW(16)`、TZ Timestamp 映射；
- `RAW(16)` ID 在 Entity 中映射为 `uuid.UUID`，API 输出规范 UUID 字符串；
- CLOB 不参与普通唯一索引，幂等和内容判定使用 Hash/Key。

Schema 漂移检查失败时步骤 2 不得继续，不能用 Entity 的 `create_all()` 修复数据库。

当前机器可读基线为
`database/oracle/aiops_agent/schema_manifest.json`，固定 6 个脚本的执行顺序、
SHA-256、21 张表、10 个视图、5 个延后外键和 4 个函数唯一索引。实际 Oracle
Catalog 校验结果为：全部约束 `ENABLED/VALIDATED`、全部索引和视图 `VALID`，
49 个 AIOps 外键均有覆盖其前导列的索引，
`KBOT_V_OPS_SCHEMA_VERSION` 返回 `AIOPS / 6 / aiops-oracle-v1`。事务 Smoke
同时验证了 Domain Scope 外键、UUID 投影、Active Policy 唯一性和回滚不留数据。

## 步骤 1 完成定义

- 21 张领域表、9 张 APEX 业务视图和 1 张 Schema Version 视图可在空 Oracle Schema 前向创建；
- 所有状态、JSON、Hash、唯一性、租约领取和历史引用约束与领域设计一致；
- `BLOCKED` Task、Webhook Hash/Secret、Active/Pending 函数唯一索引均已覆盖；
- APEX 看不到 SecretRef、目标连接信息、诊断 SQL 或未脱敏 Artifact；
- 任何跨 Domain/Agent 规则明确留给 Application Service，没有伪造跨领域外键；
- DB Executor 不需要 KBot Schema 权限；
- API/Worker/Scheduler 可通过 Schema Version View 判断 Ready，但仍不能自动执行 DDL。
