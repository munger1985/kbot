# 4.0 AIOps 物理数据模型

## 通用约定

- 所有可独立寻址领域实体的主键和同领域外键使用 UUIDv7；Oracle 以 `RAW(16)` 保存，API 使用规范 UUID 字符串；
- 不为同一资源并存数字 PK 与 `*_UID`；`APP_ID/DOMAIN_ID`、序号、版本和计数仍使用数值；
- 纯关联表使用端点 UUID 的复合主键；无独立生命周期的顺序子项使用父 ID + 序号；
- 时间使用 `TIMESTAMP(6) WITH TIME ZONE`，应用契约中统一 UTC；
- Hash/Fingerprint 使用 64 位小写十六进制字符串；
- 可变聚合使用 `ROW_VERSION NUMBER(19)` 乐观锁；
- JSON 使用 CLOB + `IS JSON` 约束，大数据使用 URI + Hash；
- 不保存数据库密码或 Monitor Token，只保存 `SECRET_REF`；
- 外键默认 `ON DELETE RESTRICT`，不对历史运维数据级联删除；
- `CREATED_BY/UPDATED_BY VARCHAR2(256)` 和创建/更新时间在可变配置表上统一使用；不可变事实只保存 `CREATED_AT`。

`APP_ID/DOMAIN_ID` 只存在无上级领域根的 `TARGET`、`MONITOR_SOURCE`、`POLICY` 和 `INSPECTION_PLAN`。其他表通过 Target/Run/Plan 外键继承边界，不重复存储可产生不一致的 scope 字段。APEX 通过受控视图 join 根表进行 `APP_ID/DOMAIN_ID` 过滤。

## 资产、监控与策略

### `KBOT_OPS_TARGET`

```text
TARGET_ID, APP_ID, DOMAIN_ID, TARGET_KEY, DISPLAY_NAME
DB_TYPE                     # 首期 ORACLE/MYSQL，由 Dialect Registry 校验
VERSION_CODE, ENVIRONMENT: PROD | STG | DEV
DB_ROLE: PRIMARY | STANDBY | UNKNOWN
ENDPOINT_JSON
DIAGNOSTIC_SECRET_REF, EXECUTION_SECRET_REF
EXECUTION_MODE: ADVISORY | AGENT_EXECUTE
SECURITY_LEVEL, CAPABILITIES_JSON
STATUS: ACTIVE | MAINTENANCE | DISABLED
HEALTH_STATUS: UNKNOWN | HEALTHY | DEGRADED | UNREACHABLE
LAST_HEALTH_CHECK_AT, LAST_ERROR_CODE
ROW_VERSION, HEALTH_VERSION + audit fields
```

唯一约束 `(APP_ID, DOMAIN_ID, TARGET_KEY)`。主索引：`(APP_ID, DOMAIN_ID, STATUS, DISPLAY_NAME)` 和 `(DB_TYPE, STATUS)`。新 Target 默认 `MAINTENANCE/UNKNOWN`；管理状态与健康状态独立变化。`ENDPOINT_JSON` 可空，表示只通过监控系统观测。`DB_TYPE` 不建静态 Check Constraint，由已注册 `DatabaseDialect` 强校验，新增数据库时不需要修改根表 DDL。

### `KBOT_OPS_TARGET_BINDING`

```text
BINDING_ID, TARGET_ID, AGENT_ID             # 均为 UUIDv7 RAW(16)
ACCESS_MODE: OBSERVE | DIAGNOSE | PROPOSE | EXECUTE
POLICY_ID, ALLOWED_ACTIONS_JSON, CHANGE_WINDOW_JSON
MAX_DAILY_EXECUTIONS
STATUS: ACTIVE | REVOKED
ROW_VERSION + audit fields
```

`ACCESS_MODE` 是累积权限，`EXECUTE` 包含前三级但不绕过审批。`BINDING_ID` 是单一主键，另有唯一约束 `(TARGET_ID, AGENT_ID)`；索引 `(AGENT_ID, STATUS, ACCESS_MODE)`。绑定的 Agent 必须属于同一 Domain，由 Application Service 跨领域校验，不对 Agent 领域表建外键。

### `KBOT_OPS_MONITOR_SOURCE`

```text
MONITOR_SOURCE_ID, APP_ID, DOMAIN_ID
SOURCE_KEY, DISPLAY_NAME
SOURCE_TYPE                 # 首期 PROMETHEUS/ZABBIX/OEM
ENDPOINT, SECRET_REF, WEBHOOK_SECRET_REF, TLS_PROFILE_REF
WEBHOOK_KEY_HASH            # 当前外部 Webhook 不透明路由键的 Hash
PREVIOUS_WEBHOOK_KEY_HASH, PREVIOUS_WEBHOOK_KEY_EXPIRES_AT
CAPABILITIES_JSON
STATUS: ACTIVE | DISABLED
HEALTH_STATUS: UNKNOWN | HEALTHY | DEGRADED | UNREACHABLE
HEALTH_CHECK_REQUEST_ID, HEALTH_CHECK_REQUESTED_AT
LAST_HEALTH_CHECK_AT, LAST_ERROR_CODE
ROW_VERSION, HEALTH_VERSION + audit fields
```

唯一约束 `(APP_ID, DOMAIN_ID, SOURCE_KEY)`，Current/Previous Webhook Hash 非空时必须唯一；`ENDPOINT` 与当前 `WEBHOOK_KEY_HASH` 至少一个非空，以允许仅 Webhook 的来源；新 Source 默认 `DISABLED/UNKNOWN`；索引 `(APP_ID, DOMAIN_ID, SOURCE_TYPE, STATUS)`。`SOURCE_TYPE` 由 Monitor Adapter Registry 校验，不建只包含首期三种 Provider 的静态 Check Constraint。不在此表保存 Target 在监控系统中的外部 ID。Webhook Key 只在创建/轮换时显示一次，数据库保存 Hash；Previous Hash 仅在有限轮换窗口内有效。拉取监控数据的凭据使用 `SECRET_REF`，Provider Webhook 签名密钥使用独立的 `WEBHOOK_SECRET_REF`。

### `KBOT_OPS_TARGET_MONITOR`

```text
TARGET_MONITOR_ID, TARGET_ID, MONITOR_SOURCE_ID
EXTERNAL_TARGET_KEY
ROLE: PRIMARY | SUPPLEMENTARY
PRIORITY, METRIC_SCOPE_JSON, MAPPING_OVERRIDES_JSON
STATUS: ACTIVE | DISABLED
HEALTH_STATUS: UNKNOWN | HEALTHY | DEGRADED | UNREACHABLE
LAST_HEALTH_CHECK_AT, LAST_ERROR_CODE
ROW_VERSION, HEALTH_VERSION + audit fields
```

`TARGET_MONITOR_ID` 是单一主键，另有唯一约束 `(MONITOR_SOURCE_ID, EXTERNAL_TARGET_KEY)`，保证一个外部监控对象只能映射一个 Target；同一 Target 可绑定该 Source 下多个不同对象。索引 `(TARGET_ID, STATUS, PRIORITY)` 和 `(MONITOR_SOURCE_ID, STATUS)`。Target 与 Monitor Source 必须属于同一 Domain，由绑定用例校验。

### `KBOT_OPS_POLICY`

```text
POLICY_ID, APP_ID, DOMAIN_ID
POLICY_KEY, VERSION_NO, DISPLAY_NAME
RULES_JSON, POLICY_HASH
STATUS: DRAFT | ACTIVE | RETIRED
EFFECTIVE_AT, RETIRED_AT
ROW_VERSION, CREATED_BY, CREATED_AT, UPDATED_BY, UPDATED_AT
```

唯一约束 `(APP_ID, DOMAIN_ID, POLICY_KEY, VERSION_NO)`。使用 Oracle function-based unique index 限制每个 scope/key 只有一个 `ACTIVE` 版本。已被 Run Snapshot 引用的版本不覆盖和删除。

## 触发、告警与运行

### `KBOT_OPS_EVENT`

保存外部监控事件，不用于 SSE。

```text
EVENT_ID, TARGET_ID, MONITOR_SOURCE_ID, ALERT_ID, SOURCE_INBOX_ID
SOURCE_EVENT_KEY, EVENT_TYPE, SEVERITY
EVENT_STATUS: FIRING | RESOLVED | INFORMATIONAL
OCCURRED_AT, RECEIVED_AT
FINGERPRINT, PAYLOAD_JSON, PAYLOAD_URI, PAYLOAD_HASH
NORMALIZER_VERSION
PROCESSING_STATUS: RECEIVED | CORRELATED | IGNORED | FAILED
TRACE_ID, CREATED_AT
```

唯一约束 `(MONITOR_SOURCE_ID, SOURCE_EVENT_KEY)`。每个 Adapter 必须生成非空稳定 `SOURCE_EVENT_KEY`，没有外部 ID 时使用标准化内容 Hash。`SOURCE_INBOX_ID` 是已验签原始 Delivery 的软审计关联，因 Inbox 保留期更短而不建外键；非 Webhook 采集可为空。Normalizer Version 必填。索引 `(TARGET_ID, OCCURRED_AT)`、`(PROCESSING_STATUS, RECEIVED_AT)` 和 `(TARGET_ID, FINGERPRINT, EVENT_STATUS)`。

Adapter 将原始等级映射为 `INFO/WARNING/HIGH/CRITICAL`，原值保留在 Payload。

### `KBOT_OPS_ALERT`

```text
ALERT_ID, TARGET_ID, FINGERPRINT
STATUS: OPEN | ACKNOWLEDGED | SUPPRESSED | RESOLVED | CLOSED
SEVERITY, SUMMARY, CORRELATION_JSON
FIRST_SEEN_AT, LAST_SEEN_AT, RESOLVED_AT
EVENT_COUNT, ROW_VERSION
CREATED_AT, UPDATED_AT
```

不存储 `ACTIVE_OPS_RUN_ID`，避免 Alert/Run 循环外键；通过 `RUN.TRIGGER_ALERT_ID` 和活跃状态查询当前 Run。使用 function-based unique index 限制同一 `(TARGET_ID, FINGERPRINT)` 同时只有一个 `OPEN/ACKNOWLEDGED/SUPPRESSED`。索引 `(TARGET_ID, STATUS, SEVERITY, LAST_SEEN_AT)`。

### `KBOT_OPS_RUN`

```text
OPS_RUN_ID, TARGET_ID, AGENT_ID
PARENT_AGENT_RUN_ID                         # Agent Run UUIDv7 RAW(16)
PARENT_DELEGATION_ID                        # Agent Delegation UUIDv7 RAW(16)
TRIGGER_TYPE: CHAT | ALERT | SCHEDULE | API | IM | EMAIL
TRIGGER_EVENT_ID, TRIGGER_ALERT_ID, INSPECTION_FIRE_ID
ACTOR_ID, ORIGINAL_REQUEST, IDEMPOTENCY_KEY
STATUS: CREATED | SCOPING | OBSERVING | DIAGNOSING |
        WAITING_INPUT | DIAGNOSED | PROPOSING |
        WAITING_APPROVAL | EXECUTING | VERIFYING |
        ROLLBACK_PENDING | COMPLETED | DEGRADED | REJECTED |
        FAILED | CANCELLED | EXPIRED
PLAN_SNAPSHOT_JSON, POLICY_SNAPSHOT_JSON
ROOT_CAUSE_LEVEL, FINAL_ARTIFACT_ID
DEADLINE_AT, CANCEL_REQUESTED_AT, CANCEL_REQUESTED_BY
ERROR_CODE, ERROR_MESSAGE
TRACE_ID, ROW_VERSION
CREATED_AT, STARTED_AT, COMPLETED_AT, UPDATED_AT
```

唯一约束 `(TARGET_ID, TRIGGER_TYPE, ACTOR_ID, IDEMPOTENCY_KEY)`、非空 `PARENT_DELEGATION_ID` 和 `(INSPECTION_FIRE_ID, TARGET_ID)`；最后一项在 Fire ID 为空时不影响非巡检 Run。Parent Agent Run/Delegation 必须同时为空或同时非空。索引 `(TARGET_ID, STATUS, CREATED_AT)`、`(AGENT_ID, STATUS, CREATED_AT)`、`(PARENT_AGENT_RUN_ID)`、`(TRIGGER_ALERT_ID, STATUS)` 和 `(INSPECTION_FIRE_ID, STATUS)`。`FINAL_ARTIFACT_ID` 的外键在 Artifact 表建立后增加为 `DEFERRABLE INITIALLY DEFERRED`。

`ROOT_CAUSE_LEVEL` 为空或 `CONFIRMED/PROBABLE/POSSIBLE/INCONCLUSIVE`。`IM/EMAIL` 为预留 Trigger Type，4.0 不实现对应 Adapter。

### `KBOT_OPS_TASK`

```text
OPS_TASK_ID, OPS_RUN_ID, PARENT_TASK_ID, TASK_KEY
TASK_TYPE: SCOPE | OBSERVE | DIAGNOSE | REQUEST_INPUT |
           PROPOSE | APPROVE | EXECUTE | VERIFY |
           ROLLBACK | COMPARE | REPORT
HANDLER_ID, HANDLER_VERSION
INPUT_SCHEMA_VERSION, OUTPUT_SCHEMA_VERSION
DEPENDS_ON_JSON, INPUT_ARTIFACTS_JSON
OUTPUT_ARTIFACT_ID
STATUS: PENDING | READY | BLOCKED | RUNNING | WAITING_INPUT |
        WAITING_APPROVAL | RETRY_WAIT | SUCCEEDED |
        FAILED | CANCELLED | EXPIRED
PRIORITY, AVAILABLE_AT
ATTEMPT_COUNT, MAX_ATTEMPTS, TIMEOUT_SECONDS
LEASE_OWNER, LEASE_TOKEN, LEASE_UNTIL, HEARTBEAT_AT
STARTED_AT, COMPLETED_AT
ERROR_CODE, ERROR_MESSAGE, ROW_VERSION
CREATED_AT, UPDATED_AT
```

唯一约束 `(OPS_RUN_ID, TASK_KEY)`。领取索引 `(STATUS, AVAILABLE_AT, PRIORITY)`，租约索引 `(STATUS, LEASE_UNTIL)`，Run 查询索引 `(OPS_RUN_ID, STATUS)`。任务图由受限 Planner 创建，`DEPENDS_ON_JSON` 只保存同 Run 的 `TASK_KEY`，由 Application Service 检查无环和引用存在。

### `KBOT_OPS_ARTIFACT`

```text
ARTIFACT_ID, OPS_RUN_ID, OPS_TASK_ID, ARTIFACT_KEY
ARTIFACT_TYPE, SCHEMA_VERSION
PAYLOAD_JSON, PAYLOAD_URI, CONTENT_HASH, BYTE_SIZE
PROVENANCE_JSON
TRUST_LEVEL: SOURCE_VERIFIED | USER_PROVIDED |
             KNOWLEDGE_CITATION | MODEL_INFERENCE
SECURITY_LEVEL, CREATED_AT
```

Artifact 不可变，不包含 `UPDATED_AT`。约束 Payload JSON/URI 至少一个非空；唯一约束 `(OPS_RUN_ID, ARTIFACT_KEY)` 防止同一逻辑产物因重试重复写入，不会错误合并来自不同 Task 但内容相同的观测。`ARTIFACT_KEY` 由用例使用 `task_key + output_name + revision` 等稳定输入构造，不使用随机值。索引 `(OPS_RUN_ID, ARTIFACT_TYPE, CREATED_AT)`、`(OPS_TASK_ID)` 和 `CONTENT_HASH`。

### `KBOT_OPS_RUN_EVENT`

保存 Ops Run 状态流和 SSE 投影，与外部 `KBOT_OPS_EVENT` 分离。

```text
OPS_RUN_ID, SEQUENCE_NO                     # 复合主键
OPS_TASK_ID, EVENT_TYPE, EVENT_KEY
VISIBILITY: INTERNAL | USER
PAYLOAD_JSON, CREATED_AT
```

复合主键 `(OPS_RUN_ID, SEQUENCE_NO)`；有值的 `(OPS_RUN_ID, EVENT_KEY)` 唯一；SSE 索引 `(OPS_RUN_ID, VISIBILITY, SEQUENCE_NO)`。事件只追加；`SEQUENCE_NO` 通过锁定 Run/Sequence allocator 获取，不使用进程内计数器。

## 变更、人工节点与执行

### `KBOT_OPS_CHANGE_PROPOSAL`

```text
PROPOSAL_ID, OPS_RUN_ID, OPS_TASK_ID, TARGET_ID
SOLUTION_GROUP_KEY, COMMAND_ORDINAL, PROPOSAL_VERSION
ACTION_TYPE, ACTION_TEMPLATE_ID, ACTION_TEMPLATE_VERSION
ACTION_TEMPLATE_HASH, RENDERER_VERSION, COMMAND_HASH
PARAMETERS_JSON, PARAMETERS_HASH
RATIONALE, IMPACT_SCOPE_JSON, RISK_LEVEL
PRECONDITIONS_JSON, ROLLBACK_PLAN_JSON, VERIFICATION_PLAN_JSON
EVIDENCE_ARTIFACTS_JSON, POLICY_DECISION_HASH, PROPOSAL_HASH
SNAPSHOT_ARTIFACT_ID
STATUS: DRAFT | PENDING_APPROVAL | APPROVED | REJECTED |
        EXPIRED | SUPERSEDED | CONSUMED | ADVISORY_READY
EXPIRES_AT, CREATED_BY_TASK_ID, CREATED_AT, UPDATED_AT
```

唯一约束 `(OPS_RUN_ID, SOLUTION_GROUP_KEY, COMMAND_ORDINAL, PROPOSAL_VERSION)`。`PROPOSAL_HASH` 不全局唯一，因为不同 Run 可合法产生相同命令；对它建普通索引用于审计对比。其他索引为 `(TARGET_ID, STATUS, EXPIRES_AT)` 和 `(OPS_RUN_ID, SOLUTION_GROUP_KEY, COMMAND_ORDINAL)`。Proposal 内容不覆盖，状态可迁移；修改命令必须新建版本。`SNAPSHOT_ARTIFACT_ID` 指向包含权威命令预览、Hash、参数来源和验证计划的不可变 Artifact，外键延后创建。

### `KBOT_OPS_HITL`

```text
HITL_ID, OPS_RUN_ID, OPS_TASK_ID, PROPOSAL_ID
REQUEST_TYPE: DATA_REQUIRED | MANUAL_DIAGNOSTIC_SQL |
              MANUAL_ACTION_RESULT | CHANGE_APPROVAL
ASSIGNEE_USER_ID, PROMPT_TEXT, RESPONSE_SCHEMA_JSON
INPUT_ARTIFACTS_JSON
RESPONSE_JSON, RESPONSE_URI, RESPONSE_HASH
STATUS: PENDING | ANSWERED | APPROVED | REJECTED |
        EXPIRED | CANCELLED
IDEMPOTENCY_KEY, REQUESTED_BY, RESPONDED_BY
REQUESTED_AT, RESPONDED_AT, EXPIRES_AT, ROW_VERSION
```

唯一约束 `(OPS_RUN_ID, IDEMPOTENCY_KEY)`。使用 function-based unique index 限制同一 Task/Request Type 仅一个 `PENDING`。待办查询索引 `(ASSIGNEE_USER_ID, STATUS, EXPIRES_AT)`。Chat 诊断请求的 Assignee 固定为对话用户；Alert/Schedule 不创建 `MANUAL_DIAGNOSTIC_SQL`。

`PROMPT_TEXT` 只保存安全的用户说明，不保存 SQL 或上传正文；完整请求由 `INPUT_ARTIFACTS_JSON` 引用不可变 Artifact。`CANCELLED/EXPIRED` 也保存结构化 Outcome JSON，满足终态响应约束并说明诊断如何收敛。步骤 8 不增加 Upload 表，暂存会话由 `UploadPort` 管理。

### `KBOT_OPS_APPROVAL_TOKEN`

```text
APPROVAL_TOKEN_ID, PROPOSAL_ID, HITL_ID
TOKEN_HASH, NONCE_HASH
APPROVER_ID, POLICY_DECISION_HASH
TARGET_VERSION, PARAMETERS_HASH
STATUS: ISSUED | CONSUMED | REVOKED | EXPIRED
ISSUED_AT, EXPIRES_AT, CONSUMED_AT, REVOKED_AT
ROW_VERSION
```

`TOKEN_HASH/NONCE_HASH/PROPOSAL_ID` 分别唯一，从数据库层保证一个 Proposal 最多一次审批授权。过期、撤销或已消费后不能为同一 Proposal 再签发，重新请求执行必须创建新 Proposal Version，原历史保留。`TOKEN_HASH` 是规范化 Approval Claims Hash，不存在返回前端或落库的明文 Bearer Token。消费使用条件更新 `WHERE STATUS='ISSUED' AND EXPIRES_AT>:now`。

### `KBOT_OPS_EXECUTION`

```text
EXECUTION_ID, PROPOSAL_ID, OPS_RUN_ID, OPS_TASK_ID, TARGET_ID
IDEMPOTENCY_KEY, EXECUTOR_REQUEST_ID
PROPOSAL_HASH, ACTION_TYPE
ACTION_TEMPLATE_ID, ACTION_TEMPLATE_VERSION, ACTION_TEMPLATE_HASH
PARAMETERS_HASH, COMMAND_HASH
MODE: MUTATION | ROLLBACK
APPROVAL_TOKEN_ID
STATUS: CREATED | SUBMITTED | RUNNING | SUCCEEDED |
        FAILED | TIMED_OUT | CANCELLED | UNKNOWN
EXECUTOR_INSTANCE_ID, CLAIMED_AT, GRANT_JTI_HASH, STATUS_VERSION
RESULT_ARTIFACT_ID, RESULT_HASH
ROLLBACK_OF_EXECUTION_ID
STARTED_AT, COMPLETED_AT
ERROR_CODE, ERROR_MESSAGE, ROW_VERSION, CREATED_AT, UPDATED_AT
```

`IDEMPOTENCY_KEY`、`EXECUTOR_REQUEST_ID`、`PROPOSAL_ID` 分别唯一。Mutation/Rollback 必须有 Approval Authorization；Read-only 诊断不进入本表，直接作为 Task Artifact。因此 DDL 中 `MODE` 只允许 `MUTATION/ROLLBACK`。`EXECUTOR_INSTANCE_ID/CLAIMED_AT/GRANT_JTI_HASH` 从 `SUBMITTED` 起必填，`STATUS_VERSION` 从 1 单调递增；跨实例 Claim 或乱序回调不能推进状态。

```text
EVENT_TYPE, IDEMPOTENCY_KEY
PAYLOAD_JSON, PAYLOAD_URI, PAYLOAD_HASH
STATUS: PENDING | PUBLISHING | PUBLISHED | RETRY_WAIT | FAILED
AVAILABLE_AT, ATTEMPT_COUNT, MAX_ATTEMPTS
LEASE_OWNER, LEASE_TOKEN, LEASE_UNTIL
PUBLISHED_AT, ERROR_CODE, ERROR_MESSAGE
TRACE_ID, CREATED_AT, UPDATED_AT
```

`IDEMPOTENCY_KEY` 唯一。领取索引 `(STATUS, AVAILABLE_AT)` 和租约索引 `(STATUS, LEASE_UNTIL)`。Outbox 仅保存交付事实，不替代 `RUN_EVENT` 用户可见流。

## 外键与循环引用

所有子表对 Target/Run/Task/Proposal/Plan/Fire 建立真实外键。`RUN.FINAL_ARTIFACT_ID`、`TASK.OUTPUT_ARTIFACT_ID`、`PROPOSAL.SNAPSHOT_ARTIFACT_ID`、`REPORT.CONTENT_ARTIFACT_ID` 和 `EXECUTION.RESULT_ARTIFACT_ID` 是父对已产生 Artifact 的当前指针：在 Artifact 表创建后由建库脚本的最后一段增加 `DEFERRABLE INITIALLY DEFERRED` 外键，并在同一事务内写入。

不对 `PARENT_AGENT_RUN_ID/PARENT_DELEGATION_ID/AGENT_ID` 创建跨服务表外键，这些是版本化契约引用。Monitor Source/Target、Plan/Target 和 Binding/Agent 的 Domain 一致性在 Application Service + 集成测试中强制。

## APEX 投影

APEX 不直接更新状态机表。提供至少以下只读视图：

- `KBOT_V_OPS_TARGET`：Target + Monitor 健康摘要；
- `KBOT_V_OPS_INSPECTION_FIRE`：Plan 时点、展开计数、状态和跳过原因；
- `KBOT_V_OPS_RUN`：Run、Target、触发和根因/报告摘要；
- `KBOT_V_OPS_PENDING_APPROVAL`：Proposal、影响、风险、命令和证据摘要；
- `KBOT_V_OPS_REPORT`：可按 APP/DOMAIN/Target/类型/时间筛选的报告列表；
- `KBOT_V_OPS_CHAT_PENDING`：当前用户的 Chat 补充数据请求。

每个视图从 Target/Plan/Monitor Source 根表透出 `APP_ID/DOMAIN_ID`。审批、取消、回贴、Target 和 Schedule 更改仍通过 API Command，不让 APEX DML 绕过乐观锁、审计和 Outbox。

## 删除、归档与保留

- Target/Monitor Source/Policy/Inspection Plan 已被 Run 或历史引用后只停用，不硬删除；从未使用且无绑定的草稿配置可删除；
- Run、Proposal、HITL、Approval Token、Execution 和 Report 不级联删除；
- 大型 Monitor/DB/User Result 按 Artifact URI 的保留策略转存/清理，保留 Hash、Provenance 和摘要；
- 已发布 Outbox 和已处理 Inbox 可在可配置窗口后分批清理；
- 默认建议：原始外部 Event Payload 90 天，但被 Alert/Run 引用的 Event 元数据行保留到引用解除；普通 Run/Artifact 180 天、Inbox/Outbox 终态 30 天；变更审批/执行/审计和报告按合规配置长期保留；
- 保留期是部署策略，不写死在 DDL Check Constraint 中。

清理 Worker 必须按 Target/Run 分页、限流并记录审计结果，不使用无边界单事务删除。Oracle 分区是可选优化，不作为 4.0 必需能力，避免强制依赖特定许可。
