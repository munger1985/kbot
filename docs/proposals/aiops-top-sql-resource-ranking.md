# Top SQL 多指标资源排行设计

状态：已实现；Ammolite 与 KBot4 同步。修订日期：2026-11-04。

## 1. 产品范围

复用“Top SQL”快捷功能、自然语言能力目录、冻结计划、Worker、Workload 查询和
TABLE 证据链；不创建另一套排名服务。用户先在 Agent 授权边界内选择业务系统、
数据库 Target（实例连接），再选择时间窗口、排序指标、方向、阈值和 1–50 条返回数量。
默认最近 15 分钟、总耗时降序、10 条。自定义时间必须包含时区，冻结为绝对 UTC 时间。

数据库能力来自服务端指标目录。两端页面按所选数据库过滤选项，切换数据库时移除
不支持的阈值、恢复有效排序；服务端仍再次校验，不能通过直接调用绕过。
自然语言解析器获得同一份参数目录，排序和筛选条件进入冻结 Tool 输入，重试不重算时间。

## 2. 指标与合同

| 数据库 | 可排序指标 | 单位与边界 |
| --- | --- | --- |
| 三库 | 总耗时、平均耗时、执行次数、处理／返回行数 | 秒、秒/执行、次、行 |
| Oracle | CPU、每次 CPU、逻辑读、每次逻辑读、物理读 | 秒、秒/执行、Oracle 块访问、块访问/执行、Oracle 块 |
| PostgreSQL | 共享块访问、共享块读取、临时块读取／写入 | 共享块访问 = shared_blks_hit + shared_blks_read；读取不保证触达物理磁盘 |
| MySQL | 扫描行数、临时磁盘表、锁等待 | 行、表、秒；扫描行数不是逻辑读 |

稳定参数：`rank_metric`、`sort_direction=DESC|ASC`、`min_executions`、
`min_metric_value`、`min_cpu_seconds`、`min_logical_reads`。
后两个阈值当前仅支持 Oracle；多个条件按 AND 联合筛选。所选指标最低值的单位与指标一致。
阈值必须有限、非负；不接受布尔值、NaN、无穷大、任意排序表达式或未知字段。

CPU 不用总耗时估算，不推导 CPU 使用率；MySQL/PostgreSQL 当前来源没有 SQL CPU 时明确拒绝。
缺指标不补零，不以其他指标替换用户所选指标。新 Oracle CPU/读指标需要两个采集了新字段的
可比较快照，旧快照不回填、不从当前累计值推测过去。

## 3. 采集和持久化

Oracle 继续使用当前实例及容器的 V$SQLSTATS，不依赖 AWR；新增 cpu_time、buffer_gets、
disk_reads，cpu_time 保留原生微秒。PG/MySQL 复用已采集的扩展指标。
各字段保存在现有 database_metrics_json；不增加表、列，不执行数据库初始化或历史回填。
模板输出、SHA-256、原生字段映射和目录验收基线同步维护。

有界采集按多个资源指标的 ROW_NUMBER 排名交错选择，保留总行数上限，避免只收集累计耗时
前 N。Oracle 同时考虑总量及每次执行 CPU/逻辑读，PG/MySQL 考虑各自提供的资源维度。
这种策略减少偏差但不保证完整召回：低资源累计、高窗口增量、新出现、被淘汰或两次快照之间
消失的 SQL 仍可能遗漏。没有建立连续基线的 SQL 不按零估算。

BOUNDED_CANDIDATES 与 VISIBLE_SET 保持原策略语义；后者只有未截断、未触及上限且来源
完整时才声明读完凭据可见集合。即使读完，也不是原子快照或所有执行的完整记录。

## 4. 窗口算法与实例边界

执行顺序：

1. 以 Tenant/Domain/Target（KBot 为 Domain/Target）读取授权范围内快照。
2. 对齐不晚于请求起止边界的最近快照，保留请求/实际窗口、偏差及不连续区间。
3. 按真实实例身份和启动代次分组，再按 SQL 身份、库/Schema、用户、top_level、计划分组。
4. 仅在相邻、连续、可比较且未识别重置的快照间计算计数器差值。
5. 对每个指标独立计算增量、缺口和质量，聚合窗口内有效区间。
6. 应用最低次数、所选指标阈值、CPU/逻辑读联合阈值，再排序，最后截取 Top N。

CPU/逻辑读的重置不抹除其他有效资源指标；指标缺失或回退不参与该指标的数值计算。
部分区间可用时保留观测总量并标记 PARTIAL；没有任何区间可用时返回未知值且不参与该指标排名。
派生每次指标使用相同覆盖区间内的总量/次数；零执行时均值未知，但资源增量仍可进入总量排名。
累计平均值、max、P95 不相减；不同实例/重启代次不合并，MySQL 仍使用既有 Uptime 容差判断连续性。
并列时使用 SQL 主体和实例代次稳定排序。

Target 代表授权实例连接，不声称支持 RAC 集群内任意节点切换。连接漂移会形成不同实例组与
连续性缺口，而不会合并成一条“实例总 SQL”。跨实例集群排行不在本次能力边界内。

## 5. 结果与证据

表格保留 SQL 摘要、身份、执行次数、总/平均耗时，增加引擎真实支持的资源指标、单位、
实例身份和指标覆盖提示。原始 Artifact 保留 query_options、排序指标、候选/匹配数量、
指标质量、快照 ID、实例启动代次和窗口缺口；页面显示中文查询摘要和实际覆盖范围。
精确数值以十进制字符串传递，避免前端大整数/浮点丢失。

返回 Top N 之外仍有匹配记录时明确标记截断。窗口无数据、不支持指标、未采集指标、
未启用采集、权限不足分别呈现，不得解释为数据库没有执行 SQL。
带非默认资源查询条件时不自动提供按耗时排序的累计参考，以免将不同问题的结果当作回答。
SQL 摘要继续脱敏和截断；“深入分析”继续使用服务端原始行选择与授权校验。

## 6. 查询预算和演进

单次 Top SQL 查询最多读取 20,000 个快照和 100,000 条语句；仓储查询使用额外一行探测预算，
超出时明确要求缩小窗口，不静默截断后生成排名。其他工作负载报告不受该 Top SQL 专用预算影响。
时间参数仍允许最长 365 天，但实际可查询范围受留存、采集覆盖和上述预算约束。

本次不自动启用采集、不改数据库权限、不启用收费 Pack。AWR 的按指标窗口聚合、
集群级实例选择、候选连续基线补采、长窗口预聚合及独立浏览页属于后续增强；
不得将当前按耗时截取的 AWR 前 15 条重排后称作完整资源排行。

## 7. 回归要求

两端验证：资源高但耗时低的排名、升降序、联合阈值先于 Top N、时区冻结、
按有效区间加权的单次指标、零执行、缺失/重置、实例漂移/重启隔离、候选限制、
预算超限、页面能力切换、SQL 摘要/数值与证据来源，以及模板 Hash/原生映射。
离线回归不等同于真实目标库 SQL 执行或部署验收，交付时单独报告验证范围。

## 8. 周期快照调度与运行状态

快照由应用调度器按 Target 已发布的采集策略创建固定诊断任务，再由 Worker 读取目标库
累计统计并落入应用的工作负载快照/语句存储；数据库一直运行不代表应用已成功采集。
这不是 Oracle AWR 快照，也不会自动补齐过去未采集的时间窗口。

周期工作负载与活动采样均使用当前有效的 Agent 版本 → 业务系统 → 活跃资源 →
数据库 Target 授权链，不要求旧的 Target–Agent 直接绑定。只允许启用 Agent 和 Target，
保持 Domain 隔离，Ammolite 另外保持 Tenant 隔离。共享资源或多个可用 Agent 时按
Agent ID 稳定选择一个执行者，沿用每 Target 到期锁与冻结版本上下文，不重复创建采集任务。
找不到授权 Agent 时保留 ACTIVE_AGENT_BINDING_MISSING，并记录不含连接信息的告警。

Top SQL 原始结果额外保存本次读取快照数量及查询时的采集运行状态：
last_attempt_at、next_run_at、last_error_code、consecutive_failures。
last_attempt_at 来自既有运行字段，不声称是最近成功时间；快照数量包含窗口边界基线，
不等于有效快照或可比较区间数量。缺口次数也不再显示成容易误认为快照数的“(1)”。
启用但失败时展示实际原因和稳定错误码，提示先恢复采集；仅证据不足时提示积累快照。
当前失败不抹除已有可用历史区间；关闭采集时仍明确提示未启用，不把遗留错误当当前失败。

成功创建任务只清除已恢复的授权阻塞，其他执行错误不会在调度阶段清空；
失败次数在正常快照持久化后按既有规则收敛。不自动启用已关闭策略，不添加兼容读写、
数据库列、初始化、历史回填或绕过授权路径。

部署验收需分别确认两端策略状态、成功创建的采集任务、Worker 成功落库以及连续可比较
快照覆盖请求窗口。5 分钟间隔下，两次快照仅能形成约 5 分钟区间；完整最近 15 分钟通常
需要约 4 次连续快照及合适的边界基线。只读授权查询通过不代表线上快照已恢复。

## 9. 未发布草稿中的采集配置

入口为“配置与治理 → 业务系统 → 系统构成 → 数据库资源抽屉 → 历史 SQL 采集”。
未发布的新资源没有正式 Target，仍可配置周期快照；不能因为缺少 Target ID 隐藏整个区块。
旧草稿缺少可选采集字段时显示与 WorkloadPolicy 合同一致的关闭默认值，不要求重建草稿。
新资源的设置存入草稿 database.workload_snapshot_policy，正式创建载荷传入
database.target.workload_snapshot_policy；保存和重新打开草稿、切换资源或 RAC 节点均保留各自策略。

新资源仅展示“尚未发布”，不展示虚构的最近采集时间，不请求不存在的 Target，
不提前创建资源、启动采集或执行能力刷新。连接测试继续使用抽屉底部的无持久化测试入口。
已有资源仍使用暂存策略、Target ETag 与业务系统资源授权校验，已上线系统继续只读。
三库的开启/关闭、范围与间隔、草稿重开、首次发布、节点隔离、迟到响应及已有资源并发合同
均纳入回归；浏览器使用隔离接口，不代表已部署或真实采集已开始。
