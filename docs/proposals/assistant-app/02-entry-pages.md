# 02 · 三个业务入口页面设计

## 共同交互规则

三个入口都将一次用户发起记录为可恢复的 Run。前端接收 SSE 仅用于显示进度；刷新或断线后必须从 Run 详情恢复终态、正文、引用和图片资产。展示的进度只能是公开、结构化阶段，例如“正在检索已授权知识”“正在执行 X Search”“图片正在生成”，不显示模型隐藏思维过程。

每页具备四种明确状态：未配置、空记录、运行中、失败。失败需显示稳定错误摘要、可复制的 `request_id`/`run_id` 和安全重试入口；不得把 OCI 原始错误、密钥、完整上游 URL 或未清洗响应展示给用户。

## 知识问答

知识问答是唯一允许使用 KC 和问数模型的会话入口，复用既有 Knowledge Retrieval Agent Runtime。页面由左侧会话/Agent、中间会话、右侧运行上下文三列构成。

```text
┌──── 最近会话与 Agent ────┬──────────── 会话与输入 ────────────┬──── 运行上下文与证据 ────┐
│ [新建会话]               │ Agent：经营知识助手                │ Domain：华东销售          │
│                           │ 模式：智能选择 / 问文 / 问数 / 闲聊 │ KC：销售知识库             │
│ Agent A · 当前            │                                    │ 问数：经营分析 v3          │
│ Agent B                   │ 用户消息、公开执行阶段、最终回答     │                            │
│ ─────────                 │                                    │ [C1] 文档引用              │
│ 会话列表                  │ 多行输入框                 [发送]   │ [Q1] 查询结果              │
└───────────────────────────┴────────────────────────────────────┴──────────────────────────┘
```

Agent 下拉框只列出当前用户在当前 Domain 获授权且已启用的 Agent。新建会话前没有 Agent 时，页面只给出创建/申请权限路径。

模式的语义如下：

| 模式 | 允许的执行路径 | 结果标识 |
| --- | --- | --- |
| 智能选择 | Agent 已启用能力内的既有受控 Router | 在最终回答顶部写明实际路由 |
| 问文 | 仅 KC 文档检索 | `[C1]` 等文档证据 |
| 问数 | 仅已绑定、已发布的语义问数模型 | `[Q1]` 查询结果与截断提示 |
| 闲聊 | 通用对话 Skill，不读取 KC 和数据源 | “普通对话，未访问知识或数据” |

智能选择可以进入现有 `HYBRID_*` 路由，但只能使用该 Agent 已绑定的 KC 和问数模型；它绝不访问 X Search。右栏随最终 Artifact 显示真实证据：`[C]` 打开文档定位预览，`[Q]` 打开受权限控制的查询结果预览。

## X 实时搜索

X 搜索是一次独立研究 Run，不建立知识问答的 Conversation，也不要求选择 KC 或 Agent。页面左栏是历史与收藏，中间是搜索条件、公开进度和结论，右栏是实际来源卡。

```text
┌──── 搜索历史 ────────────┬───────── 查询、进度与结论 ─────────┬──────── 实际来源 ────────┐
│ [新建搜索]               │ 查询：___________________________ │ [X1] @handle              │
│ 收藏                     │ 日期：起始 ─ 结束                 │ 发布时间、来源链接          │
│ 今日 / 本周 / 本月        │ 限定账号（可选）                  │ 摘要与“打开 X”             │
│                           │ 图片分析 / 视频分析（模型支持时）  │                            │
│ 历史 Run                  │ [开始搜索]                        │ [X2] …                    │
│                           │ 阶段 → 结论正文与 [X1] 引用       │                            │
└───────────────────────────┴────────────────────────────────────┴──────────────────────────┘
```

页面按模型能力动态显示媒体理解选项。账号“仅包含”和“排除”是二选一控件；日期范围使用完整日期且在提交前校验起止顺序。页面不开放模型、Tool 名称、原始请求 JSON 或任意上游参数。

右栏来源卡由服务端返回的真实 citation 创建，至少包含账号、外部链接、发布时间（若上游提供）、检索时间和受限摘要。回答内出现的 `[Xn]` 必须能在右栏找到；来源不足时明确标为“外部信息不足”，不得用模型推断补齐。顶部始终展示“外部实时线索，不等同于企业已确认事实”。

## 文生图

文生图使用独立的 Generation Run 和图片资产，不复用对话消息。左栏列出草稿和历史任务，中间提供创作提示与受限参数，右栏展示当前结果或历史资产。

```text
┌──── 草稿与历史 ──────────┬────────── 创作提示与任务 ──────────┬───── 图片资产与溯源 ─────┐
│ [新建草稿]               │ 描述你希望生成的内容                │ 当前结果预览               │
│ 草稿                     │ [ 多行提示词                         │ MIME / 尺寸 / 创建时间     │
│ 已完成 / 失败任务         │ ]                                   │ 模型显示名 / Run ID        │
│ 我的图片资产              │ 比例：1:1 / 4:3 / 16:9 / 9:16       │ 提示词版本                 │
│                           │ 数量：由策略允许的选项               │ [下载] [复制受控链接]      │
│                           │ [生成图片]                          │ 历史版本                   │
└───────────────────────────┴────────────────────────────────────┴──────────────────────────┘
```

用户可编辑文本提示、比例和策略允许的数量；尺寸、最大数量、内容安全策略和模型绑定由管理员配置。开始按钮创建 Run 后展示“已接受/生成中/已完成/已拒绝/失败”，而不是阻塞页面。

若未来开放“从 X 搜索创作”，必须由用户从具体 Run 中选择来源，系统仅生成可编辑的图片 Brief；用户确认后才会创建新的图片 Run。该操作保存显式的 `source_run_id`，但不能把 X 原文自动附加到提示词。
