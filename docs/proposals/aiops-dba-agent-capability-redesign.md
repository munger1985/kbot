## 1. 设计决策与文档关系

建设一个问题驱动的 DBA 调查内核，复用现有 Conversation/Turn、Run/Task、Artifact、
Evidence、受控 Executor、Proposal、Verification、Report 和运维知识 Registry。
不另建与现有 investigation 并行的 SQL Agent、报告 Agent 或案例 Agent 状态真相。

一次调查形成可修订、可追溯的调查记录；回答、报告和案例是该记录的不同投影，
不能相互反向解析正文来制造事实、根因或执行记录。

本文规定跨场景的目标行为；[SQL 诊断详细设计](aiops-sql-diagnosis-detailed-design.md)
继续规定语句身份、窗口统计与计划等专项细节，两者累积适用，不降低 SQL 专项门禁。
现有架构、正式报告和运维知识文档保留当前实现说明；与本文不同的旧目标约定，
在对应实施切片交付时按本文直接替换，不通过兼容路径、双读写或历史自动回填解决。
任何部分交付均须明确剩余缺口，不把本设计标记为整体已实现。

## 2. 产品目标、范围与非目标

Agent 应像 DBA 一样明确问题、主动找信息、比较解释、选择有区分度的检查、
给出针对环境的处置方案，并说明如何验证；不能承诺任何故障都能自动确认根因。

覆盖数据库性能、SQL、锁与事务、连接、容量、复制与高可用、备份恢复、
配置与维护、巡检、故障复盘、实施文档和知识问答。Oracle、MySQL、PostgreSQL
交付相同业务闭环，但使用各自真实机制、版本、许可与数据来源，不伪造等价指标。

不把下面事项作为默认能力：任意 SSH/Shell、任意 SQL、自动安装扩展、扩大权限、
自动启用采集、任意访问业务表、未经审批执行变更，以及尚未接入的 APM/云平台。
“能建议一个检查”不等于“已有执行这个检查的 Adapter”。

任务采用不同完成标准，不把所有请求都变成深度根因调查：

| 任务 | 应交付 | 不应强制要求 |
| --- | --- | --- |
| 直接查询、Top N | 同口径结果、范围和简短解释 | 根因、Finding、执行计划 |
| 原因诊断 | 已确认事实、原因判断、竞争性解释与关键边界 | 固定指标套餐、必有根因 |
| 优化与处置 | 证据关联的候选措施、适用条件、风险及验证 | 必须先获得执行授权才能写方案 |
| 巡检 | 每项适用性、检查覆盖、风险和跟踪事项 | 无副本也查询复制延迟 |
| 纯知识问答 | 已授权知识引用、适用性与尚需现场核验事项 | 必须连接数据库 |
| 实施文档 | 环境化步骤、参数来源、检查与停止/回退条件 | 自动执行步骤 |
| 已有诊断导出 | 忠实冻结已有记录 | 再次查库或重新诊断 |
| 补充调查后编制报告 | 明确的新取证任务与后续报告 | 把报告模板当作取证授权 |

## 3. 一条证据链与四种交付物

```text
用户问题 / 告警 / 巡检 / 授权材料
               ↓
问题与范围 → 发现可用来源 → 按假设取证 → 评估、补证或停止
               ↓                            ↑
      版本化调查记录 ← 经授权的执行与效果验证
        ├─ 回答：当前问题的简洁沟通
        ├─ 报告：选定范围、版本与时间的冻结复盘
        ├─ 方案/Runbook：待审阅的处置与实施计划
        └─ 案例候选 → 脱敏、审核、索引 → 发布的经验知识
                                                    ↓
                            后续调查的检查线索，不是现场事实
```

调查记录是技术判断的权威来源；原始 Evidence/Artifact 是观测的权威来源；
Proposal/Execution 是审批与执行的权威来源；Verification 是效果判断的来源。
Report 保存冻结出版物，Registry 管理知识资产与发布，KC 仅承担原文、索引和精确引用。
模型输出、用户确认和文档生成均不得覆盖这些职责。

## 4. 实际能力发现与资源授权

### 4.1 声明、许可、访问与观测分开

来源能力至少保留配置声明、探测结果、探测时间、配置版本、可访问范围及失败原因。
每项能力分别表达 `AVAILABLE / UNAVAILABLE / UNKNOWN / NOT_APPLICABLE`；
访问失败进一步区分权限、许可、版本不支持、未接入、无历史、暂时故障及预算限制。
能力状态不等于数据库健康状态，无复制拓扑不是“复制故障”。

Oracle 配置只读连接不能推定拥有 SELECT ANY DICTIONARY、包执行权限或 Pack 许可；
PG/MySQL 的角色、扩展和 Performance Schema consumer 也必须按实际观测处理。
许可由显式治理配置决定，不能由视图可查询反推出已获商业许可。
配置变化、凭据轮换或实例切换使相关探测过期；过期结果保留来源但不能作为当前可用保证。
每轮按需要做低成本核验，不做无界权限扫描，也不修改应用自身数据库 Schema。

按需短时采样允许规划器在明确证据需求和判断作用后，选择目录声明的低成本固定数据库工具：
每轮一组、2–4 次，前次完成后至少间隔 2–10 秒；每次最多 5 秒、200 行、128 KiB，
整体至多 60 秒并受 Run deadline 与任务租约收紧。每次独立签发 Grant 和请求幂等身份，
采样组不做整组自动重试；一次性查询可以升级为一组采样，已调度采样不能通过改次数/间隔绕过防重复。
权限缺口、截断、旧时点/重复请求、预算耗尽立即停止，保留已完成时点与明确缺口。
这些事实进入同一证据/报告链，保留当前或累计口径，不自动声称指定历史窗口已覆盖，
也不绕过统计重置、主体、单位与计数器语义校验来生成差分。不启用周期采集或执行动态采样 SQL。

### 4.2 发现不是猜测名称

| 来源 | 目标发现能力 | 安全与解释边界 |
| --- | --- | --- |
| Prometheus | 目标限定的指标名、标签、类型、帮助信息、历史可见范围和抽样数据 | 结果与基数有界；元数据缺类型则标未知；历史出现不等于当前有采样 |
| Zabbix / OEM | 已授权对象的指标、单位、历史范围及可用查询能力 | 仅使用真实 Adapter 接口，不伪称支持任意 PromQL |
| 数据库直连 | 版本、角色、实例/容器、可见目录、统计来源和按需权限探测 | 固定目录优先复用；受 AST 策略约束的动态查询覆盖长尾 |
| 日志与附件 | 精确授权流、时间范围、格式和受控检索 | 日志缺记录不能证明事件未发生；用户材料保留原可信级别 |
| 拓扑、发布、APM、备份平台 | 已接入能力、授权对象与时间映射 | 未接入时提出具体补证需求，不生成虚构调用 |
| 运维知识 | 发布版本、适用范围、引用和当前可用性 | 只能给方法、经验与条件，不能证明本次现场状态 |

新增指标可通过目标限定发现后进入同轮查询，不要求预先加入显示 Profile。
Profile 只负责常用检查与呈现，不是规划器能力白名单。动态 SQL 仍须经过 AST、
对象/函数范围、绑定、只读事务、超时与结果上限等既有安全门禁。

### 4.3 单目标与授权范围扩展

默认继承当前明确选择的 Target；业务系统范围先冻结已授权成员快照，每项证据仍归属
具体 Target。需要关联主机、主从或上下游时，只能访问当前 Agent/操作者实际获准的成员
及绑定来源。发现了另一台主机或数据库不意味着获得其访问权。
超出原任务范围、需要新来源授权或有明显采集风险时，提出明确扩展请求，不隐式跨库扫描。

## 5. 问题与调查任务合同

扩展现有 TaskFrame，而不是增加新的顶层 WorkflowKind。冻结的问题上下文包含：

- 用户的原问题、任务类型、症状、预期交付和各子目标；
- 逻辑 Target、已核实物理身份与拓扑范围，未核实维度显式为未知；
- 用户时间范围、时区、采样需求、比较区间和基线/SLO（存在时）；
- 已知事实引用、用户陈述、历史推断与知识线索的分离；
- 可用来源、只读/审批边界、成本预算及待澄清的业务条件。

每个子目标独立记录 `SATISFIED / PARTIAL / BLOCKED / NOT_APPLICABLE` 及原因。
“列出排行”完成而“解释变慢原因”未完成时，不得用一个 ANSWERABLE 掩盖后者。
纯列表任务也不能被历史对话中的单条 SQL 诊断劫持。

默认时间按任务定义：当前会话使用时点；Top SQL 沿用默认最近 15 分钟；
故障优先采用症状发生区间；趋势按问题与真实留存选择可解释区间；
报告自然周期不能用统一的 15 分钟替代。相对时间仅在创建调查时冻结一次。
需要业务高峰、恢复目标等不可自动发现的信息才向用户澄清，不要求用户代查已可得指标。

## 6. 通用证据与关系语义

### 6.1 观测封套

在现有证据合同上统一表达，不让模型在自然语言里自行补齐：

| 维度 | 必须保留的语义 |
| --- | --- |
| 身份 | Tenant/Domain、逻辑 Target、可核实实例/启动代次、库/容器和对象身份 |
| 来源 | Tool/Adapter/版本、不可变 Artifact 与行/字段定位、采集参数摘要、内容哈希 |
| 时间 | 采集起止、数据实际覆盖、时区、粒度、时钟偏差及请求窗口偏差 |
| 测量 | 时点/累计/增量/分布/估算/状态、单位、可加性、分母和统计范围 |
| 质量 | 权限可见性、覆盖、截断、采样、重置/淘汰、缺失和源版本变化 |
| 信任 | 系统来源观测、人工材料、知识引用或模型推断，不随流转自动升级 |
| 血缘 | 原生计数器/日志事件身份、派生计算与输入引用，明确哪些结果并不独立 |

计数器、OID、SQL 标识使用精确整数/Decimal；超出浏览器安全范围的值通过字符串传输。
空、零、无权限、不适用、无采样和采样未命中必须可区分。
缺失值不补零；源的空结果只能回答其实际观测范围内的问题。

### 6.2 关联与派生

实例→数据库→会话→事务→SQL→对象，以及数据库→主机/存储/副本的边，
均携带依据、方向、时间有效性和状态：已观测关联、待核验候选或背景。
不能因名称相同、同属一个逻辑 Target 或时间接近就确认物理身份相同。
全库 CPU、对象顺序扫描不能无关联证据归因于某条 SQL。

导出的图表、摘要与报表若来自同一原生计数器，不构成新的独立证据。
多次采样可以证明持续性或变化，但不会自动证明另一种原因。
派生指标保存公式、输入、单位、舍入和质量传播，不能从自然语言反推统计值。
当前受控代数以 `MEASUREMENT_GRAPH.v1` 保存依赖图：原始字段输入、计数器差分、
窗口速率、总量相除与可加窗口量求和。图必须无环，最多 256 个原始输入、128 个
计算节点、32 层依赖；禁止重复血缘求和、任意表达式、单位/作用域或窗口混算。
至少 80 位 Decimal 计算，保存实际精度和舍入规则，缺失/部分/重置/未核验输入向后传播。
窗口 Top SQL 的图随证据进入调查记录和报告；效果报告的图引用原始窗口 Artifact 字段，
案例复核使用原始报告再次计算。它不是自动推断未知指标语义或跨源单位映射的许可。
跨轮引用重新检查当前权限；旧模型结论不能作为新 SOURCE_VERIFIED 观测。

## 7. 假设、判断与完成标准

### 7.1 假设可更新，经验路径不限制候选

每项候选解释包含待解释现象、可能机制、支持与反证、区分性检查、适用范围和剩余未知。
模型可以提出新解释，不能只在固定的 CPU/I/O/索引几个槽位中选择。
对外保存的是简洁、可审阅的检查理由和依据，不采集或展示模型私有思维链。

例如连接增长可由业务并发、连接泄漏、慢事务、阻塞和连接池配置解释。
下一步应选能区分这些解释的检查，而不是对所有候选重复读取同一套参数。

### 7.2 逐项判断，而非整篇自由文本背书

每项 Claim 至少有：稳定 ID、陈述、目标/对象、时间、类型、证据行/字段、
推导摘要、支持强度、反证、替代解释、限制及版本状态。
事实、原因、风险、预测、建议与“已排除”采用不同类型，避免全局 confidence 混用。
物理观测可标已观测；原因使用待验证、有支持或已确认；预测保留模型与假设。

可复核直接观测足以确认相应事实，例如当前谁阻塞谁；确认其是业务故障根因还需
匹配故障时间、影响范围及其他解释。没有证据的根因即使写得肯定也不能升级。
不再用“两个来源组、两个测试”作为通用根因门槛，也不允许模型自行声明 DIRECT
便获得确认。按主张类型检查对象/时间适配、机制与反证，保留语义质量评测。

程序负责引用存在、权限、身份、时间/单位、计算、可信级别与状态约束；
引用校验不声称能自动证明因果。高风险、矛盾或无法核验的原因必须保留不确定性。

### 7.3 冲突与修订

实现约定：同轮 claim_id 只在其来源 Artifact 内唯一。跨多轮修订以
`prior_artifact_id + prior_claim_id` 精确定位；服务端重新授权并核验仍有效的历史判断，
不能因中间轮次未重复旧判断而丢失修订入口。历史判断保留原证据身份，
不转成新一轮 SOURCE_VERIFIED 观测。历史重验有界，超限不隐式继承。

新证据使主张被支持、降级、驳回或替代时，追加修订并保存原因。
不能在会话中寻找“最后一次 CONFIRMED”来绕过其后的反证；不同对象或不同故障阶段
也不能取最高等级拼成一个根因。显示当前有效判断及关键变更，历史版本保持可追溯。
知识、报告和案例的下游引用保存确切版本，不能通过循环互引增加支持强度。

### 7.4 完成不等于解决

调查结束原因包括：目标已回答、可读证据已穷尽、预算耗尽、需用户选择、
需额外授权或安全停止。运行成功、问题已回答、原因已确认、措施已执行与故障已解决
分别表达；Finding 数量、工具数量、监控覆盖率不能代替这些状态。

## 8. 补证、时延与可靠性

每个动作注明要解决的问题、预期区分结果、来源、依赖、成本/风险和停止条件。
按诊断价值、可获得性和成本定性排序，不输出未经校准的精确信息增益分数。
相互独立且预算允许的检查并行；依赖实际发现的参数才顺序执行。

选择规则：

1. 已有可信证据能回答时先回答，不为补齐套餐继续调查。
2. 有关键未知且存在安全、可执行的区分性检查时补证。
3. 暂时故障有限重试；确定的无权限、不适用和不存在历史不原样重试。
4. 同源再次采样必须说明其用途，例如持续阻塞或短期速率；新时间戳不自动算新进展。
5. 无法追补的历史窗口立即说明边界；新采样只能回答新观察区间。
6. 无关缺口不降低已被支持的局部判断，也不延长本轮。

冻结排队、规划、工具、模型、字节/行数、目标/来源并发和总耗时预算，
预留总结时间；进入等待后记录续跑预算规则。绝对 deadline、取消、租约围栏和
迟到结果隔离覆盖整轮，不能仅限制重规划。模型输出限制来自 Model Serving 配置，
不得靠截断证据或正文伪装完成。现有 90 秒目标不是已验收 P95，须通过真实并发测试校准。

中途可展示已完成查询与有证据支持的进展，不提前流式发布未校验的根因或变更命令。
超时从已持久化证据生成部分回答；失败、零行和没有执行取证不得混为一谈。

## 9. 场景化调查能力

下表是最小验收场景，不是工具、假设或指标白名单。具体选择由问题与可用信息决定。

| 场景 | 常见区分方向 | 需要形成的业务输出 |
| --- | --- | --- |
| SQL/性能 | 负载变化、单次代价、阻塞、计划、数据分布、主机争用、应用重试 | 排名与原因分开；针对原因的措施与比较办法 |
| 锁/事务 | 阻塞者、等待链、事务年龄、持锁对象、应用归属与回滚成本 | 影响、临时缓解、事务根治和终止风险 |
| 连接异常 | 服务/监听、认证、连接池、并发、泄漏、等待占用 | 可核实的失败层、处置顺序与恢复条件 |
| 容量/增长 | 已分配/可扩展、物理余量、增长对象、临时/永久、清理约束 | 不同分母、可用时间估计条件与扩容/治理方案 |
| 复制/高可用 | 拓扑、角色、传输/回放、长事务、槽/归档与网络 | 影响、风险、原因候选和安全恢复步骤 |
| 备份/恢复 | 作业、链完整性、保留、恢复目标、介质与实测演练 | 备份状态与可恢复性分离，不以 WAL/Binlog 存在证明可恢复 |
| 配置/维护 | 版本、实际工作负载、对象统计、索引、清理与冻结 | 风险候选与已证实问题分开，不凭阈值直接实施 |
| 实例不可达 | 数据源健康、已有日志、故障前监控、已授权离线材料 | 在不能查库时仍分析，明确哪些现场事实无法核验 |
| 巡检/趋势 | 拓扑适用性、同口径历史、覆盖、季节性、问题复发 | 检查状态、趋势与待处理事项，不把缺数据写成健康 |
| 知识/实施文档 | 来源版本、环境差异、操作前提、缺失参数 | 有出处的方法与环境化步骤，不生成假执行结果 |

Oracle 保留 RAC/CDB、AWR/ASH/SQL Monitor 的范围和 Pack 门禁；PG 保留
Timeline/LSN、语句多维身份与扩展差异；MySQL 保留 Schema/Digest、GTID/Binlog、
consumer 与复制 channel 差异。观察类型不适用时可用其他证据回答，不虚构对照字段。

## 10. 统一调查结果合同

目标新增 `DBA_INVESTIGATION_RECORD.v1` 作为不可变 Artifact，复用现有存储与访问边界。
首批严格合同已嵌入 Turn 结果 Artifact；下列完整领域结构仍是目标态，
不是新增对外接口，也不要求为每个子结构新建数据库表。

```text
record_id / revision / previous_revision / schema_version
scope: agents, authorized_targets, observed_identities, time_ranges
problem: original_request, task_kind, goals, symptoms, constraints
provenance: source_turns, runs, frozen_prompts, models, source_artifacts
observations: evidence_refs, measurement_metadata, derivations
relationships: subject_edges, evidence_refs, validity, uncertainty
hypotheses: candidate_explanations, checks, support, counterevidence, status
claims: claim_id, kind, subject, time, statement, support, limits, revision_state
goal_assessments: goal_id, status, claim_refs, blocking_gaps
recommendations: action_id, claim_refs, preconditions, draft_steps, risk, validation
execution_refs: proposal/execution identities and actual receipts only
verification_refs: measured_effects, comparability, confounders, guardrails
gaps: affected_goals, reason, importance, collectability, next_step
completion: stop_reason, budget_used, follow_up, generated_at
```

子结构使用严格类型、稳定引用和版本校验，禁止用任意 dict 绕过权限与事实约束。
服务端负责身份、公式、状态和来源校验；模型负责提出解释和建议并接受结构化反馈。
报告生成、案例提炼失败不回滚已经完成的调查；通过幂等任务、Outbox/Inbox 和
不可变 Artifact 重新处理，不能再运行一次诊断来掩盖下游失败。

## 11. 诊断回答设计

### 11.1 问题优先的回答

默认结构按任务裁剪，不固定展示所有段落：

1. 直接回答：当前能确认什么、主要影响或用户请求的数据。
2. 关键依据：只展示支撑判断的少量数字、关联和必要表格，附对应引用。
3. 原因与边界：区分已确认、有支持、待验证；只解释影响当前判断的限制。
4. 建议：优先顺序、适用条件、措施、风险与验证；未执行明确标注。
5. 下一步：仍影响决策的缺口及系统可继续做什么；无需每次重复免责声明。

直接列表先展示列表，SQL 文本按长度截断并提供受控完整查看；深入分析不重复 Top SQL 主表。
纯知识问答先给有引用的方法，再说明环境核验，不伪装成已查当前库。
不以“本轮 Finding 为空”“没有卡片可解释”等内部流程开场；无 Finding 不阻止回答。
零行说明观测时间与范围，不外推为历史没有负载。

### 11.2 内容与呈现分离

Answer Composer 从调查记录选择 Claim、结果表和建议，生成 `claim_refs` 明确的展示块。
自然语言可以压缩、翻译和重排，不能添加未经记录的新数字、根因或执行结果。
必要的新推断返回调查评估后形成新 Claim，再进入回答，不在润色阶段偷偷引入。
程序生成数据表、单位、时间与统计标签；模型不重写事实表格。

回答中的“已观察到改善”不等于“证明该措施是唯一原因”；已确认阻塞关系与
已确认业务故障根因也分别表达。重复限制集中说明，紧邻易误读结论保留必要限定。

## 12. 解决方案、实施文档与执行隔离

每项建议关联它解决的 Claim/目标，区分继续调查、立即缓解、长期修复、
预防和观察。记录对象、动作、适用条件、预期机制、风险、验证指标与停止/回退条件。

措施状态独立表达：建议草案、待补参数、待审阅、已审批、已执行、已验证或失败。
参数标明来自观测、用户输入、手册还是待确认；未知端口、路径、对象和容量不能猜测。
不完整步骤标为不可执行，并指出具体缺项，不用看似可运行的默认值掩盖风险。

可在权限允许的展示范围内生成待验证的具体 SQL/命令草案；这不是执行授权。
生产实际计划、长时间扫描或诊断函数即使只读，也必须评估锁、资源和执行风险。
用户提供的 SQL/脚本仅是材料，不能直接执行；草案不能直接进入 Executor。
执行仍必须使用既有受控目录、独立凭据、审批冻结、短期 Grant 和执行前重验。
不在目录中的动作标人工执行或未支持，不以聊天“同意”绕过审批。

Runbook 从同一记录与专业编译器生成，保留节点、版本、参数来源、依赖、
预检、步骤、执行身份、验证、停止条件、回退或不可逆补救与交付物。
逐项声明三库支持程度，不把 Oracle 档案名称映射到 PG/MySQL 假装已支持。
稳定执行回执与人工执行材料分别记录，人工复核不会把材料变成系统直连观测。

## 13. 效果验证与问题闭环

验证计划在执行前建立，并冻结基线、成功条件、护栏、比较区间、负载特征和停止条件。
执行后重新取证，比较相同对象、身份、统计口径和可比业务负载；重启/重置、
业务自然下降、并行发布、缓存预热等混杂因素必须记录。

累计值先验证连续性再做差；平均值按总量和次数计算；累计最大值不相减；
P95/峰值只有具备相应执行分布或采样证据才输出。不同长度窗口明确采用速率或
每次调用成本等归一化，不能用总耗时下降直接证明单次 SQL 优化。

验证分别给出效果 `IMPROVED / UNCHANGED / DEGRADED / INCONCLUSIVE`、
症状是否恢复、护栏是否通过及归因强度。存在改善不自动确认为根因，
执行成功不等于措施有效；告警恢复也不自动关闭 WorkItem。
当前切片提供 Proposal 下的“业务效果验证”：冻结真实窗口基线及主要效果、护栏、
负载和可选症状规则，再关联动作回执与只读复核，以新的受控窗口报告复算。
条件冻结后不可修改；证据授权、哈希、实例/启动代次、重置/淘汰、版本与单位逐次重验。
支持真实报告中可核验的原生计数器，不以固定显示 Profile 限制选择。
Oracle 使用平台周期快照而非 AWR；MySQL Uptime 估算只容许 2 秒启动时间误差，
Oracle 不同计划保留独立身份。累计最大值不做差，业务自然降载不认作优化。
观察性改善保留 LIMITED 归因，不能伪造隔离实验或直接升级已验证案例。
预登记的匹配对照使用另一个当前 Agent 已授权且物理身份不同的同类数据库：
冻结完整主体、同口径规则、主要效果/护栏/业务负载、三个以上同步等长前期窗口及原始哈希。
执行前核验样本量、前期归一化趋势和业务负载可比性，执行后同步取得两组新窗口。
主要效果采用 `(处理后/处理前)/(对照后/对照前)-1`，对照稳定、负载、护栏和原始来源
均通过，且权威执行成功及动作只读复核通过时，才允许 SUPPORTED 效果归因。
这是匹配对照的准实验支持，不是随机试验，不保证排除未观测并行变更或共享基础设施影响，
不提高原调查的根因等级。没有对照、人工回执或来源不可重放时不能获得该等级。
正式效果报告保留原调查、执行提案及全部原始窗口，提炼为待审核案例而不是自动发布。
发布和检索均重读权威 Execution、冻结计划及原始窗口重算；人工修订动作/根因不能继承已验证等级。
执行前可冻结自动验证开关；只使用已启用且仍获授权的周期采集。
动作复核完成后，经事务 Outbox 等待稳定期及观察窗口，自动生成窗口证据、
复算并发布正式报告。实际区间按采样对齐，不插值，不自动开启采集。
重试耗尽留下失败状态及安全错误类别，不静默当作完成。
逐信号保存有效覆盖时间：指定 SQL、负载及护栏各自必须覆盖完整区间；
无关 SQL 的淘汰或无关指标缺失不一票否决已完整的信号。
启动代次、物理身份或全局采集连续性缺口仍阻断比较，缺失/重置信号不补零。
持续性问题按合理业务周期观察复发；业务确认可作为单独人工证据，而非替代全部测量。

## 14. 正式报告设计

### 14.1 两种生成模式

- 导出已有调查：冻结选定范围的调查记录修订、执行/验证引用和报告模板；不查库、不执行操作。
- 补充调查后编制：用户明确提出范围和目的，创建新的受预算约束的调查任务；完成或部分完成后再冻结报告。

选择模板只改变出版物结构，不增加来源访问、时间范围或变更权限。
报告是否自动生成由现有业务入口策略显式决定；本次不新增触发规则。
报告不是案例的必经前置步骤，案例也不是报告的前置步骤，避免循环收口。

### 14.2 报告内容与跨轮合并

报告冻结问题与范围、执行摘要、业务影响、事实与原因、调查时间线、已排除解释、
措施建议、实际执行、效果验证、剩余风险和证据附录。按报告类型裁剪，
未发现根因时不输出假根因章节，未实施时不输出假恢复结果。

按 Claim ID、对象、故障阶段和修订关系合并相关 Turn；多问题分别呈现。
保留已选范围内各轮的覆盖清单，不能只取最后一轮，也不能把所有聊天全文送模型
重新决定真相。已驳回判断不进入当前结论，但可在调查过程说明为什么排除。
源间矛盾不能通过“取最高 CONFIRMED”等级消失。

正式报告、原生 AWR/ASH 和外部工具报告区分职责：原生文件可作为不可变附件和取证来源，
不因成功生成 HTML 就认定已完成 Agent 诊断。
月/季/年报使用闭合自然周期与真实覆盖；日点 P95 不标为原始采样 P95，
不从缺少分母的状态快照计算精确月度可用率。

### 14.3 完整性、冻结与修订

明确分离生成状态、必需内容完整性、调查目标状态、原因等级、措施状态和验证结果。
文档 READY 只能说明对应必需出版内容已形成，不能意味着根因确认或故障解决。
有价值的部分调查也能生成标明 PARTIAL 的报告。

统一适配器必须覆盖现有 MARKDOWN、ANALYSIS_MARKDOWN、SOLUTION_MARKDOWN，
以及目标结构化记录；但旧自由文本只能作为原始陈述，不反向升级为新 Claim。
同一次直接切换更新所有生产者/消费者，不建立永久双引擎。
正文丢失、来源不可解析或证据引用缺失不能默认为 READY。

ReportSource 保存记录/证据版本与哈希、模板、统计和脱敏规则版本；
Web、PDF、Markdown 消费同一份冻结内容。模型仅做有约束的叙述组织，
编辑展示不修改底层事实、原因等级、动作或验证状态。实质更正创建新记录和报告版本。
打印布局、格式转换和摘要不能吞掉方案、限制或引用。

## 15. 案例知识设计

### 15.1 案例来源与资格

案例以有权限、不可变、可追溯的调查记录为基础，也可从正式报告定位其来源记录；
允许显式选择多轮有效判断，不从聊天正文、最后一个 CONFIRMED 或 PDF 文本推断根因。
未生成正式报告不阻止形成候选；新 SQL 及其他诊断结果不得因 Artifact 类型不在旧名单而被遗漏。
历史没有结构化来源的内容不自动升级，也不自动回填；必要时显式重新核验。

性能优化、容量治理、复制恢复、维护、巡检发现和失败尝试都可能产生可复用知识，
不再用 INCIDENT + READY + CONFIRMED 作为所有案例的统一资格。
但没有任何可复用、可追溯检查或结论的“证据不足”不自动成为知识垃圾。
含敏感阻断项、来源不可验证、结论已撤回的候选不能发布。

### 15.2 知识用途、判断强度和效果相互独立

使用用途而非单一“成功案例”标签，目标案例类别包括：

| 用途 | 最低要求 | 可如何复用 |
| --- | --- | --- |
| `DIAGNOSTIC_REFERENCE` | 可追溯的有效检查、事实或排除路径；未确认原因明确保留 | 建议检查顺序与竞争性解释，不声称有确定根因 |
| `VERIFIED_RESOLUTION` | 措施确已执行、效果可比、目标症状与护栏满足、审核通过 | 借鉴已验证处置及条件，不保证新环境有效 |
| `VERIFIED_OPTIMIZATION` | 可比业务负载下测得改善、成本/写放大等护栏通过 | 借鉴优化机制、适用负载与权衡 |
| `NEGATIVE_EXPERIENCE` | 失败/无效/恶化的动作和结果可追溯，说明限制或混杂 | 作为禁忌、反例或风险，不作为推荐方案 |

问题类别、根因支持强度、执行状态、效果、归因强度、验证方式和可见范围分别保存。
`VERIFIED_*` 的 VERIFIED 只描述对应措施效果已被验证，不自动表示根因已确认。
症状通过临时绕行恢复但原因不明时，明确为缓解而非根治。
同一案例可包含成功与失败尝试；不能将整篇案例中的所有动作一起背书为有效。

### 15.3 案例结构与证据约束

目标严格合同保留：问题签名、环境/版本/拓扑、症状与时间、关键判断、
诊断路径、支持/反证、尝试动作、实际效果、测量办法、可比性、适用性、
禁忌、未决问题和不可编辑的来源血缘。新增类别和字段在实施时原子更新合同与治理流程，
不在旧自由文本字段夹带状态语义。

每项案例陈述关联原调查 Claim/观测；每项动作关联真实执行回执或注明人工来源；
每项效果关联比较证据、时间、负载、公式和护栏。
前后引用集合不重叠只是必要检查之一，不足以证明可比或有效；两张不同 PDF 不能算效果验证。
单独一条“用户说已恢复”可以记录为人工报告，不能冒充受控测量的 VERIFIED。
可变摘要不能改写不可变测量；人工新增无证据动作必须与已验证动作分开。

### 15.4 提炼、脱敏与发布

完成调查后可异步提出候选，绝不因模型肯定、报告生成或 WorkItem 关闭而自动发布。
候选经过来源/引用校验、去重、脱敏、范围核对和人工审核，进入 Registry 既有
版本与发布流程；失败、拒绝、退役和重新审核都有审计。
候选生成失败不影响用户已收到的回答，不通过重跑数据库调查重试。

脱敏不仅移除密码和令牌，还处理客户/业务标识、主机/IP、账号、路径、SQL 字面量、
个人信息、样本数据和外部地址。保留必要技术结构，用一致化占位映射替代真实标识；
受限原始证据与可共享案例分层存储，索引、摘要、引用预览与导出同样受控。
不得把原环境执行脚本中的路径、账号和对象作为新环境可直接执行参数。
人工材料和自动观测的信任级别在脱敏后仍保持。
入索引前先做确定性规则脱敏，再由案例知识库已配置的 parser_llm 进行受预算约束的
语义识别。模型只返回可逐字核对的敏感片段及类别，服务端一致化替换，
不接受模型重写结论、动作、效果或来源。模型/Prompt 不可用、超时或片段不可核验
时不向索引发送正文。保存模型与 Prompt 版本、输入/输出哈希及替换计数，
不保存敏感值映射。发布仍须人工审核，并重验扫描后正文哈希；
这是已接通的扫描链路，不是对真实语义模型零漏报的保证。

### 15.5 更正、撤回与权限

本批读路径先阻断后复核：发布及检索检查当前来源，正文检索返回后再次确认
Registry 状态/确切 Revision/权限；同会话显式反驳或替代沿确切来源追踪。
后台轮转复核已接通 Registry 暂停、审核留痕和可定位维护人的站内通知；
两端也已接通精确版本的人工复用反馈；这些机制不保证跨系统外部消费者的缓存已撤回。
语义扫描及受控窗口效果复算另有实际入口；
它们不代替真实质量验收、对照归因或正向 VERIFIED 案例生产链，人工反馈不提高验证等级。

源 Claim 被驳回、报告被实质更正、验证被撤销或来源权限变化时，通过血缘找到受影响
案例版本。技术结论受影响则暂停新检索并进入复核；纯排版更正不无条件撤销有效知识。
发布新版本后按原 Registry 流程切换；重新处理失败不能继续推荐已知错误的旧版本。
历史 Run 保留引用标识和哈希；实际读取仍重验权限，不保证被撤权内容继续可见。

去重依据问题机制、环境、动作和来源身份，不仅比较标题或错误码；
重复提炼幂等，人工合并保留各自证据和冲突，不通过复制案例刷高“成功次数”。

沿用 AIOps Registry → 结构化候选 → KC 精确 Revision 检索 → Citation 的链路，
不新增向量库或绕过发布状态。硬过滤权限、安全级、发布/暂停状态和明确禁忌；
版本、拓扑、工作负载及症状的相符、冲突、未知分别表达。
标签和错误码用于定位，不作为排除长尾问题的固定词表；未知版本不伪装为匹配。

不让“已批准手册”在明显不适用时机械压过更相关案例，官方文档也需核对版本。

Agent 把知识转成待核实假设或检查方案，然后获取当前证据。

同一事件派生的报告、案例、摘要不得在回流后被算作多个独立现场证据。
检索无结果不阻止数据库诊断；知识问答缺可靠来源时明确限制，不编造引文。

复用反馈记录是否适用、检查是否有价值、措施实际效果与失败原因；
点击、好评、模型自评不能自动提高验证等级或发布新版本。

## 19. 分片交付与验收门禁

### P0：先修正确性与统一来源

交付报告正文无损转换、权限推定修正、证据血缘/来源独立性、严格调查记录与
普通诊断 Claim；新 SQL 结果可进入报告和案例候选，去除旧 Artifact 名单断点。
回答、报告、案例共用一份有效判断，但案例仍保留治理门禁。

验收：有分析/方案却生成空 READY 报告必须失败；相同计数器经两工具读取不增加
独立支持；后续反证不能被早期 CONFIRMED 覆盖；人工复核不提升事实信任级别。

### P1：补齐主动调查与三库处置

交付监控/数据库发现、开放假设、跨源身份与时间关联、局部目标完成、
有界补证、环境化建议和验证计划。按真实支持范围交付三库 Runbook，
不存在实现的档案明确未支持，不能以 Oracle 模板复制充数。

验收：换指标名/标签、缺监控、缺计划、缺权限、数据库离线、不同拓扑和计数器重置时，
仍能选择可用检查或给出准确边界；不等待补齐无关数据，不能默默切换任务口径。

### P2：报告与案例全生命周期

交付跨轮/多问题报告、可比效果验证、四类知识用途、脱敏、版本审核、
更正撤回、精确检索、引用权限与复用反馈。案例不依赖先生成正式报告，
报告也不依赖先把诊断收口为成功案例。

验收：性能优化、未决但有效排查、失败尝试均能按实际用途提炼；
不可比前后数据不能成为 VERIFIED；错误案例及时退出新检索；
历史案例不能使当前诊断自证，也不能在原始内容撤权后通过摘要继续泄露。

### 真实闭环发布门禁

三库分别准备可控业务读写、隐藏故障真值及相似症状不同原因的场景，至少覆盖第 9 节。
场景不适用须给出机制依据，不能为了凑齐字段伪造功能。
采用真实数据库/监控/模型和浏览器走完整链：问题→证据→判断→方案→
经授权实施→同口径验证→报告→审核发布案例→相似与不相似问题复用。
故障注入、DDL、终止会话与恢复演练只在隔离或明确批准环境执行。

逐项评价任务回答准确性、原因区分度、证据归属、方案针对性、验证可靠性、
文档一致性、知识适用性与权限安全；不能只数 Tool/Citation 或平均 LLM 评分。
越权、凭据泄露、编造执行、错误 VERIFIED、把累计冒充窗口等关键失败必须阻断发布，
不能被其他高分抵消。记录首个有效结果/总时延、排队、模型、数据库成本、
并发、取消与失败行为，达标值通过真实试验制定，不宣称已经达到。

本地合同/替身测试、格式和构建通过只是基础验证，不证明 DBA 诊断有效。
每个交付批次记录实现、部署、真实场景、未决缺口与回退方式；
只有完整业务闭环验收通过后，才能对外声称对应场景具备诊断与解决能力。

## 20. 端到端行为示例（验收示意，不是线上诊断结论）

### 20.1 Top SQL → 深入诊断 → 优化知识

用户先问“MES 最近 15 分钟 Top 10 SQL”。系统确定 Target、窗口和排序，
发现可用统计来源后返回真实可比范围的排名；只有累计统计则明确窗口未完成，
累计参考单独呈现，不能启动一个无关单 SQL 的调查来替代排名。

用户选择其中一条要求解释原因。系统继承精确身份和原证据，按新问题联合查询
语句、对象、活动、监控和可得计划；没有计划不阻止调查锁、负载或应用重试。
回答必须指出哪个原因有何支持，下一项区分性检查是什么，
不能把“高频累计耗时”直接改写成“扫描方式差、需要索引”。

如果经批准采取优化，再以相同业务负载和可比区间验证单位调用代价及写入护栏。
回答更新为实测效果，报告冻结优化前后与混杂因素；
只有满足效果与治理门禁才能成为 VERIFIED_OPTIMIZATION。
没有实施则只能沉淀有价值的 DIAGNOSTIC_REFERENCE，不生成成功记录。

### 20.2 业务卡住 → 锁事务调查 → 处置案例

数据库直连返回匹配时点的阻塞关系后，可确认相应会话事实，不要求再凑第二个来源。
进一步核对事务、等待对象、业务影响及持续性；
若只能看到当前阻塞，不能声称它解释了此前整小时的全部业务超时。

先给出应用事务处理与可用缓解，说明终止事务的回滚成本和审批要求；
不为完善报告而无关地采集所有内存参数。
取得执行与恢复观测后仍核对是否只是阻塞者自然提交或业务流量下降。
报告保留证据区分与实际处置；案例保留成功措施及禁忌，
人工登记的终止操作不会被写成 Agent 自动执行。

### 20.3 备份成功 → 可恢复性缺口 → 排查参考

用户问“备份成功，能保证恢复到昨晚吗”。系统按需要获取备份元数据、
归档/WAL/Binlog 连续性、保留、目标恢复点与介质可读性证据。
现有数据不足时明确“作业成功已确认，目标点实际可恢复尚未验证”。

给出隔离环境恢复演练的检查和停止条件，而不是对生产库自动执行 Restore。
未演练的报告仍可完整说明这次调查与缺口，但不能声称恢复保障已通过。
如调查发现有价值的链路检查路径，可审核为诊断参考；
只有实测演练及对应坐标、RPO/RTO、业务校验满足要求，才记录已验证的相关效果，
不能仅因报告 READY 或人工审核完成而升级。
## 2026-10-28 执行期限实施补充

Run 建立前的队列/规划同样受创建时冻结的绝对期限约束，后台有界轮转收敛，
接受任务、规划前后与启动诊断前重复核验；已有任意 Run 时由 Runtime 管理。
范围澄清最多保留一天，人工等待暂停机器预算，恢复精确结转剩余毫秒，
不得重新发放完整预算。原命令不可改写，恢复后冻结期限优先于原创建期限。
本机制不是新增执行授权，也不代表跨进程强杀远端查询的验收已完成。

## 监控序列的精确计算与重放

监控点保留大整数和高精度十进制字符串，摘要、日均点、期间变化、日变化量及
有界 Theil-Sen 斜率不再经 float 往返。时间点先排序，同刻同值去重，同刻冲突、
无时区、非法数字或超预算时不生成派生值；保留原 Artifact 与可解释警告。
最新值按时间而非数组顺序选择。采样值 P95 只在至少 20 个有效时点时产生，
明确不是单次 SQL 执行延迟 P95；没有逐次执行记录时不能冒充执行分位数。

新增内部 SERIES_COMPUTATION.v1，保存原 Artifact 字段路径、来源/绑定版本、单位、
维度、原始有效输入、计算版本、质量及摘要。单序列最多 4096 点、每份观测最多
8192 个计算输入和 128 行；斜率最多 128 个代表点、有界两两斜率，不执行任意表达式。
模型仅收到结果、质量与引用，不重新发送整组原始输入；调查记录仍冻结完整计算。
回答冻结和报告投影重新计算；正式报告、会话报告、案例提炼及来源复核还回读
同 Run 的原始 Artifact，核对哈希、逐条输入、身份与质量，拒绝仅自述一致的伪计算。

普通趋势/预测仅针对已知 GAUGE；COUNTER/STATE/未知语义只给采样统计，不通过
末值相减冒充计数器窗口增量。截断、缺失点、覆盖不足或单位未知时不预测。
容量预计使用率和耗尽时间仅允许同源、同绑定版本、同目标定位、同单位、
同维度且最新时点相同的 used/max 连接；不由指标名称或显示单位近似推断可比。
此项不代表任意跨源单位换算、对象关系或控制实验归因已经完成；无线上操作或新表。

## 三库同连接物理身份基础

固定目录和动态只读查询都在原连接补采受控身份字段，最多增加一次、最长一秒的
可选探测，仍受原 Grant/Run 截止限制，取消不被探测吞掉。主查询已完成后才探测；
PostgreSQL 先结束原只读事务，探测权限不足不会使主查询结果失效。
PG 读取 system_identifier、启动时间及数据库 OID；Oracle 读取 DBID、实例号、
启动时间及当前容器；MySQL 读取 server_uuid，不声称启动代次或重置边界已知。
Oracle 原始无时区启动时间保持数据库本地时间标识，不擅自解释为 UTC。

Executor 明确标记 SAME_CONNECTION_CURRENT 后，调查来源才接受这些字段；
旧连接测试、缓存探测或仅有逻辑 Target 不充当当前物理身份。
相同原生数据库家族的不同 Target 别名保守归组，Oracle RAC/主备不凭来源数量升级因果。
物理身份未知的来源不能凭逻辑 Target 不同而被认为独立互证。

### 查询访问观测的安全复用

读取结果可冻结访问对象组及探测有效期，但不把成功探测当作当前授权保证。
固定目录与动态只读执行共用有界缓存；当前 Grant 与凭据每次重验，成功查询每次实取。
明确的权限拒绝仅对同域、同 Target/凭据/版本/策略及完整查询参数短期复用三十秒，
命中输出专用缺口并说明未再次查库。认证、超时、对象不可见不缓存为权限结论；
联合查询失败不反推每个对象的权限。缓存过期、时钟异常或配置/实际凭据变化恢复未知。

### SQL 对象关系的逐类证明与重放

SQL_OBJECT_GRAPH.v1 将指定统计主体的显式语法对象引用、匹配游标/计划的对象行、
原生目录的索引归属与分区后代分开保存，不把名称相同升级为运行时访问路径或因果。
先消歧主体，再核对物理数据库/容器、引号语义、采集时间及可得启动代次；
默认 Schema、未知跨库范围、Root 中缺容器的游标、历史/人工材料不得自动连接。
有界图随调查冻结，回答/报告重放；正式报告和案例生命周期还核对同 Run 原始
工具 Artifact 的哈希、行列与身份。对象元数据只生成语义明确的边，
实际计划/代表参数、视图展开与跨源对象映射仍按真实可用证据继续调查。
仍保留 NATIVE_ORIGIN_COARSE：这是当前连接身份基础，不等于跨 Exporter 映射、
逐计数器来源和完整跨源对象图已经完成；未知身份不阻止其他有效诊断。
