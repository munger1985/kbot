### 监控原生身份见证与跨源关系（2026-10-28）

新增可选 db.identity.info 指标与 DATABASE_IDENTITY_INFO.v1 见证协议，
以及 PHYSICAL_IDENTITY_GRAPH.v1 确定性来源图。普通诊断、SQL Evidence Bundle、
不可变调查记录和报告/案例共用同一见证；报告和案例独立重读原始
OBSERVATION_SET / DBA_TOOL_RESULT，重新投影并重建关系，不能靠自述图或哈希副本增信。
类型化时点按值复核，避免Python时区对象repr与JSON重放形式不同而误拒绝。

查询必须在 Source Binding 显式授权的指标集合内，以精确 target_key 定位；
不自动扩大默认基线、Profile、能力、凭据或权限。身份保留为原始字符串标签，
避免PG系统标识/Oracle DBID被浮点化；通过timestamp(info)保留原始抓取时间，
而不是把范围查询求值时点当作原始采样。陈旧、未来、非法、截断及作用域不符均不升级匹配；
有界保留16条身份见证，图最多64节点/128关系，超限明确标记。

PG与Oracle只确认来源自报的数据库族匹配，不能区分同族主备/RAC/Data Guard；
MySQL可确认来源自报UUID匹配，但启动代际仍未知。
Oracle无时区启动时钟不转UTC、不跨来源比较；相同Target/IP/版本不产生身份匹配。
同一采集作用域身份变化或多义时保持未知；近时原生字段不符单独报告冲突。

三库sql_exporter Collector资产见 scripts/deployment/aiops_observability/configuration/identity/。
它们是待实际部署审核的同连接见证生产配置，不含凭据、不自动启用或授予权限。
标准mysqld_exporter没有字符串UUID时保持未知，不能用旁路DSN证明它的来源。
同一job/instance的身份序列也不证明其他指标来自相同连接；
metric_series_assignment_verified、exact_runtime_instance_verified、
window_continuity_verified及independent_corroboration均不因身份自报而置真。

本批已接通来源自报身份关系和原始来源重放，不关闭第①项：
实际Exporter部署配置、其他指标的同连接归属、剩余计数器语义和真实验收仍待完成。
未部署、重启、变更Target权限或发布线上Prompt。


### 跨轮原始来源与行投影约束（2026-10-28）

历史 SQL 筛行统一使用确定性投影：保留原始工件、原时间、内容摘要和原生来源，
重排所选行的原生维度；超过原生身份映射预算的源行显式保持未知，不能借用第零行身份。
每个投影保存原充分性工件/Run/Turn、源证据引用及原始行号，清除不再适用的派生图与图表。
充分性快照只作定位，发现与显式选择必须回查原始 DBA_TOOL_RESULT 或 TOP_SQL_WINDOW_RESULT，
核对原始目标、行值、字段、口径、警告与来源；没有原生映射也不能跳过校验。
提交事务、Worker 每次领取、正式报告及案例发布/检索独立复核同会话所有者、
Agent/Target 版本、当前授权、原始来源与投影，继承密级不得低于任一原来源。
失效时移除旧观测和旧调查判断，保留明确缺口，不只删数值留下旧结论。
用户消息和规划快照只保存白名单选择定位信息，不复制SQL原始行或派生值，
避免撤销正式证据后仍从不可撤销的消息/快照副本读取旧数据。
后台未来观察复用与直接取证共用正式投影，保留原采样警告；独立来源重放通过后，
不再把历史导入事实当成本轮原始工具重复校验。此项不建立跨 Exporter 身份、
历史窗口连续性或真实业务效果的证明。

## 1. 目标、问题与非目标

产品目标：从窗口 Top SQL 或用户指定的 SQL 进入同一诊断流程，对确定的数据库语句、
时间范围和证据，回答“谁在消耗、为何慢/影响谁、如何处理、如何验证”。
诊断必须能联合已授权的数据库直连、监控、日志、计划、对象、应用与变更等可用信息，
形成可追溯的性能画像、原因判断、可执行或条件化的解决方案及验证方法。
系统必须可以诚实地输出部分结果，而不是承诺所有场景都能自动定位根因。

本次重构针对的原始问题（当前实现范围以实施记录为准）：

1. 两端深入分析只提交含标识的自然语言；SQL 所在实例、库、用户、子游标及原始证据行
   没有作为结构化对象传递，后续需要模型重新推断。
2. 单 SQL 可采集累计统计、活动及全库对象数据，但证据没有统一按 SQL、实例和时间关联；
   PostgreSQL 累计统计本身没有历史实际计划。
3. 固定摘要能避免部分错误推断，却主要罗列指标和固定建议；有用的计划、窗口或对象证据
   未必进入结论。
4. 周期快照当前截取有限的累计候选；窗口内新出现、淘汰或统计重置的语句可能遗漏。
   当前窗口取样只选请求区间内快照，精确起止时间通常不与采样时刻重合。
5. 单 SQL 可能再次显示 Top SQL 主表；未知字段被笼统翻译，证据缺口和内部 Finding
   在正文中重复出现。重规划限制不是全流程硬时限。
6. 取证顺序和摘要过于固定，监控、数据库、日志等没有按问题协作；缺计划就只能补计划，
   无法有效诊断阻塞、应用重试、外部资源竞争等并不总以执行计划为中心的问题。

本次设计决策：固定身份、安全、统计语义、证据引用和执行预算，不固定指标清单、
调查顺序或根因候选。复用现有 investigation，而非另建一套与其并行的 SQL Agent；
诊断质量由真实场景中的原因区分、方案针对性和验证闭环衡量，不以填满报表或 Finding
数量衡量。常见路径是经验起点，不是能力上限，也不是每次必须跑完的检查表。

非目标：自动安装扩展、变更目标库配置、执行用户提供的 SQL、自动创建索引或承诺任何一次
都可识别根因；不引入假数据、不按数据库名称或特定 SQL 写特例。

## 2. 产品交互与范围

| 用户任务 | 默认结果 | 口径与动作 |
| --- | --- | --- |
| Top SQL | SQL 文本、统计排名、主要工作量特征与诊断入口 | 默认最近 15 分钟、总耗时降序、10 条；支持调整窗口、数量、排序指标；显示实际区间与候选完整性 |
| 当前活跃 SQL | 指定采样时刻的活动会话 | 明确是时点快照；0 行不代表历史无负载 |
| 多 SQL 比较 | 各主体的画像、原因与方案及跨 SQL 比较 | 同一 Target/引擎内 2–4 个独立请求；缺项保留部分结果，不混算累计与窗口 |
| 单 SQL 深入诊断 | 身份、SQL、证据质量、指标、诊断、建议 | 默认继承原选择的 Target、统计身份与时间范围；不重复展示 Top SQL 主表 |
| 直接输入标识或 SQL 文本 | 先确认 Target 和唯一对象，再诊断 | 不唯一时返回候选供选择；SQL 文本只作为不可信材料，不自动执行 |

当单点不足以区分当前假设时，可按统一 DBA 设计追加一组低成本目录采样，
显示真实次数、间隔、实际时点及中止原因；其当前/累计口径不变，不替代所请求的历史窗口。

用户未明确时间范围时使用最近 15 分钟；保留 5 分钟、1 小时、24 小时及自定义区间。
只在冻结本轮计划时将相对时间转换成带时区的绝对 UTC 范围；展示用户时区和实际覆盖。
查询指定排序字段不可得时提示能力缺口，不默默换排序方式。默认排除事务控制语句的
Top SQL 产品筛选应由可见筛选条件表达，可切换查看，不能修改原始证据或妨碍单 SQL 诊断。
默认不启用周期采集；启用前显示权限、频率、成本、留存、采集模式与生效方式。

任务范围冻结为“排行”“指定 SQL 诊断”或“负载/慢 SQL 调查”，并记录用户待回答的问题、
症状、时间、基线/SLO（如有）和完成标准。仅询问 Top N 时先完成排名和简短负载解读，
不能因历史会话分析过某条 SQL 就自动转为它的完整调查；窗口不可得时明确告知，可分开
展示累计参考，但不能把累计表当作窗口任务完成。用户要求解释原因或解决问题时才进入
相应深入调查；同一引擎与证据链可复用，不让每次列表查询承担完整诊断的时延。

## 3. 结构化对象、跨轮与授权

### 3.1 选择与 Turn 合同

对现有 Conversation Turn 创建合同增加可选的类型化 SQL 选择输入，不能借任意
`client_metadata` 绕过验证。Top SQL / 当前活跃 SQL 每行由服务端生成不透明的
`selection_ref`，绑定不可变的 source artifact、结果集、行序号或稳定行键、内容校验值、
原采集时间、所需 SQL 身份及有效期。展示名称和 SQL 文本不作为可执行输入。

目标 Turn 请求示意（字段名和最终版本在实现时纳入双方共享合同与 OpenAPI）：

```json
{
  "content": [{"content_type": "TEXT", "text": "继续深入分析这条 SQL"}],
  "idempotency_key": "<request-id>",
  "sql_diagnosis": {"selection_ref": "<opaque-row-reference>"}
}
```

沿用现有会话 Turn 路由、认证、幂等及 SSE；原有自然语言或 Starter 不受影响。
服务端对选择引用重新验证调用者、Agent 版本、会话、Target/资源授权、证据归属、
证据完整性、是否过期或已撤权，再从不可变证据提取身份；不能信任浏览器传来的 Target、
用户、SQL 文本或行内容。引用过期/删除/越权/Target 不兼容时返回明确可恢复错误或
澄清，不退化为任意 SQL 或换用其他 Target。重新提交同一幂等键必须语义一致。

自然语言标识输入先解析已授权 Target 的数据库类型，再进行相应身份校验；模型提议
仅是待核验候选。存在多条相同标识或缺必要维度时，展示候选供用户选择；不能把缺失
维度默认为其他用户、Schema、实例或 Oracle 子游标。上下文信息以原来源、时间和证据
可信等级为准，不把上一轮模型结论当作事实；可引用同一授权会话内被明确选择的历史行，
不限于紧邻上一轮，但每次都重验访问权限及目标兼容性。逻辑 Target 相同不等于实例未切换。

### 3.2 SQL 身份与序列化

建立统一的 `SqlSubject` 和引擎维度，区分“已确定”“缺失”“不适用”：

| 数据库 | 必要身份 | 需要保留、不得隐式合并的维度 |
| --- | --- | --- |
| PostgreSQL | 实际实例/集群身份、database OID、query_id | user OID、top_level；多行时分别展示 |
| MySQL | 实例身份、Digest、Schema（含明确的 NULL） | 版本、摘要来源与统计周期 |
| Oracle | DBID、实例/启动代次、容器、SQL ID | child number、plan hash、解析 Schema；聚合前保留各行 |

实例身份使用驱动与目标实际可验证的信息；取不到稳定身份则标 `UNKNOWN`，
不得假定可跨时比较。Oracle RAC、多容器按实际实例和容器归属处理，不能用本地
DISPLAY_CURSOR 冒充另一实例/子游标的计划。哈希、Digest、query_id 并非全球唯一，
SQL 文本差异或碰撞无法排除时返回歧义。

身份格式校验属于引擎与来源适配：PG query_id 的有符号十进制值不能套 Oracle SQL ID
正则，MySQL Digest 按已发现来源格式校验；缺失维度走消歧而不是格式错误或隐式聚合。

当前实现按 PostgreSQL 库/用户/顶层、MySQL Schema、Oracle DBID/实例/容器/游标/计划
保留独立统计主体。PG 只有 query_id 时，可使用版本化 statement.subjects 在凭据可见范围
定向发现完整维度，不猜当前连接数据库就是该 query_id 的库；Oracle 游标读取 DBID/CON_ID，
MySQL 显式 NULL Schema 不降为未知。最多检查 256 行、展示 20 个主体，截断明确保留。
多个完整且未截断的主体可分别诊断并做描述性比较；结论声明 subject_ids，单主体判断只能
引用自己的直接观察，COMPARISON 判断须引用每个参与主体。不能把一条游标的计划或用户的负载
套给其他主体，不生成混合对象图。维度缺失、文本冲突或截断仍保留歧义，不能隐式合并。
表格保留选行继续诊断能力，引用原始充分性 Artifact、原行号及行哈希，续问重验权限和 Target 版本。
历史统计和重复活动会话不扩大当前候选集合；零号子游标及计划值不得在规划时丢弃。
不同 SQL 标识比较使用 SQL_COMPARISON 与 subject_ref.subjects，限同一 Target/引擎的 2–4 个
互不重叠请求；完整 Planner 按问题精确取证，不以全库 Top N 代替。每项请求保留独立解析状态；
一项缺证或歧义不抹去其他项的局部诊断，但阻断整体完成。
完成须覆盖每个主体的直接证据判断，并由跨 SQL 比较连接全部请求，不能只比较各标识内部主体。
共享 20 主体、每观察 40 行与历史搜索总预算；不消除标识碰撞、不承诺无限集合。
多主体图冻结于 sql_subject_graphs，单主体根图与其互斥；报告和案例逐图确定性重放，
并回查各图所用原始 Artifact，不只检查第一份来源。
表格逐候选读取各自原始结果和行号，保留逐行时间与口径。真实三库/模型/浏览器闭环仍待验收。

无选行的续问按明确 SQL 主体搜索同会话最近 16 轮，跨过中间失败/无关轮，最多保留 8 份
观察、512 行和 256 KiB；达到预算须声明不完整。逐来源重新验证用户、Agent 版本、域/租户、
Target 配置和当前授权，以及原始充分性 Artifact 哈希。只投影匹配行并保存原行号、来源链和
原采集时间，不继承模型结论或历史副本。显式选择在取证前也重新读取源并校验原 TTL，
不直接复用接收请求时缓存的可信标签。历史值不是当前值，逻辑 Target 相同不是物理身份互证。

标识、OID、计数器及可能超出 JavaScript 安全整数范围的值经 wire 使用十进制字符串；
内部使用精确整数/Decimal 计算并记录单位，不得先经 float。数据库原生计数及单位保留，
转换规则与舍入由服务端确定；金额式格式化不能改变原始值。

## 4. 采集与窗口计算

### 4.1 采集策略和成本

窗口事实不限定来自自采快照：按已授权资源选择语句原生历史统计、可用报告、
逐次执行日志/事件或自采差分，并核对它们实际回答的排名问题。只有来源确实保留窗口
执行时长与次数、可说明完整性时才能给相应窗口排名；采样日志只能给已采样执行的排名，
活动采样只能给采样活动/等待负载，不能替代完整语句总耗时。Oracle AWR 区间必须按
真实快照与许可处理，不能将一小时分摊成精确 15 分钟。“至少两个可比快照”是差分
路径的要求，不是所有历史来源的统一门槛。

复用 Workload Snapshot 调度、Target 设置、只读凭据与保留策略，扩展为两种显式模式：

- `VISIBLE_SET`：尝试采集配置范围内统计源当前可见集合；记录源权限、可见范围、采集
  起止、行数、字节数、分页/查询方式、上限、截断、错误与来源版本。超限即部分采集，
  不把剩余行伪装成零。动态统计视图未必是原子快照；即使读取结束也不能证明采集间
  未出现或淘汰其他语句。
- `BOUNDED_CANDIDATES`：按配置的有限候选采集，记录筛选、上限和排序；
  只能称“已采集候选的窗口排名”，不能宣称全库 Top N。

记录每批采集的 Target 版本、实例身份和启动代次、数据库/容器、来源、版本、权限、
原生重置/淘汰信息、采集起止与质量。统一行数、字节、超时、并发、单目标和全局配额；
达到预算时停止并产出部分状态，不进行无界全量扫描。周期快照适用于后续窗口，不能
重建此前未采集的历史。采样模式、默认值、存储成本与留存可由管理员调整，任何新增或
变更数据库侧扩展、授权或采样参数须经现有管理流程。

### 4.2 边界、连续性与数值

窗口输入冻结为 `(requested_start, requested_end]`。按目标和采样序列查找
`requested_start` 及 `requested_end` 各自不晚于该边界的最近可用快照；必须
落在配置的最大边界偏差之内，否则报告缺口。显示真实的采样起止、各自偏差、采样间隔、
有效区间和缺口；边界未精确重合时标记为采样对齐区间，不称为精确请求窗口，不做插值。
不得把对齐区间多出的开头或缺少的结尾声称成请求区间。无足够有效快照时可按产品策略
另列累计参考，始终不能关闭窗口缺口。

同一语句同一身份，只对连续、质量合格、源口径一致且实际实例代次一致的相邻快照
计算差值。实例切换、版本/来源变化、缺采超限、字段不可得、计数器回退或已识别的
重置/淘汰都截断相应区间；新出现或消失的记录不能默认从零开始。多段有效区间只对
明确标记的区间求和，显示不连续性和各语句覆盖，不能包装成整个窗口的完整贡献。
全局重置时间、全局淘汰计数或计数器单调只能辅助判断；重置后增长超过旧值、个别语句
重置或淘汰重建可能无法检测，“未检测到”绝不等于“确定未发生”。

对有效样本：

- 执行次数增量 = 结束次数 − 起始次数；总耗时增量同理，执行频率 = 次数增量 / 实际有效秒数。
- 平均耗时 = 总耗时增量 / 次数增量；次数增量为零时显示不可计算，不输出 0 或无穷。
- 可加性计数、I/O、行数与单位必须逐字段声明；已有累计平均值、累计最大值、百分位数、
  规划数及不同计划/实例的值不得未经定义相减或合并。
- 窗口最大值/P95 只来自具备相同统计口径、完整性可说明的逐次记录或可合并分布，
  否则明确不可得。短 SQL 不在活动采样中出现不代表没有执行。

三库固定统计模板以 `NATIVE_MEASUREMENT_LINEAGE.v1` 保存逐字段语义：原生列及原生单位、
SQL输出单位、规范单位和确定比例、求和/取整投影及计数/累计平均/最大/瞬时类型。
当前覆盖41个固定模板及35个配置，含SQL之外的实例、WAL/检查点、I/O、对象、等待和内存。
字段固定选择器、逐行维度和连接维度不能互相覆盖；MySQL状态透视必须保留
`VARIABLE_NAME`。原生NULL索引名是无索引桶，不作为缺失维度，也不借用其他索引。
分组SUM/MAX及PG16/17 I/O乘积保留原生输入和乘积各操作数单位；同一输入经不同
派生表达式出现仍是同源。PG表存活/死行及分析后修改量是估计瞬时值，不自动差分；
内存高水位和累计最大等待也不是窗口最大值。
通用DBA回答投影最多64行/256个换算值，原始证据保留，截断和仅映射字段的核验范围显式说明。
Oracle等待计时采用厘秒原生单位；`V$SQL_WORKAREA.ACTIVE_TIME`是厘秒平均值，
工作区工具按实例/容器/SQL分组，仅返回工作区平均活跃时间的最大值，不能解释为累计SQL耗时。
映射必须精确绑定工具版本、Variant、模板哈希及完整输出列；动态SQL不因同名字段自动继承。
PG 18共享/本地I/O合计保留两个输入，Oracle取整后输出不可还原原值，块大小未知不换字节。
SQL Bundle的 `native_measurements` 由程序换算原输出；缺值不补零，换算不自证请求窗口可比。
每份观察最多64行原生维度，MySQL NULL Schema与缺失分离，PG多库行不借连接库OID，
Oracle缺容器不借Root范围；超限只截断身份映射并说明，不删除原始结果。
调查、报告和案例回放原始工具Artifact的信任、Run/Target、哈希、行列及版本化映射；
删除冻结映射也不能绕过原始来源核验。此机制不自证Exporter或原生对象的实际解析环境，
全局重置上下文不证明单条统计起点，原生计时已有精度边界不能由Decimal换算修复。

排名按用户选择的同口径指标降序，平值按完整稳定身份排序；不能把不同实例、用户、
Schema 或 SQL 计划无依据合并。结果分开表达：采集模式与可见范围、实际时间覆盖、
连续性、每条语句质量、排序完整性及原因；即使 `VISIBLE_SET` 也仅说明已观测统计源
的可见集合，不保证整个数据库的所有执行或源内部未淘汰条目都被捕获。
零行只能表示合格观测没有可排名记录，不证明窗口内没有 SQL。

窗口合同固定返回 `requested_start/end`、`observed_start/end`、边界偏差、
`valid_intervals`、`gaps`、`candidate_scope`、`source_visibility`、
`continuity_confidence`、`rank_metric` 和逐语句质量。显示层不得仅从单一状态值
推断完整性。完整可见集只表示成功读取所声明视图、权限和采样范围内的当前可见行；
不能证明视图保存了所有 SQL，也不能抹去重置或淘汰不确定性。

窗口质量与任务完成度分开表达，不用一个 `PARTIAL` 混合两种语义：

- `availability`：`UNAVAILABLE / PARTIAL / OBSERVED`，分别表示无可比区间、
  存在断点或不合格区间、在声明的范围内满足观测标准；不等价于数据库全量事实。
- `alignment`：`EXACT / SAMPLE_ALIGNED / OUT_OF_TOLERANCE`；容许偏差内的
  采样对齐可满足用户接受的采样口径，必须展示实际起止与偏差，不称“精确 15 分钟”。
  用户要求精确边界而来源不能提供时，明确该要求尚未满足。
- 候选范围、连续性、可见性及重置/淘汰不确定性保留独立字段和原因；候选截断必须在
  排名标题中说明“已采集候选”，不能用边界合格掩盖候选缺口。

采样持续时间、非原子读取及边界误差不能隐藏；累计参考可用不提升窗口质量。
任务是否完成取决于声明的用户目标及接受口径，不因微小采样偏差永久无法完成，
也不因另一类证据可用就谎称精确窗口已取得。任务状态与诊断置信等级见第 8 节。

同名指标需引擎级定义：PostgreSQL `rows` 是统计视图记录的处理行数，不等同扫描行数；
MySQL `rows_examined`、`rows_sent` 不可直接映射为 PostgreSQL 物理读；Oracle
并行执行、游标生命周期和累计值也应保留原生单位及口径。快照间的统计增量反映该
数据源的计数归属，不必然等于窗口内开始、完成或运行的所有语句。

累计起点按来源提供的可验证语义描述；全局 reset/实例启动不能直接充当单条语句
的确定起点，单条重置、淘汰重建及统计容量边界须单列。不能把“累计参考”统一写成
“自实例启动以来”，也不能用统计起点未知否定已观测计数本身。

### 4.3 存储和交付边界

扩展现有 Workload snapshot/statement 实体及版本化 artifact，保存完整身份、原生计数、
连续性和质量；缺值用 NULL 加来源状态，不能用 0 填充。需要容量测试、目标/时间/身份
查询索引和按保留期清理，避免原始 SQL 和绑定值进入日志或通知。

Ammolite 更新 canonical PostgreSQL ORM/初始化及 acceptance；KBot4 更新 canonical
Oracle DDL、manifest、初始化/受控升级和 acceptance，应用层实现数据隔离与业务唯一性。
业务状态、枚举和组合关系由合同与领域逻辑校验；KBot 不新增 CHECK/UNIQUE 业务约束。
不添加运行时自身 Schema 探测、历史双读双写或未经授权的重建/回填。发布须评估现有数据、
保留与兼容影响；实际数据操作、迁移、重建及回滚分别走审批。

| 数据库 | 已有可复用的证据 | 目标补齐及不可推断边界 |
| --- | --- | --- |
| PostgreSQL | 语句累计视图、活动、表/索引元数据及自采快照 | pg_stat_statements 不保存历史实际计划；只在可用来源取匹配计划；规范化语句的占位符并非真实绑定参数 |
| MySQL | Performance Schema Digest、活动历史和对象统计 | 历史环形缓冲会覆盖；按 Digest/Schema 匹配，保留查询版本；估算计划不等于生产实际执行 |

可用性、截断、脱敏和引用。解析 SQL 对象或目录元数据只表示候选关联，历史上实际访问
路径必须依靠匹配计划或其他直接证据。被采集的计划、SQL 文本和运行时参数按敏感级别
控制查看、脱敏、保留及审计，不将原始绑定值发送给模型或日志。

### 数据库与 AIOps 的职责边界（2026-10-29）

数据库负责维护统计信息，CBO 根据数据库统计、解析环境和绑定上下文选择计划并估算成本。
AIOps 不实现另一套优化器，不主动请求重新估算；它读取已经存在的原生计划、统计、
会话、等待、错误与监控证据，解释问题机制、提出方案并给出可验证的结论。

诊断账号只需要对应诊断视图/目录/报告包的最小读取权限，不要求业务表 SELECT、
业务 Schema 访问、切换业务角色、PLAN_TABLE 写入或原业务 SQL 执行权限。
读取字典中某个业务对象的元数据不等于获得该业务对象的数据访问权；不可见时明确缺口，
不据此要求扩权或判断对象不存在。Oracle 包执行授权仅允许读取既有诊断记录的专用合同，
不开放任意 PL/SQL 或包调用。

### 5.1 已有计划与运行证据的获取

| 引擎 | 可以读取的已有证据 | 边界 |
| --- | --- | --- |
| Oracle | 完整游标身份对应的 GV$SQL_PLAN / GV$SQL_PLAN_STATISTICS_ALL、DBMS_XPLAN.DISPLAY_CURSOR；有版本、权限和许可支持时读取 ASH、SQL Monitor、AWR 及既有报告 | 缓存可能淘汰，短 SQL 未必进入 Monitor/ASH；RAC/容器、SQL执行标识、子游标和计划分别匹配；不调用 EXPLAIN PLAN 或写计划表 |
| PostgreSQL | pg_stat_statements、pg_stat_activity、锁与系统统计、对象/索引目录；读取已接入的 auto_explain 日志或 DBA 已提供计划 | pg_stat_statements 不保存历史执行计划；不能从 Query ID 或规范化文本推导绑定值和任意历史计划，不自动开启 auto_explain |
| MySQL | performance_schema / sys 中已有语句、等待、锁及统计，可见目录、已接入日志和 DBA 已提供计划 | Digest 不保存任意历史计划或全部参数；事件历史可能已淘汰，不能从 Digest 重建真实语句执行 |

仅使用已接入并获授权的来源，不把能力清单当作所有来源均已接入或每条 SQL 都有记录。
图形计划与原始计划 Tab 保留。E-Rows、Cost 等字段是数据库原生估算，原样保留其
单位与来源；Cost 不是毫秒，AIOps 不重新估算成本。实际统计只在原生证据具备时展示，
不从估算行数、累计均值或相邻事件造出实际行源。

诊断通道禁止 EXPLAIN、EXPLAIN PLAN、EXPLAIN ANALYZE、PREPARE/EXECUTE 业务语句、
角色切换、业务表访问以及配置/统计信息写入。不因只读事务、审批或旧开关而例外。
已移除估算申请、对象白名单、参数提交、独立审批、专用 Grant/兑换、后台任务调度、
三库估算驱动与执行/回传 API；旧策略即使保存 enabled=true 也不能重新开放路径。
旧待运行任务由于 Handler 不存在而终止，不执行 SQL，不转入补证重试。

没有匹配计划时继续结合 SQL 工作量、每次开销、锁链、等待、错误、索引/统计目录和
资源背景诊断已能确认的范围；不把计划缺失作为所有诊断的硬门槛，也不以“累计值”
否定一切分析。访问路径不能确认时指出这一具体限制。PG/MySQL 不虚构与 Oracle
等价的历史计划能力；需要计划时读取已存在的授权材料或用户上传 DBA 已提供的计划，
不是让用户授权 AIOps 重放或重新规划业务 SQL。

结论区分“发现问题”“已检查范围未见明显异常”“关键证据不足”，关联具体证据、
机制与措施。缺证不代表健康，全表扫描也不自动代表故障；不输出固定审批模板代替诊断。
收集统计、创建索引、配置跟踪等数据库运维变更只能由用户明确请求进入独立的变更流程，
不能从诊断缺证推导执行授权；本次不删除独立变更能力，也不实际执行变更。

### 历史计划证据与隐私清理

不删除历史数据库记录、报告或案例。旧 CONTROLLED_ESTIMATE 结果只读保留独立来源、
原采集时间及 runtime_statistics=NONE 等边界，不改称当前缓存或生产实际执行。
历史读取器仍验证当前作用域、授权、原始 SQL/安全回执、后台关联、独立密文和结果哈希；
篡改或权限变化后拒绝复用。报告/案例沿同一证据链核验，不凭副本自证。
历史参数材料只保留受权限约束的安全摘要和撤回清除入口，不再接受提交或兑换，
参数原值不进入模型、日志、报告。已保存结果不因材料到期/清除而自动丢失，
更不会恢复原来的执行权。移除的是源代码执行路径，不是线上数据清理。

### 5.2 从视图及同义词追到可核验的实际依赖对象

不能把 SQL 文本中的视图名当作底表，也不能靠解析视图定义猜 search_path。
固定工具 db.sql.object_dependencies 按精确 Schema/对象名读取原生直接依赖：
PG 使用 pg_rewrite/pg_depend，MySQL 使用 VIEW_TABLE_USAGE（8.0.13+）；
Oracle 使用 ALL_DEPENDENCIES/ALL_SYNONYMS，并区分 LOCAL/REMOTE。
默认40行，最多200行、256 KiB、10秒；逐对象继续查询仍使用原有只读授权、预算及准入。
目录合同声明 BOUNDED_ENUMERATION，达到请求或默认 limit 时由 Executor 保守标为可能截断，
与完成用户指定条数的 TOP_N 排名区分；没有读取额外行就不能宣称枚举完整。
零行可能来自可见性、目录覆盖或对象类型；例如 PG 固定系统对象的依赖可能未记入目录，
不能据零行证明无依赖。远端引用不自动授权连接另一数据库。

SQL 对象图从已消歧主体的完整显式语法引用或匹配计划目录行出发，
按源/目标字段端点展开可达的本地视图与同义词，再接表/分区/索引目录。
最多四层依赖、128条边，循环去重，预算耗尽显式截断；
每一跳与原语句证据核对物理范围、五分钟时差及可得启动代次，
不能靠相邻近时点连续跳转扩大覆盖。缺失的原解析上下文、远端链接、动态对象或参数保持未知。
目录名称匹配不保证 DDL 期间对象生命周期不变，也不证明运行时内联、扫描、索引使用或因果。
本地依赖目录不是代表参数下的实际执行计划，不能据此关闭计划证据缺口。

回答冻结原字段引用和关系；报告、案例重建关系并回查同 Run 原始工具 Artifact、
哈希、可信度、原始行与身份，不能凭一份自述一致的关系副本升级结论。
真实管理通道只读目录检查与 Agent 绑定诊断凭据、模型及浏览器闭环分别验收。

#### 未限定名称、原生默认上下文及目录候选

对象图的 `references` 保留原语句字段引用、精确名称、解析状态、原生上下文引用及目录候选，
不能因 `FROM orders` 未写 Schema 就丢弃。按 SQL 词法作用域排除 CTE，保留引号大小写；
支持单条 SELECT/INSERT/UPDATE/DELETE/MERGE 中可明确识别的关系名称，
不把字符串、表函数、Oracle DB Link 或三段跨库名称当作已识别本地关系。

- `EXPLICIT_SCHEMA`：原文本显式限定；依然不证明实际访问或 DDL 生命周期连续。
- `NATIVE_DEFAULT_SCHEMA`：仅 MySQL 同一 Digest 统计行原生 `schema_name` 可提供默认数据库；
  使用独立 `SQL_TEXT_DEFAULT_SCHEMA_CANDIDATE` 边，不能排除临时表遮蔽，不能用连接 `DATABASE()` 替代。
- `CONTEXT_REQUIRED`：PG 累计视图不保存历史 `search_path`；Oracle 的 `parsing_schema_name`
  本身不能证明私有/PUBLIC 同义词选择。目录只剩一个候选也不升级为已解析，不自动展开其索引/依赖。

`db.sql.object_candidates@1.0.0` 按精确名称、可选 Schema 读取三库可见原生目录，
默认40行、最多200行、256 KiB、10秒；声明 CURRENT_ACTIVITY 及 BOUNDED_ENUMERATION。
PG 限同连接数据库并使用 schema/table 权限过滤，原生函数显式限定 pg_catalog；
MySQL 保留精确大小写，不虚构稳定对象 ID，临时表不在该目录中；Oracle 限当前容器的
ALL_OBJECTS，并显式返回原生 CON_ID 参与 Root/PDB 范围匹配，不调用 NAME_RESOLVE，不跨 DB Link。
零行不证明不存在，达到上限标可能截断。

每主体最多64个语法引用，每引用最多16个目录候选，截断显式传播。
未取得候选时附带精确名称和固定预算的版本化 lookup 建议，只有会影响原因/措施时才选择；
建议不是授权，仍走签名工具、预算、准入及跨轮去重。评估、重规划和 SQL 诊断模型均获得
服务端重建的对象图，不能只在展示层新增字段。调查、报告、案例重放全部引用；
即使没有已确认对象边或直接事实主张，也必须回读语句及候选原始 Artifact，不能靠副本自证。

### 5.3 已有计划材料的安全导入与逐主体匹配

现有对话附件入口支持 PostgreSQL EXPLAIN JSON（单元素数组或 auto_explain 的计划对象）、
MySQL EXPLAIN JSON，以及 Oracle 导出计划行的 SQL_PLAN_IMPORT.v1 封装。
Oracle 19c 不假定存在统一原生计划 JSON：封装的 plan 为小写字段名的行数组，
至少包含 id、parent_id、operation，可带 options、object_owner、object_name、
object_type、cardinality、cost、last_starts、last_output_rows、last_elapsed_time。
只能有一个根，原节点编号唯一，不能循环或悬空；多个游标或计划必须分别导入。
这一路径读取已有材料，不执行 EXPLAIN、不启动计划采集或重放业务语句。

需要声明 SQL/来源身份时使用如下封装，subject 按引擎提供完整维度；
physical_identity 与 captured_at 可缺省，但核验结果保持不完整/未知，不自行补值：

```json
{
  "schema_version": "SQL_PLAN_IMPORT.v1",
  "database_type": "POSTGRESQL",
  "subject": {
    "query_id": "1285382359565720997",
    "database_oid": "16510",
    "user_oid": "16384",
    "top_level": true
  },
  "captured_at": "2026-10-28T00:00:00+00:00",
  "plan": [{"Plan": {"Node Type": "Seq Scan", "Schema": "mes", "Relation Name": "mes_equipment_signal", "Plan Rows": 1000}}]
}
```

MySQL subject 使用 digest/schema_name（显式 NULL Schema 不当成默认库）；
Oracle 使用 sql_id/dbid/inst_id/container_id/child_number/plan_hash_value。
物理身份按引擎保存 system_identifier/database_oid、server_uuid 或
dbid/container_id/instance_number，以及 instance_started_at；
这些均为用户声明，和数据库来源一致也只能是 DECLARED_MATCH，而不是 SOURCE_VERIFIED。
完整维度缺失、SQL/引擎/启动代次冲突、历史时间均逐主体区分。
有运行统计不等于已核验生产执行，也不证明与代表参数属于同一次执行。

解析上限为 1 MiB、128 节点、32 层、64 个参数类型；重复 JSON 键、非有限数、
布尔数值、异常精度、破损树或超界均拒绝，不把失败计划回退到原文检索。
只保留有界节点/目录标识和精确数值，原 SQL、谓词、表达式、参数键和值、
任意扩展字段不进入安全投影；原上传仍按既有权限和保留策略保存。
如封装带 parameters，仅冻结 NULL/BOOLEAN/NUMBER/STRING/ARRAY/OBJECT 类型序列，
不保存可猜测的值哈希，也不把类型当作代表性证明或执行参数。
安全投影在写入可检索正文前完成，避免 artifact.search 再把原值交给模型。

PG actual_rows 为每循环口径，仅实际循环大于零才与估算比较；
Oracle LAST 输出行数按 starts 归一，starts=0 或估算为零不生成比率。
MySQL 普通 JSON 保持估算口径，优化器成本不当作毫秒，表名可能是别名；
Oracle 索引对象不误投影为表名。解析的运行统计按 NONE/PARTIAL/PRESENT 保存。
逐节点证据使用中文列标签，并保留原生字段含义。

每主体有界核对至多四份已有计划，优先保留该完整主体的匹配计划，不能被其他主体的前四份材料挤掉；
匹配结果进入 SQL Evidence Bundle 和不可变调查记录；
多 SQL 请求分别核验，不能继承第一条 SQL 的结果。记录冻结计划材料与数据库身份锚点引用，
报告/案例重算匹配并回查同 Run 原始 USER_UPLOAD_EXTRACT/DBA_TOOL_RESULT、
哈希、信任、时间、节点和行值，不接受一份自述一致的副本。
人工计划支持具体待核验假设；不能凭上传计划确认生产访问路径或根因。
只读取已有计划；不再提供代表参数提交或独立审批后估算。运行时动态对象和真实三库验收仍受可用证据约束。

### 5.4 Oracle 完整游标的现有缓存计划与绑定元数据

`db.oracle.statement.plan@1.0.0` 和 `db.oracle.statement.bind_metadata@1.0.0`
只读取 Oracle 19–26 现有动态性能视图，不调用 EXPLAIN、DBMS_XPLAN、AWR，不重放 SQL。
两个工具均要求 sql_id/dbid/inst_id/container_id/child_number/plan_hash_value 六维必填；
只给 SQL_ID 时先由 cursor_details 枚举统计主体，不将其他实例/容器/子游标计划混用。
精确身份齐全时基线可读取两个工具，完整调查仍按问题选择所有已授权证据，不把计划设为万能前提。

计划读取 GV$SQL_PLAN_STATISTICS_ALL 的节点、目录对象、估算和可得 LAST 行源，
不读取谓词、projection、SQL 或绑定值。最多读取129行，结构化文档最多128节点；
触及枚举边界、混合身份或树/数值损坏时保留数据库原件和明确缺口，不生成完整计划投影。
绑定元数据使用 GV$SQL_BIND_CAPTURE 与 GV$SQL，按实例、容器、SQL、子游标及 child_address 连接，
再核对六维身份；最多65行，不读绑定名、VALUE_STRING、VALUE_ANYDATA。
last_captured 保留数据库无时区原生时间，不擅自解释为 UTC 或指定执行时间。
两工具各10秒，分别256 KiB及128 KiB，沿用签名 Grant、当前凭据和持续授权围栏。
目录声明 CURRENT_ACTIVITY 观测口径，规划器或 Playbook 不能将其改标为历史窗口/累计统计；
错误在冻结执行前拒绝，不等待取证完成后才丢失结果。

正式 Worker 从原始 DatabaseObservation 重建 origin=DATABASE_CURSOR 的安全文档，
observed_at 为采集时间，与上传计划的 declared_captured_at 分开。完整身份和同连接物理来源匹配时
可给 SOURCE_MATCH，但 production_execution_verified 仍为 false，代表参数仍为 UNVERIFIED。
Root 连接仅在行显式带 CON_ID 时关联对应容器；远端 RAC 实例不能借用本地连接启动代次。
绑定元数据只在同游标、非截断、同物理范围和五分钟内关联；LAST 与 bind capture 不是同次执行证明。

LAST 输出行数按 starts 归一与估算比较；各节点统计不保证可定位为某个完整指定执行。
缺少 LAST 不否认缓存估算计划，零行不当作没有业务执行。报告、案例及未来观察复用均重新读取
原始工具 Artifact 并重建安全文档与匹配结果；删除/篡改派生计划或绑定引用不能自证。
用户上传仍是 USER_PROVIDED，不可通过改 origin 获得数据库信任。

2026-10-28 Oracle 19.3 管理通道只读检查，原模板从同一现有完整游标读取17行计划、2行绑定元数据。
真实17行计划通过安全解析生成17节点，运行统计 NONE；不补造实际行源。
此结果不代替 Agent PDB 绑定凭据、真实模型和浏览器验收；未改权限、Schema、采集开关或线上 Prompt。

## 6. 可发现的信息资源与受控查询

### 6.1 当前基础与待补齐边界

以下是本次修订核对的实现基础，不是对全部环境已接入的承诺：

| 信息资源 | 可复用基础 | 本设计要求补齐 |
| --- | --- | --- |
| 数据库直连 | 三库 Tool Catalog、Target 只读执行、版本能力；Oracle/PG 受控动态 SELECT | 查询实际权限/视图/字段与成本边界；补齐 MySQL 同等安全的长尾只读查询能力 |
| 时序与事件 | Prometheus、Zabbix、OEM Adapter；标准 Metric/Profile；受控 PromQL | 按实际绑定与能力发现可用序列、标签、语义和覆盖；不将 Profile 清单作为诊断上限 |
| 日志 | Loki Adapter、绑定范围内的受控日志查询 | 识别已采集的慢日志、错误/死锁日志、应用日志及其身份/时间关联能力；有 Loki 不代表这些日志都已采集 |
| 计划与材料 | 各引擎目录工具、报告、artifact、受限上传检索 | 匹配 SQL/游标/参数/时间，区分估算、实际、人工来源及可信等级 |
| 主机、拓扑、应用链路、发布与配置变更 | Diagnostic Source 端口已有 host.inspect、topology.resolve、change.query 等抽象，但当前 Adapter registry 未注册相应实现 | 先定义并接入受控 Adapter、授权和审计再启用；APM/发布平台接入不能仅凭端口存在宣称完成；已采集主机指标仍可经监控读取 |

复用 `ports/diagnostic_source.py`、`adapters/diagnostic_sources/registry.py`、
`application/investigation/discovery.py` 和现有 Tool Catalog。不复制第二套源配置、
凭据或查询执行器。两仓库逐项验证实际支持；外部能力只有在相应工具/Adapter 已注册、
绑定、授权、连通和语义验证均成立后才作为可执行动作。缺少某类可选资源不阻止其他有效路径。
基础交付必须打通三库直连、已接入监控与日志、计划/元数据和既有材料；未接入的
APM/变更/主机操作分别列明后续接入范围，不能作为基础功能验收的虚构前提。

### 6.2 能力快照与发现

建立版本化 `SourceCapabilitySnapshot`，由服务端从受信配置与受控探测构建：

- 来源/Adapter/版本、绑定 Target 与实际实例、可关联 host/service、许可与实际可用权限；
- 可查询内容与维度（语句、会话、事务、对象、主机、应用、事件等）、查询接口和策略引用；
- 当前/历史时间能力、留存、采样周期、覆盖、延迟、已知时钟偏差与时间不确定性；
- 可见范围、数据质量、源血缘、支持的身份键及关系解析能力；
- 限行/字节/序列/点数/超时/并发预算、访问风险及需要额外授权的操作。

发现首先读取已有绑定、目录和缓存元数据；仅在具体证据需求出现时做受控探测，不能
每轮遍历所有源、全量枚举系统目录或扫描指标标签。缓存有 TTL，并包含权限、Target、
版本和绑定版本；每个动作执行前重验授权、许可、范围及当前可用性。冻结能力快照
用于审计，不等于许可不会撤销。模型只能选择服务端提供的 source_ref/策略，不传凭据、
地址或任意端点。业务系统多 Target 或数据库到主机/应用关系不明确时先核验映射，
不因 IP 相同或名称相似就跨库、跨服务或跨租户关联。

`AVAILABLE / NOT_CONFIGURED / UNSUPPORTED / FORBIDDEN / UNREACHABLE / STALE`
等能力状态与一次查询的 `SUCCESS_EMPTY / TRUNCATED / ERROR` 等结果状态分开；
0 行只说明相应范围的有效查询未返回对象，不能自动视为无问题或源不可用。

### 6.3 标准目录与长尾查询的协作

Metric Catalog/Profile 继续是标准指标语义与页面定义的唯一来源，Tool Catalog 继续
提供版本化、安全的常见动作；二者是复用和效率机制，不是 Agent 能观察世界的固定边界。
复用 [原生监控设计](aiops-monitoring-dashboard-integration-detailed-design.md) 的
标准定义，同时允许针对具体证据需求发现真实源并查询目录外信息：

1. 常见证据优先复用已验证目录，避免同义重复查询；目录无法表达需求时选择可发现、
   有授权且风险可控的查询能力，不要求先发布一个 Metric Code 才能调查。
2. 监控和直连数据库并列互补。历史趋势通常选时序/历史源；当前锁链、配置和对象细节
   通常选直连；同一问题可组合使用，不存在“监控不足才允许查数据库”的硬性先后。
3. 时序长尾查询先核实真实指标/标签、单位、类型、采集方与重置语义；不得猜测名字后
   把空值填 0 或用未经证实的 rate/聚合公式。PromQL 继续走现有 AST、精确 Target
   绑定和配额；Zabbix/OEM 只使用各自已实现能力，不伪装支持任意 PromQL。
4. 直连长尾查询复用服务端冻结的引擎/版本策略：AST、实际授权目录/视图/字段、允许
   函数、参数绑定、只读保护、成本上限及脱敏。禁止 DML/DDL、锁定/任意过程、任意文件/
   网络访问和未批准函数；不能以“SELECT”或只读事务为无副作用保证。MySQL 须补同等
   守卫及回归后启用，不能直接复制 Oracle/PG 策略。业务表数据抽样、真实 SQL 重放、
   主机命令及采集配置变化不在默认诊断授权内。
5. 日志只查受信绑定、时间和受控过滤范围；记录采样/丢弃/轮转/截断，不把日志中的
   SQL、命令或指令当成 Agent 指令。主机/API 等新源亦必须有能力策略和执行器，
   不能让模型借“需要补证”发起任意 SSH、HTTP 或 Shell。
6. 新观察保留原生语义与血缘；稳定、复用价值高的查询经评审与测试后再沉淀为目录或
   Playbook，不自动修改配置，不在页面生成第二套指标定义。

## 7. 问题与假设驱动的调查、诊断与解决方案

### 7.1 自适应调查闭环

目标工作流是“确定任务/对象 → 发现所需资源 → 提出问题与假设 → 选择取证动作 →
关联证据并检验 → 收敛诊断、方案和验证”，不是固定的“统计 → 计划 → 对象”流水线。

负载/Top SQL 原因调查可在预算内选择多条有区分力的语句、阻塞者或相关工作负载，
联合分析调用、资源与竞争关系；不只盯累计排名第一，也不逐条机械运行全部工具。
选取依据和未覆盖范围可见，采样之外没有排名的阻塞事务同样可能是主因。排行、单 SQL
和负载调查共用证据模型，但保留各自完成标准，不能中途偷偷扩大或替换用户任务。

复用现有 InvestigationPlan/Action，增加下列结构化语义；不另建平行任务系统：

| 对象 | 必填语义 |
| --- | --- |
| DiagnosticQuestion | 用户目标、症状、SQL/负载范围、时间、已知事实与来源、完成标准、已接受的证据口径 |
| HypothesisCase | 可验证的原因、适用时间/范围、支持与反证预测、替代解释、现有引用、状态及尚缺的关键证据 |
| EvidenceNeed | 要回答的具体问题、对哪个判断有影响、必要/可替代性、所需精度与时间、可用源及成本限制 |
| InvestigationAction | 对应需求、受控工具/源/参数、预期产出、依赖、风险、超时、可能改变的判断与停止条件 |

一次循环：

1. 从已核验身份、可用历史证据与当前症状提出少量最有区分力的问题；既有 Playbook
   提供经验路径，模型可提出目录未预列的原因，不局限于预设“CPU/IO/索引”分类。
2. 按需求选择能区分原因的证据，权衡相关性、时效、可靠性、预期信息增益和成本。
   不要求虚构精确收益分数；选择理由可解释、可审计即可。独立低成本动作可并行，
   SQL/对象等未确定时不提前运行依赖动作。
3. 执行器检查安全、授权及剩余预算；结果先登记为 Evidence，再参与计算和关联。
   新信息可能支持、反驳、缩小、拆分或替换原假设；不为维持原结论选择性引用。
4. 若新问题来自证据且能影响用户目标，补做高价值动作；没有可执行的新需求时收敛，
   不因缺口数量未归零、Finding 为空或未拿到计划就重复规划。

停止条件：完成用户目标；关键判断已充分且继续查询不会改变建议；剩余关键证据在
当前权限/历史/预算内不可得；达到 deadline/动作与重试预算；或确需用户消歧/额外授权。
不可追补的历史与未配置采集不能通过重复采样补齐。可短时重采的活动问题必须有新的
观测价值和受控时间，不以新时间戳包装同一查询无限循环。

模型负责提问题、提假设、选择候选动作、跨证据推理及解释方案；服务端负责权限、
范围、查询安全、精确计算、质量与引用校验和收敛。不能把模型限制成只解释固定摘要，
也不能允许模型把新假设直接登记为已验证事实。

### 7.2 可扩展证据模型与关联

版本化 `SqlEvidenceBundle` 是按需求组织的受控投影，不是“几个字段填满才可诊断”
的门槛；可记录任意已支持来源的类型化 observation：

| 部分 | 内容及必填质量信息 |
| --- | --- |
| subject/task/window | 已核验 SQL 与关联资源、任务、请求/实际时间、接受口径和质量 |
| observations | 原生/标准指标、时序、日志事件、会话/事务/锁链、计划、对象、配置、应用或变更材料等；kind/schema_version、值或 artifact_ref、单位/测量语义、时间、范围、来源血缘、权限与质量 |
| relationships | SQL↔session↔transaction↔object↔instance↔host↔application 的有类型关系；身份键、有效时间、direct/verified/inferred/unresolved、证据及关联置信度 |
| derived_facts | 服务端确定性计算值、输入字段引用、公式/版本、适用范围与误差 |
| hypotheses/assessments | 待验证原因、已支持/已排除范围、替代解释和反证，不污染原始事实 |
| gaps/actions | 缺失或冲突对哪个判断的影响、可重试性、替代源、下一步及责任方 |

新增证据种类需注册 schema 与语义验证，不接收无来源的任意 JSON 为事实；
新原生指标可以使用通用数值/时序类型及元数据，不要求每个指标重新硬编码分析规则。
按问题分批检索和压缩投影，保留原始 artifact，不一次把全库表、所有日志塞入模型。
跨轮继承原观察及适用时间，不继承上一轮推理为事实；“沿用”不等于不需检查新鲜度。

关联与解释必须遵守：

- 精确 SQL/实例/用户/Schema/游标、session/transaction、对象与 host/service 映射优先；
  仅文本、对象名或相邻时间相似只能生成候选。SQL 解析处理搜索路径、同名对象、
  视图、CTE、函数和分区；无法唯一解析时按需查目录，不扫描全库。
- 区分采集时间和事件/测量时间；窗口、采样粒度、重置与时钟偏差不匹配时不可精确
  关联。当前配置、索引和计划不能自动代表历史状态；当前无活动不能否定历史慢 SQL。
- 同源 Exporter 与直连读取同一计数器不算独立互证；累计总耗时也不是独占 CPU 时间，
  并发执行时不能简单除以墙钟时间声称 CPU 占用或系统贡献率。
- 数据库/主机指标单独不能归因某 SQL；结合语句身份、等待、时间、资源映射及其他证据
  可支持资源竞争或受害关系。区分“SQL 导致压力”“SQL 被其他工作负载影响”及共同原因。
  时间重合只支持相关性，不自动证明因果。
- 对象级顺序扫描不直接归因目标 SQL；共享块命中是访问次数，不是独立页数或物理读。
  无业务 SLO 不能仅凭平均 23ms 断言正常/异常；但明确死锁、报错或锁链等事实不依赖
  延迟 SLO 才能判断，事实确认和影响严重度分开。
- 分区父表的大小/存活行估计为 0 可能与数据位于子分区有关；不可直接解释为全表为空、
  统计陈旧或“证据无法解析”。零分母比率标为不可计算并按语义处理，不能作为失败卡片；
  修改量低也不能单独证明统计分布准确或所有分区不需维护。
- 负证据要求来源覆盖、身份/过滤和时间足够；采样未捕获、权限不可见或保留期过期不是
  原因不存在。矛盾证据登记冲突，先核对身份、单位、时间和血缘，不以多数投票消除。
- 所有结论可还原到 observation/行/字段及公式；证据权限失效时重新授权投影或拒绝查看，
  不借跨轮引用绕过访问控制。SQL/参数与日志内容不可信，按敏感级别脱敏后才进入模型。

### 7.3 诊断判断：证据强度而不是固定指标阈值

输出 `SqlDiagnosticAssessment`：每条判断记录问题、事实或原因、影响/受影响对象、
适用时间、支持证据、反证/替代解释、剩余不确定性及建议引用。区分：

- 已观测事实：能直接引用的数据或关系，例如当前阻塞链、计划节点、错误事件。
- 有证据支持的解释：存在机制与匹配证据，说明为何更支持该解释、仍有哪些替代原因。
- 待验证假设：列出能区分原因的下一步，不包装成已确认根因。
- 当前无法判断：明确阻止哪个判断，不写成整轮无价值或源中不存在问题。

判断等级按结论逐条给出，不能全篇盖一个“证据充分”章。既无匹配计划也无其他等价
直接执行证据时，不能断言扫描路径，但不妨碍确认当前锁阻塞；只有计划也不能断言业务
调用放大或过去所有参数都如此。
确定性守卫验证计算、身份/时间/范围/引用和安全，不宣称能机械证明模型所有因果判断；
上线需用专家标注和对照场景检验推理。对无法支持的强因果断言降为假设或阻止发布，
保留被拒绝理由与相关证据，不用修改措辞掩盖事实缺口。

校验优先使用已有策略与类型化证据，不为每条回答强制串行再调一轮模型“证明根因”；
必要的复核动作同样须有明确价值并计入预算，避免把质量治理重新变成耗时循环。

常见路径用于启发与测试，不是穷尽原因或每次必跑的框架：

| 问题/证据线索 | 可按需组合的信息 | 可形成的判断与处理方向 |
| --- | --- | --- |
| 总耗时高，单次延迟未同步升高 | 窗口调用量/延迟、可比基线、应用调用/重试、批任务与并发 | 区分业务增长、重复调用、重试放大；按证据选择缓存、合并请求、退避或并发治理，不预设建索引 |
| 单次退化、参数差异或计划变化 | 历史/当前匹配计划、代表性参数范围、统计/索引、变更时间与等待 | 分析访问路径、估算偏差、参数倾斜或发布回归；条件化改写/索引/统计维护/回退 |
| 活跃 SQL 等待或事务拉长 | 当前会话、阻塞链、事务年龄、锁对象、应用事务与可用历史 | 确定当前阻塞者/受害者；先处置事务边界或竞争，不先要求计划；终止会话须另行审批 |
| CPU/IO/内存/存储压力或队列增加 | 语句工作量/等待、主机与数据库时序、其他负载和映射 | 区分本 SQL 高消耗与外部竞争；评估限流、批任务错峰、容量或访问优化，不能单凭高命中调缓存 |
| 报错、超时、死锁、连接异常 | 数据库/应用日志、事件、事务/锁、连接与重试信息 | 诊断错误链路、连接/事务管理或放大效应；缺历史日志时不假造过去事件 |
| 当前没活动，用户投诉历史变慢 | 已有语句快照、慢日志/采样、监控、历史计划/报告与变更 | 调查历史窗口；若确无历史来源，给已确认边界与后续采集方案，不循环查询当前活动 |

### 7.4 解决方案是交付物，不是统一“再补证”

每条 `Recommendation` 必须关联诊断/假设、适用时间与对象，给出：

1. 为什么做：要解决的原因/影响、证据、反证和适用条件。
2. 做什么：具体动作或条件化方案；区分立即缓解、根因修复和必要的验证/补证。
3. 如何安全做：目标与版本、前置检查、权限/审批、执行责任方、风险/副作用、变更窗口。
4. 如何证明有效：可比窗口/负载/参数与基线、成功指标及接受标准；同时观察吞吐、错误、
   业务影响和写入/资源成本，避免只让单条 SQL 快却损害整体。
5. 如何退出：停止条件、回滚/恢复方式和验证；不能完全回滚的动作必须明示恢复限制。

方案可涉及索引/SQL/统计信息，也可涉及调用放大、重试策略、事务边界、并发、批任务、
资源容量或发布回退。只能解释支持该方向的证据，不能把经验清单原样当最终方案。
未确认原因时仍可提供明确条件与验证步骤的候选方案，不必全部退化为“缺计划请补充”；
但不能声称未经验证的改动必然有效，不能编造收益百分比。

可在对象、引擎版本与安全前提核实后给出具体查询或变更草案；生成建议不等于获准执行。
只读诊断可展示标为“待验证/待审批”的方案及风险，不因没有执行权限就一律隐藏措施。
实际执行仍走现有逐项审批、最小权限和审计；不自动执行草案，不自动结束事务、
建索引、改参数或开扩展。草案仅在显式执行流程重新验证后才可成为工具输入。

验证指标必须与来源相符：窗口平均耗时用总耗时增量/次数增量，累计 max 不相减，
P95/P99 仅在分布/逐次记录可支持时使用；必要时以可用的平均、吞吐、等待或错误率
定义验证。只做观测而无变更不需要虚构回滚语句；有不可逆影响时不能声称“删掉即可”。

SQL 改写建议还须列明语义保持条件及正确性验证，覆盖 NULL、重复行、聚合/排序、
时区和事务一致性等与该语句相关的风险；不能只验证耗时。索引建议基于已核实的
定义/有效性、选择性和访问证据，避免重复索引或只优化读而忽略业务写入成本。

### 7.5 输出契约与行为示例

排名回答交付排名、时间/范围、主要工作量特点及选择入口；单 SQL 回答先给核心判断与
影响，再给关键依据、最有价值的措施、验证及真正影响判断的缺口。数值表是证据摘要，
不能替代诊断；有可信原因时必须解释机制，而不是只列计数器和风险声明。

- 高频 SQL：若可比窗口显示执行次数明显增长、均耗近似稳定，且应用证据支持重试
  放大，则解释调用增长的影响并给退避/去重等针对性方案；无应用证据时只确认
  工作量变化，重试为待验证原因，不用累计排名直接判定调用放大。
- 无计划的当前阻塞：若会话、事务与锁链确认阻塞边及时间，明确阻塞者、受害者及
  当前影响，建议核查/缩短事务并给处置风险；历史缺失只限制历史归因，不阻止该诊断。
- 有匹配实际计划：解释相关节点、loops、扫描/返回差异、参数与对象，并用索引/统计/
  选择性证据评估具体优化；单计划不代表所有参数，最终措施包含同负载验证和写入成本。
- 只有累计统计：如实说明画像与计数边界，只列高价值待验证原因及安全措施；不宣称
  当前异常、不算伪窗口，也不把“Finding 为空”当开场或解决方案。

示例描述行为与所需证据，不能把示例中的故障预写入真实数据库的结论。

## 8. 执行状态、预算与展示

### 8.1 时延与执行治理

复用现有编排、工具和 worker，禁止为单 SQL 再叠加一轮固定摘要/重复完整规划。
设全流程持久化硬 deadline，覆盖排队、模型、工具、重规划、组合及终态提交；各下游
受剩余预算约束。交互默认预算目标为 90 秒，可受控调整；为汇总及可靠终态保留预算，
目标先在 15 秒内展示已确认基础进展，不将心跳当有效取证，不保证外部系统必定达标。
排队时亦由独立超时/租约机制收敛，不能等 worker 领取后才开始计时。

每轮有可配置的动作数、并发、token、查询成本和重试预算；按需求终止而不是为用完轮数
继续查询。动作去重键含实例/Subject、来源/策略版本、查询与参数、观测窗口和所需新鲜度；
只有新证据需求或允许的短时重采才能重做。不可重试的历史缺口/未授权直接停止该路径，
暂时性故障有限退避，重试也计入全流程预算。关闭与本任务无关的通用采集，PG 不应因
Oracle Alert Log 或无关复制指标缺失而延时或被判诊断失败。

支持端到端取消、驱动查询终止/资源隔离、租约释放、幂等收敛与审计。上层 timeout 不代表
底层查询已结束；必须验证连接/事务/任务回收。超时后禁止继续创建动作或追加第二份回答，
迟到结果单独审计。预留结构化事实的安全降级输出，模型超时也能交付已取得的可用结果。

确需用户消歧/审批/提供材料时进入 `WAITING_USER`，结束当前自动运行预算，显示具体
请求和期限；用户回应后按授权创建续跑预算，不能把人工作业等待显示为数据库运行。
挂起超过期限或用户跳过时按已有证据终结；deadline 机制需区分挂起与运行，不能后台
无限等待，也不能在等用户时继续取证。
客户端断线不自动等于取消，重连可取同一结果；有明确取消请求时收敛为取消终态。

### 8.2 三个独立的质量维度

| 维度 | 判定与呈现 |
| --- | --- |
| 任务执行 | `COMPLETED / PARTIAL / FAILED / CANCELLED` 为终态；`WAITING_USER` 为挂起状态。按用户完成标准判定；外部能力不支持或证据不足不是系统崩溃 |
| 证据质量 | 每个窗口/来源/结论独立给覆盖、对齐、候选范围、时效及缺口；不压成一个“充分/不充分”布尔值 |
| 诊断置信 | 事实、支持解释、假设或无法判断，逐项表达；任务完成不代表所有根因已确定 |

用户只要排行且已取得接受口径的结果，可完成；用户要精确窗口却只取得累计参考则部分
完成。用户要求确认根因而只有画像时同样部分完成；无计划但当前阻塞诊断与方案已充分，
可完成该目标。可选主机/APM 没接入不自动变部分完成。真实系统错误且无可用结果才标
失败；零行可能是成功的空查询，也可能不足以回答历史问题，按目标区分。
所有原因码保持稳定，不能用调整状态掩盖缺口。

### 8.3 结果展示与可观测性

SSE/非流式消费同一版本化 Assessment/Recommendation 与展示投影；进度说明当前回答
什么、为什么需要及取得什么，不泄露凭据/绑定参数。状态转换、幂等和租约保证只产生
一个终态及一份权威结果，重试/重连不重复渲染。

Top SQL 使用紧凑表格显示 SQL 片段、执行次数、总/平均耗时等与本次排序相关字段；
标识可复制、完整脱敏 SQL 可展开，其他技术列按需查看。单 SQL 使用详情与诊断视图；
不因来源工具名是 statement.top 就重新显示整个 Top SQL 表，也不重复“有数据累计表”
与“空活动 Top SQL 表”。其他范围的观察保留于证据区并正确命名。

按结论与用户影响排序正文，不用内部 Finding 数量组织回答；没有 Finding 不写
“本轮 Finding 为空/无卡片可解释”。Finding 是可选的诊断投影，不是回答门槛。
字段有稳定名称、单位与维度，例如数据库/用户/top_level，不能把它们展示成“观测字段”。
缺口按问题及根因合并，区分真正影响建议的关键缺口和无关/可选资源；原始证据仍可查。
模型/工具耗时、队列等待、重试、去重、token、覆盖、实际取证收益、取消回收和终态
均有脱敏记录，用于查清一次 500 秒究竟花在哪里。

   方案、草案审批隔离和可比验证。替换 `diagnosis/sql_evidence_answer.py` 固定摘要
   作为唯一答案，以及 `workers/turn_answer_handlers.py` 的单 SQL 固定摘要/按工具
   类型展示主表路径；不是再加一套关键词特例或 Prompt 补丁。
6. **全流程执行与 UI**：持久化 deadline/取消/去重/终态，排行与单 SQL 不同投影、
   真实进度/关键缺口与证据；同步 SSE、前端字段和两端产品/运维文档。
7. **逐场景真实验收**：先做一个已授权真实库的“排行→选 SQL→取证→原因→方案→验证”
   纵向闭环，再补齐 PG/MySQL/Oracle 同语义矩阵与差异边界。单库完成不等于三库交付；
   不能先宣称功能完成再把关键接入/关联/原因分析留作后续。

每个切片同步合同、实现、schema/初始化（如涉及）、测试和文档，两端分别验证；
不得仅复制文档宣称实现对齐。按项目变更流程批准部署/回滚，不擅自重启或改目标库。

### 10.1 正确性与安全矩阵

| 场景 | 必须观察到的结果 |

| PostgreSQL 同 query_id 多库/用户、超过 JS 安全整数范围 | 身份/字符串精确，不跨用户、实例或库串联 |

OBJECT_ACCESS_OBSERVATION.v1 保留原时间、请求和查询摘要，贯穿取证、模型、冻结记录及

| 取消、挂起、队列超时、模型/工具挂死、断线重连 | 有界收敛、底层资源回收、单终态；SSE/非流式一致 |

### 10.2 真实运维诊断场景

使用真实引擎和可核验负载构造下列对照；故障注入必须另行授权，不能在生产自行制造故障。
相近指标不同原因必须导致不同调查路径和建议，不能只让模板多填几个字段。

| 对照场景 | 取证与方案验收重点 |
| --- | --- |
| 总耗时同高：高频稳定 vs 单次退化 | 分开调用增长/延迟退化；有可用应用重试证据时追重试，不都建议加索引 |
| 相似慢 SQL：锁阻塞 vs 扫描低效 | 前者依锁/事务证据，后者依匹配计划/对象；无计划仍能给正确阻塞处置方案 |
| 相似 CPU 高：本 SQL 放大 vs 其他批任务竞争 | 联合等待/负载/主机与映射，区分来源与受害者，避免归因倒置 |
| 同 SQL：参数倾斜/计划变化 vs 业务量变化 | 选择匹配参数/计划或基线/调用证据；相应改写/回退或调用治理，不混原因 |
| 延迟近似：应用重试/连接等待 vs 数据库执行 | 对齐应用与库耗时/事件；不把端到端延迟直接当数据库耗时 |
| Top N 高耗时语句 vs 排名之外的长事务阻塞者 | 允许多 SQL/事务关联，找到真实竞争关系，不把排行第一当作必然根因 |
| 监控缺指标但直连可用；数据库无当前活动但有历史日志 | 自动使用能回答问题的授权来源，不把监控或活动快照设成唯一门槛 |
| 无匹配计划但有死锁/错误；无任何历史 | 前者给事件/事务诊断及措施；后者诚实部分结果，停止不可追补查询 |
| 有匹配实际计划且有可验证低效路径 | 给针对性措施、风险、审批草案与可比验证，而不是只有“请补计划” |
| 可选 APM/变更源未接入，或只有累计统计 | 未接入不伪造；能回答的任务正常完成，不能回答窗口/根因的明确部分完成 |
| 自采快照缺失但有合格历史源，或只有采样日志 | 前者按真实时间/授权获得历史证据，后者限定为采样范围；不强制走双快照路径 |

每个用例预登记环境/版本/许可、可用源、故障真值和可接受解释、关键证据、错误归因禁项、
预期措施与验证条件；运行时隐藏故障标签，防止按测试名称猜答案。记录实际发现的资源、
动作选择、原始 Evidence、计算、判断、建议和最终 UI。由 DBA 复核机制与措施，不能仅
用“出现预期关键词”或模型自评判通过。根因未必唯一，应接受有证据的替代解释，不强行
要求与预设标签完全同文。

### 10.3 闭环、性能与交付门禁

- PostgreSQL、MySQL、Oracle 分别完成真实业务读写下的基本路径，源端事实、快照、
  推理和 UI 可追溯；历史计划、AWR、分位数及额外 Adapter 按版本/授权单列能力矩阵。
- 在预登记的可诊断用例中，必须给出有依据的原因、具体或条件化措施、成功标准与风险；
  不能全部以部分结果、补证清单或固定“缺 SLO”免责。无法诊断的用例必须如实限定。
- 在授权测试环境对至少一个代表性措施做受控变更与同负载前后比较，验证延迟/吞吐/
  等待/错误和副作用；无效果也必须正确识别，不以累计值上涨当优化成功。无执行权限
  时验证方案草案和审批边界，不能宣称已执行；实际变更证据作为相应发布验收门禁。
- 单元/契约/架构/故障注入与真实 UI 测试共同覆盖；单测或跨仓库对齐检查不是诊断有效
  的证明。回归集纳入此前 SQL_ID 误校验、重复卡片、漂移到旧 SQL、错误累计起点、
  无关 Finding 前言、对象统计误归因和无限重规划等反馈。
- 测量排队、模型、工具、重规划及汇总各段耗时、P50/P95、完整/部分/失败率、
  查询开销、保留空间、并发和取消回收；分任务/场景报告。默认 90 秒目标需真实验证，
  包括正常场景有用答案在预算内交付及异常场景按 deadline 收敛，不能用大量立即
  PARTIAL 刷时延，也不能容许静默运行 500 秒。超预算异常有告警与定位证据。
- 主设计、监控设计、产品入口和当前边界文档保持一致；仍未实现的内容继续标为目标。
  文档提交本身不启用采集、不部署、不修改数据库、不执行用户 SQL。

本设计的完成标准不是“永远有根因”，而是同一受控引擎能随可用证据选择正确调查路径，
在有证据时给真正有针对性的诊断与解决方案，在无证据时准确停在边界，并能通过同负载
验证区分“措施有效”“无效或有副作用”。
## 2026-10-28 三库受控动态采样

单 SQL、等待与长尾目录查询可以声明一组有界 sampling，而不是仅重复固定工具。
动态 SQL 先按各引擎原有 AST、对象/函数和许可策略验证并冻结，单次上限为
5 秒、200 行、128 KiB；EXPLAIN 语句及需要审批的查询不进入采样，不限制合法的现有计划视图读取。固定与动态采样
共用整轮一组、2–4 次、间隔 2–10 秒、至多 60 秒及任务/Run 剩余预算。
每次具有独立 Grant、请求身份和当前凭据兑换；保留各时点原始结果与完成数，
不把采样时点改标过去窗口，不直接差分累计最大值，也不把同源样本当独立互证。
普通固定/动态查询和采样共享 Executor 进程只读并发，不能各自叠加配置限额；
逐 Target/来源及跨进程配额、来源跨请求分页仍属于未完成范围；
后续证据复用及三库同执行游标分页已由下述增量接通。

## 2026-10-28 持久化未来观察增量

对需要较长观察、且已声明 observation_schedule_policy 的低成本固定工具或三库受控动态查询，
模型可提出 observation_schedule：次数 2–4（含当前成功基线）、间隔 30–900 秒。
它与短时 sampling 互斥，共用每轮一组额度；不能通过换间隔重复安排同一动作。
仍受原 AST、对象/函数、只读和 Oracle 商业许可边界限制；不发起任何 EXPLAIN。
单次最多 5 秒、200 行、128 KiB，不改变周期采集配置、数据库权限或业务表。

基线完整成功、未截断且时间/目标合法后，在完成事务内复用现有 Run/Task 建立 EVIDENCE_FOLLOWUP。
原始基线 payload/hash 不变，调度关系保存在独立请求 Artifact 和 provenance；整源 Run 最多一组。
等待由持久化 available_at 承担，不占 Worker 或连接 sleep。每时点最多一次，不因 Worker 重启重试整点；
后继至少在前点完成后再等待声明间隔，不密集追赶。领取迟到超过 30 秒不再查询。

每次领取、兑换凭据以及读取结果重新核验来源哈希、Agent/Target 版本、当前策略和凭据绑定。
执行前撤权/取消不兑换凭据；已知物理实例身份变化或丢失、旧时间、重复请求及口径变化不纳入序列。
未知物理身份仍保留未知，原始观察不自动成为可比较窗口。出现查询缺口或截断立即结束后续采样，
Run 如实标为 PARTIAL；失败、取消、租约过期和截止时间保留已落盘时点，不伪造未执行观察。
汇总通过真实任务产物键重放；终态读取复算原始序列，不让副本自证。原始来源损坏不阻止取消收敛。

对话显示后台观察入口；运行记录支持查看状态、逐时点原始表格、刷新及取消。
运行中展示已采集进度而非完成回执，取消后仍可查看有效原始记录。
该批先交付调度和查看；后续复用链已由下述增量接通，统计可比性仍须独立核验。
本增量也不关闭分页、跨进程/逐 Target/来源联合配额，以及真实三库/模型/浏览器验收。


## 2026-10-28 三库受控动态查询的有界游标分页

工具卡声明 pagination_policy 后，规划器可按明确的 evidence_need/decision_impact 设置
action.pagination={page_size:1..200,max_pages:2..4}，每轮最多一组。只适用于三库受 AST
策略约束的动态只读查询；不能与短时采样、后台未来观察或 EXPLAIN 叠加，不改变对象、
函数、Oracle 商业许可或当前凭据边界，固定目录工具不能借此扩大结果上限。

规划冻结总行数（至多800行）、有效行内容字节（1MiB）、列/单元格和20秒语句上限，
一并写入签名 Grant。SQL 最多多一行哨兵；哨兵只判断是否触及总行数上限，不进入结果。
每项动作独立冻结，分页扩大后的行数不能流入同轮其他普通查询。重规划指纹忽略分页
大小及其生成的顶层 LIMIT，不能通过反复改变页数重新调度同一分页查询；允许一次性
查询在确有证据需求时升级为分页，不授予无限重试。分页任务不整组自动重试。

同一授权和一次只读执行中持续读取原游标，不用 OFFSET 重跑会变化的性能视图。
PG 使用服务端 Cursor.fetch；Oracle 收紧 arraysize、关闭预取并逐行有界物化字符 LOB；
MySQL 使用 SSCursor，独占连接关闭时不排空未读结果。每页及合计预算同时受限；
行数、字节或单元格超限时保留有效前缀和实际页行数。取消不吞掉异常或返回伪成功，
连接清理沿用三库取消路径。网络/超时导致未完成的请求不冒充有有效返回，仍呈真实缺口。

一个分页查询只产生一个原始观察和一个证据引用，不作为多时点或多源互证。
分页摘要保留 requested、returned_page_rows、stop_reason；EXHAUSTED 只表示已读完
本次有界查询，source_completeness 固定为 UNKNOWN，不证明整个来源全量、过去窗口、
当前持续状态或可比较增量。截断结果标为 PARTIAL，不包装为完整成功。
Executor 拒绝缺失摘要、预算不匹配及行数/截断状态不一致的结果。
分页范围贯穿调查、SQL诊断上下文及正式报告/案例来源复核；改导入副本预算不能自证。
两端计划页面展示同次查询分批，不将“4页”展示成“4次采样”。

本增量仅交付数据库同执行游标分页；监控来源的跨请求分页需按各 Adapter 的真实合同，
联合配额、真实三库/模型/浏览器和并发恢复验收仍需完成。未新增表、执行 DDL、部署、
重启、修改目标库权限或发布线上 Prompt。

本地分页专项两仓各44项通过；与排队期限及取消回归合跑各53项通过。
完整回归：Ammolite 2202项及222个子测试，KBot4 2154项及147个子测试通过。
两仓架构、OpenAPI、双向关键语义对齐通过；Portal类型检查/构建与KBot四个Node合同通过。
回归使用Driver/凭据/仓储替身；不冒充真实三库、真实模型、浏览器或多进程验收。

## 2026-10-28 后台观察接入后续调查、报告和案例

后续用户 Turn 会有界定位同会话先前安排的后台观察，不需要全库搜索或重跑整个采样。
只导入已结束且有原始终态汇总的观察；完成、部分、取消、失败和过期状态仍分别保留，
运行中不冒充完成。每个导入组重新核验源 Turn/Run、用户、Agent 版本、Target 配置与当前绑定，
逐时点重放原始产物；原汇总、请求、基线或任一时点变化均不能靠重算导入副本哈希自证。

搜索限当前会话前 16 轮、最多 2 组；与 SQL 历史上下文共用 8 份事实、512 行、256 KiB 预算。
没有足够预算时不悄悄扩大上下文；已接纳事实携带有界搜索提示，不将未检索到解释为历史不存在。
导入覆盖固定及三库受控动态工具，不按某几个指标框架限制后台观察的诊断用途。
后台运行结束不会自动发起新调查或执行动作，只有后续用户请求才进入分析。

计划提交、Worker 领取、正式报告和案例发布/检索时再次检查当前授权及原始来源。
失效导入变成明确缺口，旧充分性副本中的相关值与旧模型调查判断也不再送入模型。
历史 SQL 继承入口不接纳这类后台事实，避免换个封套丢失原始来源重验。

证据与统一调查记录新增 followup_run_id，保留真实 captured_at、原始统计口径、原行数、
截断及来源等级。后台观察不充当本轮 Top SQL 的主结果，也不满足当前功能入口的主结果要求。
不把这些时点改称当前值、原请求过去窗口、完整窗口排名或已验证优化；累计最大值不相减。
差分和效果判断仍须原有主体、物理身份、重置、单位及窗口可比性检查。

正式报告保留结构化结论的 claim_id、适用时间、等级与证据引用，
不再把它们压缩成仅有摘要且信任字段为空的对象；不会给推断伪造 SOURCE_VERIFIED 等级。
报告和案例共用原始来源重验，即使没有 Finding 或对象图也不能跳过后台证据复核。

### 执行计划优先，不以累计统计摘要代替诊断

明确 SQL 的访问路径调查应优先复用已有匹配计划，结合实际工作量、等待、对象/索引及
资源背景解释机制；计划不是锁阻塞、事务或错误诊断的普遍硬门槛。只给累计计数及

Oracle SQL_ID 首轮发现完整游标后，正式重规划入口确定性编译缓存计划续取，不要求
模型再次猜测已知参数；工具仍经过授权目录、签名 Grant 和只读 Executor。自动续取

明确说明，不能宣称检查了全部游标。

PG 语句统计和 MySQL Digest 不能按标识还原历史计划；能力对齐指统一的计划导入、
已有原生证据读取、已有计划导入与计划解释，不虚构各引擎都能直接读取缓存计划。
对话只提示已有计划材料入口，不收集代表参数或发起估算。历史估算/缓存/人工计划

与 Oracle LAST 合计行数/启动次数不混用；人工声明一致不证明生产执行或参数代表性。

可继续发现数据库工具、动态只读查询、监控、日志及对象/计划材料，不建立诊断指标白名单。
一般性窗口缺口不自动重规划；没有问题时明确暂不变更。观察/验证建议不强造变更风险和回滚，
修复/缓解及 SQL 草案仍必须有条件、风险、验证、回退和审批。

通过字段引用、主体身份及统一调查合同校验的诊断，作为 `SqlDiagnosticCheckpoint` 随
充分性 Artifact 持久化，并随重规划传递。检查点绑定整个冻结任务范围、引擎及原始证据指纹；
同证据回答和流式展示直接复用，不重复调用模型。新证据触发重审，不能把上一阶段判断冒充
已审阅新增证据。后续模型失败停止重复生成，只保留仍可重新核验的阶段判断和原适用时点，
整体保持 PARTIAL；硬截止恢复还必须通过正式 Artifact 哈希、当前授权及原始来源复核。

真实 SQL 诊断本身可以使用回答预留，而非先被通用评估耗尽；总截止前保留少量确定性交付时间，
不刷新 Run 期限，不硬编码模型 token 上限。模型输入去除重复对象图和执行器内部血缘，
保留原始记录、精度、主体、物理身份及计划/计算来源限制；交互输出与完整报告分离。

### 交互输出、计划解释与冻结记录的职责

`SqlDiagnosticResponse` 是模型专用的交互合同，不是新对外 API 或另一套调查记录。
单主体最多四项 findings、三项建议；多主体仍逐项判断和比较。短引用只替换引用字段，
不得替换 SQL、对象名或指标原值。服务端按已引用的真实观察重建适用时间，恢复原始
Artifact 引用及正式结论，仍执行所有原有字段、信任、身份和因果作用域守卫。

有匹配计划时必须返回 `plan_reviews`：每项绑定原始证据、最多四个关键节点及唯一
finding，明确机制和影响。对应节点必须真实存在，重复、未知或其他主体的节点不得
借用。服务端绑定原始 operation/options 行字段，把解释并入结论；Oracle 稀疏原生
行号须按真实树遍历映射，不能把原生 ID 当投影节点编号。多主体完成必须覆盖各主体
已有的计划。完整计划表不被关键节点解释数量限制截断。

交互正文复用已核验的结论与建议，不重新生成完整报告。报告、案例继续读取同一冻结
记录，保留计划解释、字段引用和时间边界。旧检查点若缺少已有计划的解释，不得当作
同证据的完整新诊断；仍有效的局部历史判断只可标记部分完成。

模型调用必须把本次剩余期限下传托管服务及 Provider，服务端取消非流式生成；不能
让客户端已截止而托管端继续无界生成。输入大小与耗时可观测，但不记录证据正文。
不靠延长整轮预算或 Agent 硬编码输出 token 上限掩盖交付合同过重的问题。
开发 Prompt 保持 `1.0.0`；代码和 Prompt 输出合同必须成套生效，不能提前在旧代码上
激活新合同。真实模型回放仍不等同新代码已部署或三库生产闭环验收。

## 2026-10-29 执行计划双视图

用户选定 B 数据流图为默认，结合 C 节点详情，并保留紧凑的标准计划输出。
同一个执行计划组件提供“图形计划 / 原始计划”两个 Tab，不重复生成两份诊断卡。

- 服务端在现有 `SQL_EXECUTION_PLAN` 表格块内增加 `plan_graph`：
  `schema_version=SQL_PLAN_GRAPH.v1`、`database_type` 和 `nodes`。
  节点直接来自已通过身份及来源核对的 `SqlPlanDocument.nodes`，保留
  `node_id/parent_id/operation/schema_name/relation_name/index_name/object_name_semantics/metrics`。
  不解析字符缩进重建树，不添加 SQL、谓词、绑定原值或虚构指标。
- 图形使用从输入到父算子的真实有向边，表示数据流而非严格执行时序。节点颜色只编码
  连接、聚合、排序、访问或控制类别；未知算子中性展示。FULL 不自动标记异常，
  不把优化器 cost 画为耗时占比，也不把可能包含子节点的耗时相加。
- 点击节点显示对象、索引、上下游、来源及全部已有原生指标；保持数值字符串精度和零值。
  Oracle LAST 合计/启动/微秒，与 PostgreSQL 每循环行数/毫秒保持区分；
  MySQL 估算成本不冒充运行时间，导入材料不自行升级来源信任。
- 支持滚动、缩放、全屏、聚焦直接上下游及折叠输入分支。局部聚焦/折叠只改变图形，
  原始计划始终保留全部已取得节点，不隐式丢弃根、分支或重复算子。
- 原始计划按安全投影中的标准节点顺序显示算子、对象和已有统计列，行高约 32px。
  父子连接使用贯穿相邻行的树线，不使用被表格行距切断的字符。该 Tab 是已取得计划的
  标准节点输出，不冒称包含被安全策略排除的原生 SQL、谓词或绑定参数全文。
- 历史冻结块未包含结构节点时仍显示已保存的原始表格；图形明确说明缺少结构材料，
  不从旧文字猜树，不改写历史证据。
- Ammolite 与 KBot4 使用相同的展示器及 CSS，实现一致的图形、原始计划和交互；
  仍沿用各自主题和全局按钮样式。展示操作不连接数据库、不调用模型、不扩权，
  不增加持久化表列或变更 Prompt。

验收覆盖两端深浅主题、桌面/窄屏、连续树线、Tab 键盘交互、节点详情、折叠/聚焦、
128 节点上限、HTML 转义、多计划实例隔离，以及三库原生单位/身份与证据引用。

## 2026-10-29 Oracle 单 SQL 专属证据闭环

三库对齐诊断目标、证据可信度和交付质量，不把 Oracle 降为最低共同工具集合。
保留原生报告入口，新增四个参数化只读 Fact Tool：

| Tool | 用途与边界 |
|---|---|
| `db.oracle.statement.xplan` | 核对 DBID、实例、当前容器、SQL_ID、子游标及计划哈希，读取本地 DISPLAY_CURSOR 的 ALLSTATS LAST、谓词、别名及 Outline；不取绑定值、不执行原 SQL。远端 RAC 游标不以本地计划代替。 |
| `db.oracle.statement.monitor` | 在已确认 Diagnostics/Tuning Pack 下发现精确游标仍保留的最多三次 QC/串行执行，保留微秒、I/O 及等待计数；不是指定窗口增量。 |
| `db.oracle.statement.monitor_plan` | 只从上述正式原始行绑定 sql_exec_id 与原生开始 DATE，读取该实例的进程行源、I/O 和工作区。保留进程维度，不冒充全 RAC 汇总或精确节点 CPU 时间。 |
| `db.oracle.statement.ash` | 在 Diagnostics Pack 下按完整游标及带时区窗口聚合内存 ASH 的状态、事件、计划行及阻塞者；保留样本数、分组前总样本数及首末采样时点。 |

已有精确游标后，计划与轻量 XPLAN/Monitor 作为可选证据直接续取，不再由模型重复规划。
发现精确 Monitor 执行后，最多续取最新一项执行的本实例行源。自动增强最多覆盖两个
完整主体；其他主体和来源继续走开放的受控调查，不声明已覆盖未采集主体。

ASH 通过诊断合同 `oracle_evidence_requests` 按需申请，包含类型、真实 subject_id
及改变判断的理由；游标和执行键由服务端从原始证据重建，不接受模型给定 SQL、
游标或执行标识。明确历史区间可成对提供带时区 begin_time/end_time，最多24小时。
未提供时，以本轮游标原始观测时点冻结请求时长，缺省15分钟；默认近期窗口不能
冒充用户历史故障窗口，更广历史仍可由已授权动态/AWR 调查补充。

每个增强工具10秒上限；无许可不加入计划，剩余工作预算不足15秒不再启动增强。
零行、失败、已调度均记为已尝试，不反复重跑。可选来源缺失不能抹去已成立的
计划、统计或锁证据，也不构成“SQL 健康”的证明。SQL Monitor 通常不覆盖短 SQL，
ASH 是活动采样且保留期有限；样本数不是执行次数、精确时长或完整窗口覆盖率。

SQL Evidence Bundle 新增精确执行分组及原生计划行关联，保留原证据行、实例、
容器、子游标与计划哈希；标准化 node_id 与原生稀疏行号通过父子遍历对应，不能
直接当作同一编号。LAST、Monitor、ASH 不因行号对应就声称属于同一次执行。
诊断声明完成时，必须引用已取得非空 Monitor、行源及 ASH 的具体资源/等待字段，
不能只复述累计计数而忽略直接运行证据；无明显问题仍需说明实际检查范围。

与结构化缓存计划的完整主体、物理来源及计划哈希匹配的 DBMS_XPLAN 原文，
在“原始计划”页折叠展示，保留来源、采集时间和截断标记。原文仅为补充，不覆盖
图形结构或 LAST 指标；错误输出、未知物理来源和混合计划不伪装为匹配计划。

HTML 报告仍按需生成、下载复核，不是诊断前置条件。结构化事实与最终判断进入
现有冻结调查、报告及案例来源校验链；不新增持久化表列、不改变目标库配置，
不自动开启跟踪、不强制重放 SQL、不改变许可及变更审批边界。
本次模型合同和运行时交付指引随代码更新，无 Prompt 文件或开发数据库版本变动。
