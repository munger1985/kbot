# 可选 ripgrep 文本扫描组件设计

日期：2026-11-05。状态：独立可选组件已编码并通过合成/故障离线回归，默认关闭；真实收益和正式页面接入未验证。适用：KBot4 与 Ammolite。

本组件是 [App 独占数据的解析、索引与多模态召回算法设计](app-owned-knowledge-algorithm-design.md) 的独立可选扩展。只复用组件代码，每个 App 分别绑定自己的数据与授权，不增加跨 App 检索。

进程/物理存储与 Runtime 交付沿用[接入详细设计](app-owned-knowledge-integration-detailed-design.md)，实现与门禁属于[实施计划](../operations/app-owned-knowledge-implementation-plan.md)的 R1。本文不恢复公共 KC 存储或 App 私有 Composer。

## 1. 定位与独立性

- 提供精确文本补召回和候选内细查，不替代全文索引、文本/视觉向量、多向量或图文关系查询。
- 默认关闭，由 App 的版本化配置显式启用；安装 ripgrep 不自动启用。
- 核心算法包不依赖 ripgrep 可执行文件或具体组件实现，关闭时不加载实现、不生成扫描投影、不探测组件可用性。
- 组件未安装、被关闭或不可用，不阻断核心解析、索引、检索及其 readiness。
- 可独立安装、验证、启停和移除；不要求独立微服务，优先作为 App 侧受控适配器使用。
- 不把它变成公共文件搜索服务，不提供任意目录、连接串、shell 或目标 App 参数。
- 所有源文件、派生文本和映射仍归 App；组件不拥有公共正文表或全局文档目录。

实现位于可选包 packages/knowledge_text_scan，核心仅保留中立 TextScanPort 合同。各 App 的 TextScanOptions 工厂显式启用；没有自动安装或修改正在运行的配置。当前支持有界逐行 literal 扫描，不支持正则/跨行任意执行；代码、模式组合与离线证据见[基础编码记录](../operations/app-owned-knowledge-foundation-progress.md)。

## 2. 两种扫描模式

| 模式 | 范围 | 用途 |
|---|---|---|
| EXACT_RECALL | 当前 App、当前授权和可检索快照内的文本投影，可按合法条件缩小 | 错误码、型号、编号、完整短语、代码/配置片段的补召回 |
| WITHIN_CANDIDATES | 上述范围与服务端确认的候选对象集合求交 | 在已找到的文档/章节中进一步定位或核验 |

EXACT_RECALL 不能隐式退化为仅扫描向量 Top-K，否则无法补回第一轮遗漏文档。WITHIN_CANDIDATES 的结果只能声称覆盖该候选子集，不代表全授权范围。

启用组件不等于每次查询都扫描全部语料。受约束查询计划或显式精确查找决定调用，且必须有预算。Agent 可以请求结构化扫描，但不能直接执行命令行或指定文件系统路径。

只读已满足 App 原有发布、完整性和授权门禁的数据；不能通过扫描未审核文件、半成品解析或尚未允许检索的版本绕过索引/发布流程。索引通道故障时也不能自动扩大数据可见范围。

## 3. 文本投影与原文映射

~~~text
App 自有规范解析数据 / 允许索引视图
  -> 可重建的 UTF-8 文本投影 + 来源映射 + 快照清单
  -> ripgrep 扫描
  -> TextMatch
  -> 原始内容节点 / SearchUnit / EvidenceKey
  -> 词法信号族归并与 RRF 融合
  -> 确定性覆盖与证据预算选择（无独立模型重排）
  -> 原文定位及图文关系读取
~~~

App 数据库是权威来源，文本投影只是可删除、可重建的派生制品，不是新的共享业务数据库。仅在显式启用后构建，构建和撤回按 App 代次管理。

文本投影来自允许使用的正文、图题、OCR 或领域字段，不直接扫描二进制 PDF/Office，也不扫描混合内部标识、敏感元数据及转义文本的任意 JSON。

清单至少绑定 BackendBinding、授权命名空间、文档版本、解析/投影代次、允许视图版本、文本摘要及映射摘要。组件只能扫描 App 提供的已授权且不可变来源，不能自行枚举全盘。

来源映射包含 UTF-8 字节范围到 ContentNode、SearchUnit、原文字符跨度、页码/bbox 或逻辑位置的映射。ripgrep 的 JSON 子匹配偏移是字节偏移，不能当作字符数或原文页码；规范化和换行也必须有映射。

source map 缺失、摘要不符或快照失效时拒绝该来源，报告覆盖缺口，不能凭文件行号生成假 Citation。正文/图题到 REFERS_TO 的来源映射沿用主设计。

所有扫描目录、缓存及临时投影按 App 隔离；相同文件 Hash 不允许跨 App 复用。不得扫描未脱敏原文来绕过允许视图。

## 4. 合同与接入

以下为待实现接口示意：

~~~python
class TextScanPort:
    async def scan(
        self, request: TextScanRequest, scope: AuthorizedScope,
        snapshot: RetrievalSnapshot,
    ) -> TextScanBatch: ...
~~~

| 合同 | 核心字段 |
|---|---|
| TextScanRequest | 模式、字面量/受限模式集合、组合约束、可选候选键、时间/字节/匹配预算 |
| AuthorizedTextSource | App 内部受控读取身份、版本、文本/映射摘要；不得对外暴露本地路径 |
| TextMatch | 精确来源与单元键、匹配字节范围、原文映射、匹配类型及查询条件 |
| TextScanBatch | matches、状态、范围说明、是否穷尽、预算截断/失败、扫描策略和版本 |

组件组合根固定 App 的 AuthorizedTextSourceProvider。每次 scan 都必须传 scope 和 snapshot，校验绑定一致；候选键只能缩小范围，不能借构造 ID 读取其他 App 或未授权文档。

TextScanBatch 不提供伪造的 BM25、cosine 或相关性排名。进入主引擎后，通过确定的对象映射转为标准候选。核心 RetrievalEngine 可注入 TextScanPort，也可不注入；不将其加入 AppBoundBackend 的必实现方法。

每个扫描模式标记来源（显式用户条件或冻结查询计划）、HARD/SOFT 用途、大小写/Unicode/跨行语义和策略版本。只有用户明确且后端可执行的资格谓词可为 HARD，模型扩展词只提供 SOFT 补召回线索；扫描命中不证明满足语义问题或答案支持。

## 5. 受控执行与权限

1. 默认字面量模式；正则仅按已登记策略启用，限制长度、复杂度、耗时和输出，不接受任意命令参数。
2. 调用使用参数数组及 shell=False；可执行文件来源由部署配置固定，不让用户指定。
3. 使用机器可读 JSON 输出和 --no-config，防止用户环境配置改变行为；模式通过 -e 传递，文件参数使用 -- 分隔。
4. 禁止用户设置 --pre、外部解码命令、任意 glob、递归根路径、搜索压缩包或切换 PCRE2 等执行选项。
5. App 在扫描前生成授权来源清单，执行器只能打开这些来源；不能先扫全部文件再过滤匹配。
6. 路径、符号链接、摘要及只读隔离需校验，防止目录穿越、链接逃逸和扫描时源被替换。仅检查路径字符串前缀不构成充分隔离。
7. 不依赖 .gitignore、隐藏文件规则或遍历顺序决定业务覆盖；跳过、缺失或无法读取的来源进入覆盖状态。
8. 输入文件过多时按固定快照分批，统一计算全局时间/字节/输出预算，不能因命令行参数长度限制静默漏文件。
9. stdout 也受流式背压和总量限制；不能先收集全部输出再截断，以免高频词耗尽内存。
10. stderr、日志和 Trace 脱敏，不泄漏完整本地路径、原文、凭据或其他 App 身份。
11. 返回及后续原文/预览读取均复核授权和撤回；旧投影仍在磁盘不意味着可读。

所有实际进程创建、超时、取消和资源限制由组件适配器负责，不在算法核中拼接 shell。启用前验证配置和二进制可用性属于组件部署验证，不检查应用自身数据库 Schema。

## 6. 候选融合与覆盖语义

- ripgrep 的文件/行输出顺序不是相关性排序，首批命中不是 Top-K；--max-count 也不是全局相关性 Top-K。
- 同文档内的多个位置按对象身份归并，保留命中跨度；跨对象和同页多图不错误折叠。
- 精确程度、模式覆盖等可作为词法信号，由后续词法族归并、RRF 融合及确定性覆盖/预算选择处理；不凭空产生语义相关分数，不引入专用 reranker 或 LLM rerank。
- 全文索引与文本扫描属于同一词法信号族，先去重并在族内归并或约束权重，不能在 RRF 中无条件当作两票独立证据。
- 扫描组件故障不能清空已由其他路线召回的候选，也不能改写用户的结果数量与排序。
- 扫描命中、原文映射、归并、选择、组装和实际交付的身份/计数沿用主设计第 8.12 节；映射或交付失败不能伪装为扫描无命中，未配置 reranker 不算降级。
- 若达到预算，返回实际已扫描范围和未穷尽状态；不能声称全范围未找到或支持“列出全部”。
- 仅当授权清单全部处理、无跳过/错误/截断且映射有效时才可标记 exhaustive=true。
- 大小写、Unicode、换行和模式组合方式必须明确。一个词面匹配不能冒充语义等价，默认逐行匹配不能宣称覆盖所有跨行短语。

图号场景中，组件只能发现“图 1-1”出现；对应哪张图仍由已解析关系决定。图片反查正文直接读关系索引，不每次重新 grep，也不能以模糊字符串匹配替代消歧。

### 6.1 词法族的可复现排序

扫描结果不单独进入 RRF。启用后按以下确定性规则生成唯一 rank_lexical：

1. 按精确对象/版本/单元身份合并全文与扫描命中，保留各匹配跨度与来源；同一个模式重复出现不增加模式覆盖数。
2. 对冻结扫描请求中已登记的模式，在本 App 允许文本视图中核验完整模式匹配与组合语义。全文命中也按相同受控规则核验，不能因为不是 rg 返回就默认“不精确”；预算无法核验的标为 UNKNOWN。
3. 使用可解释元组排序：精确匹配级别降序（完整满足登记模式组合、部分模式命中、其余/未知）、不同模式覆盖数降序、全文全局名次升序（无全文名次视为无穷）、稳定 EvidenceKey 升序。不使用字节位置、文件遍历或 rg 输出先后决定相关性。
4. 没有登记精确模式时不制造精确级别，保留全文相对顺序，扫描独有对象按稳定身份进入族内候选末尾；不能伪造 BM25。若希望补召回能影响优先级，必须在冻结计划中明确有效模式并通过实验，而不是暗加模型裁决。
5. 仅保留一份词法族全局名次和版本化族权重，再与文本/视觉/多向量路线执行 RRF。扫描独有对象有明确族内位置，不丢弃，也不作为第二票重复加分。

这是无模型的词法信号排序，不是语义相关性保证。词法族排序策略独立消融；精确字符串误召回必须统计，UNKNOWN 不等于无关，也不作为删除条件。扫描不完整时名次仅对应实际候选，必须保留 PARTIAL/未穷尽说明。

### 6.2 排序与分页的能力界限

rg 首批输出不支持全范围最新 N 或语义全集枚举。FILTERED_ORDER/EXHAUSTIVE 仍由 App 后端按可执行资格、原生排序和稳定游标负责；扫描要参与其资格判定时，须完成所声明范围的匹配验证，或明确部分覆盖，不能先截 rg 输出再按日期重排冒充完整结果。

扫描请求的范围、模式指纹、快照与穷尽状态和主检索分别记账。跨批次扫描只产生一个词法族，不按进程/文件批次数增加 RRF 权重。

## 7. 状态与故障隔离

| 状态 | 语义及核心行为 |
|---|---|
| DISABLED | 默认未启用，不调用、不创建依赖，不算检索退化 |
| UNAVAILABLE | 已配置启用但实现/二进制不可用；核心路线继续，调用方可见能力状态 |
| COMPLETE | 对指定范围和匹配语义完成扫描，可为合法零命中 |
| PARTIAL | 超时、预算、跳过来源或部分失败，保留有效匹配并说明覆盖缺口 |
| FAILED/CANCELLED | 执行失败或被取消，不能伪装为空结果；核心已有结果仍可返回 |

可选路线被实际调用后失败，主检索应在 Trace/响应中报告通道状态，按主设计返回部分/退化结果，不把故障隐藏成正常零命中。独立扫描请求失败时返回扫描错误，不能因它是可选组件就伪装成功。

正确区分 ripgrep 的 0（有匹配）、1（无匹配）、2（错误），并校验结构化输出；错误可能伴随部分结果，必须按实际处理范围标记 PARTIAL 或 FAILED。超时/取消需回收进程及未消费输出。

关闭组件无需修改正文、删除核心索引或重新解析；专属文本投影可按本 App 保留策略回收，不删除原文、主检索索引及其他 App 文件。

## 8. 评测和实施边界

先在固定的无模型重排混合检索基线上比较“不启用扫描”与“增加可选扫描”，保持语料、权限、候选预算、RRF/证据选择策略、回答模型及上下文载荷预算一致，报告额外扫描资源。不为此引入重排模型。测试至少包括：

- 错误码、标点型号、代码/配置片段、完整短语与高频词。
- 中文/Unicode、换行、规范化后的字节到原文映射。
- EXACT_RECALL 找回向量候选之外的证据，WITHIN_CANDIDATES 不越界。
- 未安装/关闭时核心可导入、运行且不探测 ripgrep。
- App/Domain 隔离、撤回、旧快照、未脱敏文本及授权来源替换。
- 恶意模式/路径、符号链接、隐藏/忽略文件、超长来源清单。
- 退出码、超时/取消、部分 JSON 输出、预算截断、穷尽状态。
- 全文与扫描重复命中不被重复加权，主命中数量/用户排序不变。
- 扫描独有对象、全文独有对象、双路对象、模式覆盖同分、无模式和 UNKNOWN 按固定词法族规则排序；交换文件/输出/执行批次顺序不改变已完整扫描的排名。
- FILTERED_ORDER 的最新合资格项不因 rg 首批输出截断丢失；扫描未穷尽不能返回全量/完整排序承诺。
- 扫描正文仍能沿 REFERS_TO 带出精确图片；不以同号图替代真实目标。

质量指标关注精确任务 Recall、词法误召回、融合后排名及最终上下文证据覆盖收益，并核对有匹配却丢失载荷的异常；工程指标包括 P95、实际读取字节、峰值内存、缓存冷热与并发。不同规模、存储布局单独压测，不能用“rg 很快”代替服务容量评估。

本次只确定独立可选组件及合同；包、执行器、文本投影、配置项和测试均未实现。没有新增安装、服务、运行时数据库变更或跨 App 能力。
