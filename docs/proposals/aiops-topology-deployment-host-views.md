# 业务系统拓扑：部署分组与主机视角

## 已确认的展示原则

采用方案 B 的部署分组与方案 A 的纵向分层：应用与接入在上，数据库或 RAC 组居中，主机内部嵌套实际运行的实例，存储在下。主备组横向排列。只有资源配置了明确且一致的 location_name 才展示位置边界，不猜测生产、灾备机房。

- 数据库集群是逻辑分组，不等于硬件归属。Data Guard 连接数据库组，不生成 RAC 成员之间的多条复制线。
- 同一 resource_id 在画布只展示一次。不按主机名或 IP 自动合并资源。
- 单一承载可嵌套；多承载和循环关系保留显式连线，不强行转成树。
- 主机内部嵌套已表达承载关系，不再显示“运行于”标签或内部承载连线，并使用紧凑间距；非嵌套的承载关系仍保留连线和标签。关系数据本身保持不变。
- 应用、数据库、主机、容器、存储都可以沿用既有资源与关系模型，无新增表结构。

## 两个视角

### 业务系统视角（默认）

展示当前系统草稿或已保存配置。独占承载可放入 RAC 部署组；跨集群或同时承载非集群应用的共享主机单独展示，不能为满足分组而复制主机，或误示为某个数据库独占硬件。没有关系的资源排列于独立节点区。

### 主机视角

主机作为承载边界，内部展示数据库、App、容器及容器内工作负载。RAC 保留逻辑摘要供主备复制连接；成员实际嵌在各自主机内，不重复资源。

在主机下拉框选中已保存的主机，点击“查看跨系统承载”，读取同一资源身份在当前管理范围中的已保存承载关系。每个节点显示所属业务系统；同一主机可承载订单系统数据库、MES 应用及其他系统工作负载。未保存的主机不能执行跨系统查询。

跨系统结果只读，不参与当前向导草稿，不提供资源或关系编辑入口；“返回当前系统”恢复当前草稿。切换视角、主机、系统或空间后废弃旧请求，旧结果不得覆盖新上下文。缩放、适应宽度和画布内部滚动不改变业务数据。

## 只读接口与权限边界

相对业务系统管理入口新增：

`GET /business-systems/{business_system_id}/hosts/{resource_id}/topology?max_nodes=200&max_depth=4`

公开入口沿用平台 aiops:use 权限：KBot 使用可信 Domain，Ammolite 使用可信 Tenant + Domain。内部调用沿用服务身份与 AuthContext，不接受客户端传入的租户或空间覆盖可信范围。必须验证起始主机属于当前系统的 ACTIVE 关联，主机自身在该可信范围且生命周期 ACTIVE。

当前配置管理是空间级读取权限，本次不新增不存在的逐系统 ACL。仅输出本管理范围中非删除系统的显式、已确认 RUNS_ON 关系，资源及系统关联均须 ACTIVE；离线系统的已保存配置可以展示，但不能被解读为正在运行或连接健康。节点只含身份、类型、名称、位置、所属系统及承载关系，不返回凭据、连接串、Target 或监控内部 Locator。

跨系统读取不修改资源归属，不增加 Agent 的 allowed_business_system_ids，不自动授权诊断或受控动作。Agent 继续遵守其原有系统授权。

查询按 resource_id 去重，沿容器承载最多展开 max_depth（默认 4，范围 1–6），节点数 max_nodes 默认 200、最大 500；达到节点、深度或查询行限制时返回 truncated=true。页面明确提示“结果已截断”，不能将部分清单宣称为完整清单。它也不代表主机全部进程，不替代资产发现或运行健康检查。

## 本轮能力边界

本轮展示已建立的共享资源关系，不新增向导中“复用已有主机”的录入流程。当前新建资源仍沿用原有 NEW 模式；跨系统共享要求已有明确的同一 resource_id 及各系统内的已确认承载关系。后续资源复用入口需独立设计，不按地址、名称或监控标签猜测。

不涉及 OEM 指标、监控采集协议、Agent 权限扩展或数据库迁移。

## 双端实现与验收

Ammolite 使用 topologyLayout.ts 的确定性布局和 topologyView.ts 的转义 HTML 投影；KBot 通过 tests/contract/sync_aiops_topology.mjs 生成独立运行产物，运行时不依赖另一仓库。平台只保留各自 Vue 或静态页面的交互包装。

回归覆盖单实例、多数据库同机、RAC + DG、真实位置、共享主机双视角、循环与多承载、HTML 转义、移动端、跨空间过期请求丢弃、跨系统只读、范围隔离、容器链及截断。仓储测试使用 SQLite，不等价于线上 Oracle / PostgreSQL 部署验收。
