# 运维Agent (Ops Agent) 移植方案

## 一、差异分析总览

| 维度 | NexusCube | kbot3 | 移植策略 |
|------|-----------|-------|---------|
| 数据库 | PostgreSQL + ES | Oracle 23ai | Entity/Repository 重写，SQL 语法适配 |
| `agent_id` 类型 | `str` (UUID v7) | `int` (自增) | 全局替换为 `int` |
| `kb_id` 类型 | `str` (UUID v7) | `int` (自增) | 仅 Ops Planner 中 RAG 检索受影响的字段适配 |
| `instance_id` 类型 | `str` (UUID v7) | 保持 `str` | 不变（外部CMDB标识） |
| Skill 领域模型 | `SkillDomain` 枚举 + `SkillRunMode` 枚举 | 无（仅 string `category`） | 向 kbot3 注入 `SkillDomain`/`SkillRunMode` |
| `PacketType` | 含 `WARNING`, `REQUIRE_APPROVAL` | 不含 | 向 kbot3 的 `PacketType` 追加这两个值 |
| 配置 | `PrometheusConfig` + `ExecutorConfig` | 仅有 `ExecutorConfig` | 追加 `PrometheusConfig` |
| 指标映射 | `configuration/metrics_mapping.yaml` | 无 | 直接复制 |
| Intent 路由 | 独立 `/ops/chat` 端点，不经过 `IntentRouter` | 无 ops 端点 | 新建独立路由和 Orchestrator |

---

## 二、核心架构对齐分析

NexusCube 的 Ops Agent 和 kbot3 的 RootAgent 是**平行架构**，两者都遵循：

```
Agent → Orchestrator → Planner → SkillRuntime → Skill
```

但 Ops Agent **不经过** `IntentRouter` 和 `PlanningEngine`——它有自己的 `OpsTaskPlanner`，通过独立的 `/ops/chat` 端点直接进入 `OpsOrchestrator`。这个隔离设计**应当保留**，因为运维场景需要：
- 锁定单一 instance 拓扑（非多KB检索场景）
- Prometheus + 专家SQL 双轨注入
- 安全熔断门禁（`_check_safety_gate`）

    created_at           TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_by           VARCHAR2(64),
    updated_at           TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_agent_ops UNIQUE (agent_id, instance_id),
    CONSTRAINT fk_agent_ops_agent FOREIGN KEY (agent_id) REFERENCES kbot_md_agent(agent_id),
    CONSTRAINT fk_agent_ops_instance FOREIGN KEY (instance_id) REFERENCES ops_db_instance(instance_id)

## 七、风险点与注意事项

1. **密码加解密**：kbot3 使用 `KBOT_AUTH_ENCRYPTION_KEY` 做 JWT 签名，`CryptoToolkit` 的 AES-256-GCM 需要相同长度的密钥。需确认或新增独立的 `OPS_ENCRYPTION_KEY`。

2. **MemoryRepository 接口差异**：kbot3 的 `MemoryRepository(user_id)` 构造函数签名可能与 NexusCube 不同，`ops_planner._get_recent_chat_history()` 需要适配。

3. **DocOrchestrator.run_pipeline() 参数差异**：NexusCube 版本支持 `tags` 参数做运维领域隔离（`tags=["ops", "sop"]`），kbot3 的版本需确认是否支持，若不支持则需在 kbot3 的 `DocOrchestrator` 中追加 `tags` 过滤。

4. **AgentStreamMixin**：kbot3 的 `RootAgent` 直接把 SSE 流式方法写在类内，不是 mixin。OpsAgent 可直接复用 `RootAgent` 的 `_format_sse()` / `_smooth_stream_pipeline()` / `_simulate_char_stream()` 方法，或将 mixin 也移植。

5. **SqlClient / SQL Executor 微服务**：NexusCube 的 `OpsDBExecutor` 通过独立微服务（`:18096`）执行 SQL。kbot3 已有 `utils/clients/sql_client.py` 可用，但需确认其接口是否兼容 `OpsDBExecutor` 需要的 `execute_readonly_ops_sql()` 方法签名。

6. **skill.md 格式兼容**：kbot3 的 `SkillManager.auto_discover_skills()` 基于 skill.md 的 YAML front matter 发现技能。移植时需要确保 ops 技能的 skill.md 格式与 kbot3 现有格式一致，并在 front matter 中新增 `domain` / `run_mode` 字段。
