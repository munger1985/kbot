# 按知识库绑定模型与三档文档解析

状态：产品行为已确认；本文件定义目标合同，不代表实现、模型或数据库已验收。适用于 Ammolite、KBot4 的知识库 App 和 AIOps 运维资料库。AIOps 独立的诊断案例治理不变。本决议取代旧实现计划中的 App 级共用模型选择、建库／编辑仅保存名称说明或标签模型，以及普通知识库解析与审批并行的约定。

## 创建和编辑知识库

管理员在库的创建／编辑右抽屉里按职责绑定当前作用域模型目录中的模型。文本和视觉 Embedding 均可选；不设草稿库，新建成功直接启用。OCR 和 VLM 可分别不配置，建库不选择解析策略，也没有隐式默认策略。索引模型与解析档位独立；运维库的标签识别模型不可兼作 OCR／VLM。不配置 OCR／VLM 仍可使用原生解析，不借用 Agent 或其他库模型。模型区的问号图标打开独立右抽屉，按下表解释效果、门槛和限制；关闭返回问号位置，保留主表单输入。

| 解析方案 | 解析效果 | 库内必需模型 |
|---|---|---|
| 原生解析 `TEXT` | 保留原生文字、标题、表格和图像证据，不做模型转写。扫描图像可保留原图，但其未转写文字不可查。 | 无 OCR／VLM 要求 |
| 自动判断 `AUTO` | 原生优先；文字缺失或不可靠时，对缺失页或区域做 OCR。可用 VLM 只补强有信息量的局部图片，不做整页 VLM 转写。 | OCR 必需；VLM 可选 |
| 视觉增强 `VISUAL` | 在自动判断基础上，允许针对局部处理不足的复杂页做整页视觉转写，例如扫描表格和多栏混排。保留原图及定位，不覆盖可靠原生内容。 | OCR 和 VLM 都必需 |

OCR 和 VLM 是按库配置的解析角色，不是全局开关。文本／视觉 Embedding 也按库绑定，只用于建立与查询各自索引；不以 App 级共用模型补位。不配置文本 Embedding 时无语义检索，仍可按关键词检索。语义检索需要匹配的已发布向量索引；模型变更可以显式重建，未确认整批切换前仍使用原发布代次，解绑立即关闭对应向量通道。未配视觉 Embedding 不影响文本检索或解析档位选择。

普通知识库和运维库在同一个新建右抽屉内分两步。第 1 步填写信息并选模型；第 2 步逐项预览检索能力：「文搜文（关键词检索）」「图搜图（找原图）」是基础能力；「文搜文（语义检索）」按是否选择文本 Embedding 显示已配置或未配置。视觉 Embedding 的候选项根据模型目录登记的方向标注「支持文搜图」「不支持文搜图」或「文搜图能力未登记」。「文搜图」与「图搜图（找相似图）」分别按所选模型的对应方向显示已配置、模型不支持、能力未登记或未配置；已配置仍须等待图片索引发布。表格下单列解析说明：未选 VLM 不能使用「视觉增强」解析；已选 VLM 仍需 OCR 并在审批时校验。预览不宣称索引已发布或模型已通过运行验证。「上一步」保留输入；只有「确认创建」提交，成功后关闭抽屉并更新目录。未配置 Embedding 仍可确认创建；编辑现有库直接保存，不重复走建库确认。

| 当前库中通过校验的解析模型 | 审批可选档位 |
|---|---|
| 无，或仅有 VLM | 原生解析 |
| 仅有 OCR | 原生解析、自动判断 |
| 同时有 OCR 和 VLM | 原生解析、自动判断、视觉增强 |

上表以对应执行端可用为前提；绑定存在但模型已停用、无权调用、类别不匹配或执行端不可用时，不开放相应档位。审批页说明缺少的角色或不可用原因，不把配置成功等同于模型已生效。

## 上传、审批、执行及发布

1. 上传只登记精确文件版本并回执为待审批；上传页不选方案，不调用解析模型。保留原始文件、幂等键和接收身份；拒绝不启动解析。
2. 审批右抽屉展示三档及当前库、当前模型目录下的可选状态和禁用原因；批准必须明确选择一档，不能自动替换，拒绝无须选择。服务端重新校验审批资格、版本状态、库启用状态、模型类别、授权和可用性，不能信任客户端选项。模型改绑或目录状态变化时刷新重新确认。
3. 同一事务提交批准并冻结档位、该库适用角色的模型身份与版本、原文身份及执行参数，才放行解析；保留既有任务栅栏和幂等。任务执行与重试读取冻结规格，不重新继承当前库、其他库或 App 级模型。模型服务须能按冻结版本执行，或在取得用于本次推理的配置时原子拒绝版本不符；只对模型 ID 作一次预查不能证明执行使用了该版本。旧版不可再调用时，记录不可用，不静默换用当前版本。配置更新不自动改写历史任务或重跑已上传资料。
4. 保留新版原生解析、资源边界、来源定位和发布索引核验。原生内容、OCR 转写、VLM 转写与生成描述分别标明来源；保留缺口，模型故障不得伪装成识别成功。申明的语义检索能力仍必须匹配有效索引、模型身份及表示规格。审批通过不等于已解析或已发布；原有发布授权与治理边界不变。

本设计不要求修改、清空或覆盖系统级 TOML，不进行存量配置写入、自动回填或真实数据库 Schema 操作。切换前另核对已有待审、在途和发布版本，保留可追溯身份与原有授权，不静默改写。验证应覆盖双库不同模型、未审批不调用模型、模型可用性变化、重试冻结、原生扫描缺口、AUTO 不调用整页视觉、VISUAL 按需及发布隔离。

## 执行细节与验收

- 知识检索 App 中，失败后可按原档位和冻结模型版本新建重试任务，也可按当前库模型另选可用档位重新解析。同一文件版本和原文不变，保留失败记录和原审批；索引失败只重新建索引。
- 已发布文件更换向量模型时，复用已发布解析及其允许视图。切片规则和输入边界未变时，可复用旧切片和未改变的表示；规则或输入边界变化时，从允许视图重新切片、建立独立候选索引。不自动重新解析已发布文件。候选完整成功后自动切换，原索引在此之前继续服务，不提供手工发布。

### 可定位切片与处理诊断

2026-11-23 确认：在原有单片计量和文件级资源上限下，文本优先按段、句、分句、词拆分，最后按能放入预算的 Unicode 边界拆分，必要时保留少量相邻原文。标题上下文让位于正文。表格优先用可靠的行列结构；按行、列组、超长单元格依次细分；无法可靠恢复行列时，按原表内已有原文映射的文本跨度拆分，不推测单元格关系。保留原始段落或表格身份、页与对应文字跨度；检索与引用对重叠命中去重，不把生成上下文当作原文。

单片预算与批次条数、写入载荷预算分开。第一次索引、索引失败重试与重建使用同样的版本化规则和确定性批次；断点仅复用同代次数据。确定性预算或合同错误不自动重复投递；暂态故障保留现有重试。已解析的 RAM PDF 无须重新上传、审批或解析。真实验收还要覆盖跨切点检索、表头和单元格超长、无标点文本、断点恢复以及自动发布。

解析诊断关联任务、解析运行及模型请求，记录阶段、区域来源、尺寸、模型角色、错误分类和耗时，不记录文件正文、原图或凭据。

原生转换后先处理缺文字页（含扫描页）和视觉增强档要求补强的复杂页，再处理插图。已有可靠原生文字的区域中，自动档不把没有文字的 OCR 结果直接升级为 VLM；图表、图题等明确线索，或 OCR 返回了不可靠文字时，仍可补强。能明确识别为装饰线的图片保留原图和定位，不调用模型；不能仅凭图片小就跳过。任务内同一冻结模型、同一区域类型、同一实际图像输入复用已完成的转写，依旧保留每次出现的独立定位。

已有可靠文字的页（或只有逻辑定位、已有可靠正文的文档）里，可选插图补识别使用任务墙钟上限的至多 20%，并提前留出结构整理和结果交付时间。当可选预算不足时，保留原图、已完成的识别和正文，未识别区域记录为缺口；必需识别、模型版本错误和其他推理故障仍按原规则处理，不伪装成识别成功。任务硬资源上限、原生转换及索引完成后自动发布的规则不变。

Markdown 导入按语法处理排版：无属性的 `<br>`、`<br/>`、`<br />`（不区分大小写）在正文中作为换行，在表格中作为同一单元格内的换行，不拆行、列或表格。行内代码、代码块及转义后的同形文本保持字面含义；其他原始 HTML、带属性的换行标签及外部或未登记图片仍禁止。原文件和原文定位保留；已有失败文件可沿用原版本重新解析，无需重新上传。

原生 PDF 英文若出现大量逐字母错误间隔，解析器在原节点框内核对 PDF 字形顺序和实际字距。只有文字序列一致、词内与词间距离能区分时才恢复词边界，保留原页框、节点结构与来源；证据不足、复杂方向或无原生字形时不猜词，不调用 OCR 或 VLM。此修复发生在正文发布和切片之前，历史版本须使用「重新解析」生成新代次，单独「重建索引」不会修改解析文本。

两平台都不需要修改系统级 TOML 或数据库 Schema。

原生转换子进程启动时限制 OpenCV 与已有数值运行库的线程数，避免 PPTX 内嵌图片编码因额外线程耗尽虚拟地址空间。保持原有内存、CPU 和文件预算以及图片处理规则；Docling 包装的内存异常归类为转换阶段的 `RESOURCE_LIMIT`，其他转换异常仍按解析质量失败处理。

DOCX 已确认一类故障：转换生成的细线被送去视觉转写，模型因图像尺寸拒绝后导致整份文档失败。Office 普通图片仅在没有语义标记、不是整页且线条像素形态明确时跳过 OCR／VLM；原图和定位保留。其他图片仍按原策略处理。只有视觉模型服务明确返回 HTTP 422 和 `MODEL_IMAGE_DIMENSIONS_UNSUPPORTED` 时，才保留该区域的原图和已有 OCR 文字、记录识别缺口，其余内容可按现有的局部覆盖策略继续建索引。尺寸限制属于所用模型，不作为所有模型的预设；版本冲突、连接失败和其他参数错误仍按原流程报告。

图片转写与视觉 Embedding 分别校验各自的输入规格。单张图超出转写载荷上限时同样按区域缺口处理，不影响原图。建索引时，超出视觉表示传输上限、或模型服务明确返回 HTTP 422 和 `IMAGE_INPUT_UNSUPPORTED` 的图片，保留原图、定位与原图匹配，只在该图片、该视觉空间内记录未建向量；文字与其他图片继续建索引，全部批次成功后自动发布。首次索引、断点续跑和重建执行同一规则；批次顺序及已提交批次不变，换模型后按新空间重新校验。全局资源上限、原图完整性校验、冻结版本和正常错误处理均不放宽。

- 原生转换在有资源预算的隔离子进程完成。需要转写时，父进程才向 Model Serving 发送有界图像，请求必须携带冻结版本。目录版本和正在使用的实例都必须匹配；若任一不匹配，任务失败，不做推理，也不替换模型。审批页的可选状态是当前目录和执行端校验，不保证上游推理一定成功。
- 运维手册的审批把同一次批准绑定到所有纳入审批的文件版本；原有标签识别、案例治理、发布和重试授权保留。
- 文本与视觉 Embedding 独立配置。向量模型在模型目录登记维度；视觉多向量模型还需登记检索方向。模型版本、预处理器版本、输入模板标识由 Model Serving 为本地模型自动生成，外部 API 模型仍按供应商规格登记。索引代次持久化表示空间和模型服务版本。检索仅启用已发布清单中的匹配空间；模型更换不改写或重跑已有资料。同一查询如涉及多个空间，分别向量化和比较，不跨空间比较向量。
- 本次在现有配置、审批记录和索引清单 JSON 中存储数据，无新增表或列。不需要为这项功能升级 PostgreSQL / Oracle Schema，不回填存量版本，也不变更系统级 TOML。

真实验收按同一组原生 PDF、扫描页、混排／表格、纯图片在两平台一次执行。至少核对：未批准暨拒绝的调用次数为零，批准后只调用适用库模型，AUTO 无整页 VLM，VISUAL 需要时允许整页补强，目录版本变化和重试不会替换模型，两个库使用不同文本或视觉模型仍可分别建立、发布和检索，改绑后不会与旧代次混查。代码级测试不能替代真实验收。
