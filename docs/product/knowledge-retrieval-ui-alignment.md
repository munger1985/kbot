# 知识库 App：产品与页面整体详细设计

基线：2026-11-20 · 页面方向已确认。适用：KBot4 / Ammolite。本文定义目标行为，不代表已经实施、测试或发布。与旧提案的公共 Collection、页面合并和多模态承诺冲突时，以本文为准；未纳入范围的问数、数据源、语义模型、分享和平台扩展维持现行合同。

## 1. 产品范围及分工

知识库 App 将原始文件转为可发布知识，让使用者直接查到并核对证据，让指定 Agent 在授权范围内回答并引用实际使用的资料。上传接收不等于可检索；首次索引校验通过自动发布；检索命中不等于模型已使用。资料、原文、解析任务及批次、索引、查询回执都由当前 App 持有。直接检索只限一个启用库、当前授权、已发布且已生效的索引代次；不恢复公共 KC Collection、Bundle、独立 reranker、跨库／跨 App 检索或旧兼容路径。沿用当前 App、Runtime、解析与索引执行单元，不新增基础设施。

| 导航 | 页面设计 | KBot4 / Ammolite App 子路由 | 进入条件与唯一职责 |
|---|---|---|---|
| 查找与问答 | [直接检索](knowledge-retrieval-pages/01-direct-search.md) | 新增 `search.html` / `search` | App 使用权限 + 启用库 READ，提交查询、续页、看证据；不创建 Agent 会话。 |
| 查找与问答 | [Agent 问答](knowledge-retrieval-pages/02-agent-qa.md) | `knowledge.html` / 根路由 | 现行问答权限及 Agent 资格；保留会话、问文／问数／混合及引用。不内嵌直接检索。 |
| 资料治理 | [解析任务](knowledge-retrieval-pages/04-processing.md) | `processing.html` / `processing` | 上传者看本人任务，授权治理人员看职责范围；看阶段、错误及真实可执行操作。 |
| 资料治理 | [知识库文件](knowledge-retrieval-pages/06-files.md) | `files.html` / `files` | App 使用权限 + READ，左侧选库、右侧浏览和预览，不提供原件下载。按权限显示上传及[审批、撤回](knowledge-retrieval-pages/05-review.md)，待审批支持批量决定。 |
| 管理配置 | [知识库管理](knowledge-retrieval-pages/07-library-management.md) | `knowledge-cores.html` / `manage/libraries` | App 管理 + 库 MANAGE；新建只须 App 管理资格。只管库本身、成员与生命周期。 |

当前页面基线见[页面目录](knowledge-retrieval-pages/README.md)与[方向确认记录](knowledge-retrieval-pages/direction-approved.md)。直接检索采用新版 B「顶部检索条、结果和原文并排」；低频选项折叠在「更多条件」。解析任务及库管理采用 A，知识库文件采用合并后的 B「左侧库列表」。Agent 问答沿用本平台 AIOps「Agent 工作台」布局。上传和审批已并入知识库文件，解析任务独立。

保留原问答入口以及会话、X Search 和其他既有入口。角色和库授权是两个独立门禁：BFF 采用可信身份校验 App 岗位，App 服务检查成员、对象归属、资源状态和当前版本；不能用导航或分享资格替代后端核权。KBot4 的知识库管理为 `knowledge_core_manage`，Ammolite 为 `knowledge_manage`。撤回需 App 管理和 WITHDRAW；审核需 App 审核和 REVIEW。首次发布和重建切换均由后台执行，不再提供发布操作或成员发布权限。直接检索用 `use`，不依赖问答权限。任务、审核、文件的可见性须在列表、详情、动作及内容读取一致执行，不靠已知 ID 绕过。

## 2. 上传、审核、处理和发布

建库／编辑只配置本库模型，不设置默认解析方案。上传只登记精确文件版本并回执「已接收，等待审批」。审批人从当前库可用的档位中选择一档；服务端复核后冻结档位、模型身份与版本，再放行任务。拒绝不排队。

| 解析档位 | 库内模型要求 | 解析效果 |
|---|---|---|
| 原生解析 `TEXT` | 不要求 OCR 或 VLM | 保留原生文字、表格和图像证据；扫描图中未转写的文字不可检索。 |
| 自动判断 `AUTO` | OCR 必需，VLM 可选 | 原生优先；仅在缺字或文字不可靠时补做 OCR；VLM 只补强局部图片，不做整页转写。 |
| 视觉增强 `VISUAL` | OCR 和 VLM 均必需 | 在自动判断基础上，必要时整页转写复杂页面，保留可靠原生内容、原图和定位。 |

建库／编辑的模型区以「?」打开独立右抽屉，展示此对照表，关闭后保留表单输入。知识库文件的审批抽屉展示不可选档位及原因，不自动降档。文本、视觉 Embedding 均可选，不设草稿库；模型选择区说明未配置文本 Embedding 时，新资料不支持文本语义检索，仍可按关键词检索。Embedding 不参与解析档位判定，运维库标签识别也独立。详见[三档解析与库模型绑定](knowledge-library-parse-strategies.md)，普通知识库与 AIOps 运维资料库共用该规则。

| 维度 | 产品状态 | 判断事实 |
|---|---|---|
| 处理 | 等待审批 → 排队 → 解析中 → 解析完成／建索引中 → 索引就绪；也可拒绝、失败或取消 | 任务、解析批次、索引代次。没有数值进度时只展示阶段。 |
| 审核 | 待审核 → 已通过／已拒绝 | 特定文件版本的决定、人员、时间、意见。重复／并发决定不可覆盖已提交记录。 |
| 发布 | 未发布 → 已发布 → 已撤回 | 特定版本及有效索引指针。启用库内，审批通过且首次索引校验成功后由后台自动发布。 |

添加抽屉可多选，每个文件独立上传并创建一条新文档，不提供文件组、升版或强制重建。服务端先检查资格、格式、实际媒体类型及大小，登记事务再核权。幂等键仅标识同一主体在同一库的一次提交：同键同内容及元数据返回同一接收回执，同键不同内容冲突。超时保留同键，换文件或新一次提交才换键。回执含文件、版本、任务标识，始终描述接收而非实时进展。

2026-11-22 确认：正常首次处理改为「上传 → 审批 → 解析和建索引 → 自动发布」，取消单独的人工作业。拒绝不启动解析；解析或索引校验失败、资料取消、库停用均不自动发布。后台重新确认审批、版本、指定索引及队列租约，原子提交发布与队列交付；失败时沿用队列重试。重建索引也自动生效，移除手动发布及切换入口。已经完成但尚未生效的重建批次由 Worker 启动时复核并恢复，无需重跑模型；库停用期间完成的重建在重新启用时复核。历史已完成首次索引但未发布的资料可通过单文件重建自动发布，不批量改动存量文件。取消继续限于本人上传、未发布且处于可取消阶段。撤回即时排除新检索，旧直接检索快照不再可读该版本；历史问答引用按独立的保留与当前授权政策读取原精确版本，不回退至新版。主动内容不内联；知识库文件页只提供白名单预览，不设下载入口。

### 任务维护和向量索引切换

「重新解析」「重试建索引」「重建索引」是三个不同操作，但共用[解析任务页](knowledge-retrieval-pages/04-processing.md)。列表只保留「处理进度」列承载阶段与批次，索引最终校验通过才显示 100%；末列解析结果打开右侧抽屉，查看批次明细并按任务状态操作。索引失败不是解析失败：

| 操作 | 对象与资格 | 结果与不变量 |
|---|---|---|
| 重新解析 | 审核通过、已完成索引或当前解析失败的文件；App 审核 + 库 REVIEW | 重新读取原文件并建索引。可沿用原解析方案，或按当前库模型另选档位；保留原文件、版本、审核和任务记录。已发布文件在处理期间或失败后仍可检索旧版，新索引校验通过后自动切换。 |
| 重试建索引 | 已解析、索引失败的文件；App 管理 + 库 MANAGE | 重排同一索引任务，不调用 OCR／VLM；启用库内索引校验通过后自动发布或切换。 |
| 重建单文件索引 | 已解析、索引就绪的文件；App 管理 + 库 MANAGE 开始／重试 | 各文件独立提交，后台排队；提交成功关闭抽屉并回到表格。复用解析结果，用当前库配置重建，校验通过后自动切换该文件；已审核、原本未发布的文件自动发布。 |
| 重建及切换整库 | 更换或新增 Embedding 影响的已发布文件；App 管理 + 库 MANAGE 开始／重试 | 复用已发布解析，只重算受影响的向量通道。候选与已生效代次隔离；全部就绪后在同一个事务内自动切换，无需人工操作。 |

索引批次冻结模型表示空间、文件范围和旧指针。不同文件可以分别排队，同一文件不重复提交，整库与单文件重建互斥。任务复用 App 自有 outbox、解析结果与索引代次；整库批次与单文件批次独立记录在库内部配置，不对公开配置暴露。原发布代次与历史引用保留，无 Schema 变更。库管理审核变更时显示已发布文件数和「仅保存／保存并重建」；有未结束的索引任务时不能开始整库重建。解绑即时结束对应向量方向，不影响关键词和找原图。只改 OCR 或 VLM 不重建，也不自动重新解析发布资料。

## 3. 检索及问答

| 查询模式 | 合同及表现 |
|---|---|
| RELEVANCE | 单库文字／图片互斥，按支持方向提供输出类型并传用户 N；只按 `primary_hits` 展示，关联不计入 N；没有主结果游标就不翻页。 |
| 图片能力 | 字节精确匹配叫「查找同一原图」，不叫相似图。先开已验证的单图；多图 ANY 仅在真实行为通过验证时开放，不露图文组合、ALL、COMPOSED。 |
| FILTERED_ORDER | 先约束授权、发布及可执行筛选，再按标题或版本建立时间等已登记字段排序，使用稳定标识处理并列，取前 N。不是对相关性 Top-K 排序，建立时间不叫发布时间。 |
| EXHAUSTIVE | 沿服务端快照和稳定排序续页；只有服务端确认穷尽才显示「已到末尾」。权限、发布快照或游标失效需重新查询，不混合新旧结果。 |

数量超限明确拒绝，不静默截断。页头显示已提交条件、本次结果包含的文档及相关段落数和覆盖结论；区分无已发布资料、无匹配、无可用通道、部分覆盖、失败。零结果且通道异常或扫描不完整时不报无匹配。左侧按发布版本与章节归组，同段去重，有明确版面依据时合并 PDF 条款续行。右侧并排展示 PDF 原文或文字上下文，PDF 跳到有记录的页码并可放大，文字在当前已发布版本中标出真实命中范围并按需展开。图题、引用该图的正文、正文指向的图片仍只按明确关系归组；缺失、撤回和预算不足有对应原因；关系续取只追加对应锚点，不更改主列表。读取再次核权，浏览器不见 Scope、对象路径和模型配置。

能力声明由有效的解析／索引／检索方案、已发布索引事实和验证信号派生：未启用、待验证、可用、异常，覆盖另列。空库可以有已验证能力，仍未必可查到资料。扫描件和图片文字只有 OCR／转写真正启用且验证后承诺；语义方向必须有可用模型、匹配表示空间与验证信号。按库绑定模型，不在建库或改名时选择解析档位。

Agent 问答复用 Runtime、不可变 Agent 版本、会话和事件，发问重新核验绑定及 READ。绑定缺失或不可读时注明「本次不可问文」，不泄露库名；问数按现行 Agent 合同，混合缺口不伪装成完整回答。保留用户显式数量／排序，记录检索命中、装载、真正随请求发送、实际引用四个阶段；公开引用是答案实际使用且已发送的证据，回到精确版本。未成功发送图片不能用文字描述冒充读图。直接检索不调用 Agent 回答模型；启用语义方向时使用与该库有效索引匹配的 Embedding。

## 4. 知识库管理及通用交互

承接 AIOps 的卡片目录、筛选工具栏、右抽屉、状态徽标、确认组件及空态，不复刻无效模型字段或主题色。卡片显示名称、说明、启停、更新时间、可核验依赖摘要；未知显示「—」。新建／编辑维护名称、说明和按职责绑定的模型，问号打开三档对照表抽屉；不在库中保存解析档位。「成员」采用[方案 B：权限矩阵](knowledge-retrieval-pages/07-library-management.md#成员授权抽屉b--权限矩阵)，按个人调整本库权限，批量操作仍是逐人授权，不引入组；复核后一次保存，至少保留一名有效管理员。停用阻止新上传、新检索和新 Agent 绑定，允许管理读取／编辑，保留资料、索引与绑定；启用不自动重建。

管理抽屉桌面上限 820px，窄屏满宽；固定标题和动作区、中间滚动。表单防重、失败保留输入、版本冲突提示刷新后重新编辑。关闭按共享确认处理未保存输入，支持 Esc、焦点回归。删除仅限空库且无保护引用：锁库、校验版本、重新检查仍保留的资料及 Agent 当前／历史版本后删除；与上传登记、Agent 绑定使用同一库锁。无级联、自动解绑或「删除即停用」。同域名称在服务端统一规范化，创建与改名采用同一并发约束；停用仍占名。

页面切库、切域、切租户或身份刷新时取消旧请求，清空内容、回执／游标及本地图片 URL；再用请求代次阻止迟到响应。列表筛选先权限后分页；加载、空态、不可用和失败各有独立状态。保留主动内容安全策略与无权时的存在性保护。

知识库 App 的 Agent 创建／编辑沿用现有右抽屉。运行模型区的字段从顶部对齐，单侧说明不拉伸相邻的下拉框，窄屏按单列显示。「高级配置」不提供原始 JSON，只提供运行时实际读取的两项：路由置信度（较宽松 40%／标准 60%／较严格 80%）和情景记忆（开启／关闭）。标准和开启为运行时默认；已有非预设置信度可以继续保留。保存只覆盖用户修改的配置项，其余现有字段保留；关闭情景记忆不删除历史。未接入现行问答链路的默认路由和检索限额不展示为可用项。

## 5. 合同、代码落点及验收

| 合同 | 保留与补齐 |
|---|---|
| 库目录管理 | 保留 list/get/create/PATCH 语义及 `expected_revision`。区分使用态与管理态的投影；补更新时间、可披露统计、允许动作和阻止原因。新增带 `If-Match` 的 DELETE；公开建库接收名称、说明和按库模型绑定，不收解析档位；批准请求明确携带档位。 |
| 资料治理 | 保留上传、原文、审核、撤回、取消；移除手动发布 API；补按岗位筛选的任务与版本精确详情。分别返回处理、审核、发布及 `allowed_actions`；详情不泄漏列表不可见记录。 |
| 任务维护 | 版本操作 `:reprocess`、`:retry-index` 校验当前任务 ID；管理态 PATCH 可原子保存模型并排队。库级 `/index-rebuild` 返回控制状态并执行开始、逐文件重试、放弃或整批切换。 |
| 检索 | 保留 `/libraries/{id}/search`、主结果续取、关系续取和精确内容端口；上下文及 PDF 预览另使用检索回执与本次证据键，复用发布视图和原文件，不重跑解析或索引。游标绑定主体、作用域、模式、条件、发布快照与期限；关系游标另绑定锚点。 |
| 错误 | 参数不合法、权限不足、库停用、版本过期、依赖阻止、快照失效及服务异常分开；机器码稳定，中文信息不泄漏配置、路径或隐藏对象。 |

KBot4 用现行可信 Token／Domain、独占 Oracle Schema、`ui/knowledge_retrieval` 静态入口。Ammolite 用可信 Tenant／Domain、Portal 子路由、PostgreSQL `knowledge_retrieval_*` canonical ORM 与初始化。BFF 前缀不同，不强制统一网络路径。沿 `BFF → App 用例 → UoW / Repository` 落地；不跨 App 读取库、文件和索引。两仓同步合同、公开及内部 OpenAPI、客户端、用例和测试；KBot4 不新增业务 UNIQUE／CHECK，Ammolite 不引入兼容链和本地历史回填。

1. 权限与能力声明先行：只读用户可查而不必能问答，上传者可查自己任务，审核通过后自动发布，不隐含撤回权限；无 OCR／视觉能力不展示假入口。
2. 页面拆分及生命周期：卡片、抽屉、失败及焦点测试；停用仍可管理，只存在历史引用也不可删。Oracle／PostgreSQL 分别验证同名竞态和删除与上传／绑定竞态。
3. 证据链：两仓用同批原生 PDF、Office、表格、扫描件和带图题引用的资料验证审核顺序、撤回旧快照、同日期排序、请求数量、无命中／部分覆盖、精确预览、跨域隔离和 Agent 实际图片交付。离线夹具不等同真实模型、数据库或线上验收。

实施以[已确认方向](knowledge-retrieval-pages/direction-approved.md)为准。直接检索独立于 Agent 问答；提交单回执跳到精确任务／版本；三个治理目录由服务端读取投影提供资格、筛选和允许操作。知识库管理通过当前工作域 IAM 候选人管理成员，受保护删除复核资料与仍保留的 Agent 版本。Oracle 与 PostgreSQL 使用各自的目录写入锁，无新增表或数据回填。
