# 04 · 解析任务

[整体设计](../knowledge-retrieval-ui-alignment.md) · KBot4：`processing.html`；Ammolite：`processing`。上传者看自己，治理人员看被授予的范围。处理资料解析与索引任务；文件审批在知识库文件页；审批通过后，后台在启用库内完成首次解析和索引校验时自动发布。

## 信息与操作

- 筛选库、处理进度、本人／授权范围。列表四列为文件名、版本创建时间、处理进度、解析结果。取消重复的「处理阶段」列；最后一列用「成功 ›」「失败 ›」「未完成 ›」打开结果，不叠加按钮边框和徽章。索引失败时解析结果仍是「成功」。列表不显示文件 UUID 或错误码；查询先按岗位与归属过滤再分页。
- 「处理进度」使用已确认的 [方案 A · 紧凑百分比条](direction-approved.md)：左侧显示当前步骤、已提交批次与细进度条，百分比在右侧对齐。识别和整理仅显示实际步骤。说明入口打开右侧抽屉。当前页有未结束任务时每 6 秒尝试刷新，隐藏页面或打开抽屉时暂停，也可手动「刷新进度」。
- 结果抽屉复用知识库文件及 AIOps 的详情样式：栏头以文件名为主标题，「解析结果」为栏目标签；正文分为任务概况、按需显示的重新解析设置／索引重建和任务详情，底部集中呈现允许的操作。概况区保留解析与索引的说明及下一步提示；详情区显示错误码和历史任务。说明首次索引校验后自动发布、重建索引校验通过后自动生效；待审批不是解析排队；不显示堆栈、路径、模型密钥或其他主体资料。
- 从任务跳到有权看的文件详情；「取消任务」仅后端明确允许的上传者本人、未发布且仍处可取消阶段可见。经共享确认后提交，刷新任务；状态被 worker 抢先改变则说明不再可取消。

## 重新解析和重试索引

- 审核通过、已完成索引或当前解析失败的文件，具备 App 审核资格 + 本库 REVIEW 时，在结果抽屉显示「重新解析」。读取同一原文件，用当前解析程序创建新任务，保留文件版本、审批记录及原任务。提交成功后关闭抽屉，表格从新任务的排队状态显示进度。
- 「沿用原解析方案」复用原解析档位和模型版本，不可用时说明原因。「使用当前库模型重新解析」重新校验三档，自动判断可用时默认该档；无模型的原生解析仍按其实际能力执行。
- 已发布文件重新解析时沿用原发布索引的模型配置，旧版继续提供检索。启用库内校验通过后，后台在同一事务切换解析结果及索引；失败不替换旧版，暂时停用则等待库恢复。重新解析与同一文件的索引重建、整库重建互斥。
- 解析成功、索引失败时，App 管理资格 + 本库 MANAGE 显示「重试建索引」，不启动新的解析任务。每次提交携带当前任务 ID，状态变化或重复点击不重复建任务。
- 首次建索引和重建均分批处理，建索引的计时预算独立于解析，单批超时不抹掉已提交批次。同一解析结果、模型版本和索引规则匹配时，校验批次内容后从未提交批次继续；只有完整索引才能进入就绪或候选状态。
- 解析成功、索引已就绪时，App 管理资格 + 本库 MANAGE 可从抽屉点击「重建索引」。有两种权限时同时显示「重新解析」与「重建索引」。后台复用已有解析产物，按当前库模型重建索引，不重新运行 OCR 或 VLM。只更换检索模型时可重建索引；要应用新的解析规则或 OCR／VLM 模型时，可手动重新解析。

## 索引重建批次

使用同一解析任务页的「索引重建」查看整库批次，不新增页面。展示受影响的通道、已发布文件数和逐文件进度，失败码在对应文件的结果抽屉查看，无图片显示「视觉索引不适用」。App 管理资格 + 本库 MANAGE 可开始已保存的重建、单独重试失败文件、放弃当前批次。同一知识库有未结束的单文件任务时不能开始整库重建；整库重建未结束时也不接受新的单文件重建。

所有候选索引校验通过后，由 Worker 在最后一个任务交付的同一事务内自动切换。切换时再次核对当前模型配置、已发布文件范围及索引指针。任一文件失败、范围变化、模型改绑或指针不一致均不切换；旧索引保持服务（已解绑的通道除外）。先放弃已失效的批次，再根据当前范围开始重建。

单文件复用同一后台队列，每个文件有独立批次。一个文件正在排队或重建，不影响其他文件提交；同一文件只接受一个未结束的批次。表格和抽屉只显示相应文件的任务状态，重试或放弃只作用于指定批次。候选校验通过前不参与检索；通过后自动生效，若文件已审核但尚未发布，则自动发布。单文件重建不改其他文件或清除待整库重建状态。

## 数据、状态和验收

| 阶段 | 处理进度显示 |
|---|---|
| 等待、识别、整理 | 真实阶段，不显示预计时间或百分比 |
| 建索引、总批次未知 | 已提交 N 批；规划中显示「正在计算总批次」，不用估算百分比 |
| 建索引、已确认总批次 | 「N / M 批已提交」，进度条按占比向下取整；重试继续使用同一代已提交数 |
| 全部批次已提交、最终校验中 | 「校验索引 · M / M 批已提交」，斜纹条且不显示 100% |
| 校验通过 | 实色条与 100%；启用库内首次处理自动发布，重建索引校验通过后自动生效 |

首次构建用与执行一致的分段规则，在模型调用前以单批内存预算计算总数，冻结在现有代次清单中；重建采用来源索引已经校验的批次总数。只统计当前代次事务提交的连续批次，发布指针与候选代次分开读取；批次明细只显示有持久证据的已提交范围与未提交范围，不推断当前正在处理的序号。接口的 `index_progress` 包含 `committed_batches`、可空的 `total_batches` 与 `validated`。单文件或整库重建进行时，表格对涉及的文件展示此次重建的状态及批次，不显示来源索引的 100%；候选校验通过才显示 100%，自动切换后标记「重建完成 · 已生效」；放弃后回到原索引状态。解析结果不变，自动切换前旧索引继续提供检索。

以现有任务、parse 批次与 generation 构造岗位级别读取投影，补列表和精确任务详情；保持现有取消合同。以 `allowed_actions` 和原因呈现操作，不从错误字符串猜权限。加载、空队列、过滤无结果、刷新失败、已取消与失败分开；后台刷新不跳焦点、不覆盖切域后的页面。窄屏结果行转卡片，阶段视觉辅以文字，详情右抽屉满宽。

验收：上传者可通过回执访问本人任务；其他上传者／域不能枚举任务；解析完成不提前显示就绪；解析和索引失败各有独立的有权限操作；候选不被检索提前使用；切换失败整批回滚；取消与 worker 后续状态一致。

## 已确认布局：A · 任务清单

- 复用「知识库文件」的左侧选库卡片，仅列出有权查看解析任务的库。右侧显示当前知识库和筛选，不重复放知识库下拉或上传入口；窄屏选库区置于任务列表上方。以最后一列结果进入详情，不设常驻详情列或状态泳道。
- 任务详情从右侧抽屉打开，正文可滚动，栏头和底部操作保持可见；关闭回到原行，保留筛选与分页。窄屏为任务行卡片，详情抽屉满宽、概况单列，底部操作可换行。
