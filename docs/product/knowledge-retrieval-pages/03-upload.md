# 03 · 上传资料（原独立页面，已合并）

自 2026-11-21 起，以[知识库文件 · 方案 B](06-files.md)为准。以下内容保留原方案 C 的设计历史；独立入口已退役。

[整体设计](../knowledge-retrieval-ui-alignment.md) · KBot4：`upload.html`；Ammolite：`upload`。App 上传 + 启用库 UPLOAD。支持选择一个或多个独立文件，每个文件创建一份资料和独立审批记录；不提供资料分组、上传新版本或强制重建。

## 信息与操作

1. 选择有权且启用的库，服务端返回真实格式、大小限制、原生解析与 OCR／转写能力。没有 OCR 时明确扫描件的限制；文件选择器 accept 只提示，服务端复核实际类型。
2. 选择或拖入一个或多个文件（最多 20 个）；显示文件名、大小和逐文件状态，支持移除未接收项，保留键盘等价入口。拒绝不符合限制的文件，不生成回执；上传按钮防重。真实上传字节进度可展示，但不能冒充后续解析进度。
3. 接收成功时显示「已接收，等待审批」和库、文件／任务标识，提供「查看解析任务」「查看文件」；落地重新核权。页面不展示审核表单、解析档位或可检索状态承诺。审批通过前不启动解析。

## 数据、状态和验收

页面对每个文件分别调用 POST `/libraries/{id}/documents`，使用各自的 `Idempotency-Key` 和接收回执；失败项不阻塞其他文件，重试不重复提交已确认接收的文件。选库时预取能力，上传前核权和持久化登记时再核权。网络失败若结果未知，保留同文件和同键供重试；键冲突明确说明。换文件或新一次提交换键；切库、切域清理文件句柄、本地 URL、回执和重试键，迟到响应不挂回新库。未选库、无可上传库、读取能力失败、格式错误、上传中、已接收、网络结果未知各有状态。

验收：上传已接收不能显示「可检索」；同键同内容只产生一套待审批登记／文件；同键异内容冲突；停用和权限撤销阻断登记；无 OCR 不承诺扫描件可识别。

## 已确认布局：C · 提交单

- 顶部阶段条为「确认知识库 → 核对文件 → 查看逐文件回执」，表达当前操作阶段，不代表后台解析进度。桌面左侧是选库与文件清单，右侧是工作域、目标库及该库能力／限制的摘要，随选择同步。
- 一次确认，可包含多份独立文件，无额外向导步骤。仅收到服务端接收回执后，将「已接收，等待审批」置于同一提交单，提供任务和文件入口。窄屏按表单、摘要及回执顺序堆叠，提交前仍能核对库和格式限制。
