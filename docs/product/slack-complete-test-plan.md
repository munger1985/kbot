# KBot Slack 前端会话完整用户验收测试

## 1. 测试目的

本文档只从 Slack 使用者角度验证 KBot 的会话访问、问题理解、答案准确性和最终展示效果，不包含代码、接口、数据库、部署、后台任务或日志测试。

测试目标：

- 用户能够在 Slack 中正常发起问题并收到回复。
- KBot 能正确理解精确、模糊、混合和多语言问题。
- 回答内容与知识库事实一致，不编造、不串用不同 Asset 的信息。
- 无附件时 Slack 展示与 KBot 回答一致；有 DOCUMENT 附件时，正文
  Asset 数量、顺序与 Slack Template 一致。
- Slack Markdown、按钮、长消息和多轮会话显示清晰、稳定。
- 无结果、信息不足或处理失败时，用户能看到明确且安全的提示。

## 2. 验收范围

包含：

- 进入 Slack 频道、@mention、线程回复及连续追问。
- Asset 精确查询、条件查询、文档内容问答、结构化问数和问文问数混合。
- 模糊查找、多语言、口语化表达、拼写错误和歧义问题。
- 回答准确性、完整性、相关性、一致性及无来源内容检查。
- 正文、Markdown、Asset Template、KM Link、日期、空字段及长消息展示。
- 多用户、多频道、多线程下的用户可见结果。
- Slack Web、Desktop、Mobile 三端显示。

不包含：

- 服务端代码、接口、签名、数据库、配置、部署、后台 Worker 和日志。
- 运维监控、服务器性能、凭证管理和内部调用链。

## 3. 测试前准备

### 3.1 测试账号与会话

准备以下 Slack 测试条件：

- 至少 3 个普通用户账号。
- 至少 2 个测试频道。
- 一个允许所有测试用户访问的公共测试频道。
- 一个仅部分测试用户可访问的受限频道。
- Slack Web、Desktop 和 Mobile 客户端。
- 每轮测试使用新线程，同时保留若干线程用于连续追问。

### 3.2 测试 Asset 数据

| 数据组 | 准备内容 | 用途 |
|---|---|---|
| 精确 Asset | 10 个标题、ID、作者、日期、Solution、Product 均明确的 Asset | 精确匹配 |
| 相似 Asset | 5 组名称高度相似但内容不同的 Asset | 防止串信息 |
| 别名 Asset | 包含简称、旧名称、中英文名称的 Asset | 模糊查找 |
| 多文档 Asset | 同一 Asset 对应多篇或多个版本文档 | 去重验证 |
| 多 Asset 文档 | 一篇文档提到多个 Asset | 归属验证 |
| 缺字段 Asset | 缺作者、缺日期等可选字段 | 空字段展示 |
| 多语言 Asset | 中文、英文及中英混合内容 | 多语言验证 |
| 日期 Asset | 原始创建日期清晰且与收录时间不同 | 日期语义验证 |
| 大结果集 | 分别可返回 1、5、10、15、41 个 Asset | 极限展示 |
| 无匹配数据 | 确认知识库不存在的关键词 | 无结果验证 |

### 3.3 每个 Asset 的黄金答案

每个测试 Asset 应提前记录：

- 正确 Asset Title。
- 正确 Asset ID，仅供测试人员核对，不要求正文显示。
- Solution Briefing。
- Author Mail。
- Asset 原始创建或发布日期。
- Product、Solution、Industry、Status。
- 关键事实和禁止混入的事实。
- 所属文档及文档版本。
- 用户是否有权访问 KM Link。

## 4. 结果评价标准

### 4.1 准确性指标

| 指标 | 判断标准 | 验收要求 |
|---|---|---|
| Asset 准确率 | 返回的 Asset 是否都符合问题 | 精确查询 100%；总体不低于 98% |
| Asset 召回率 | 应返回的 Asset 是否全部返回 | 精确查询 100%；模糊查询不低于 95% |
| 事实准确率 | 标题、作者、日期、产品、方案、描述是否与黄金数据一致 | 关键字段 100% |
| 回答有据率 | 回答中的事实能否在参考 Asset 或文档中找到 | 关键事实 100% |
| 无来源内容 | 是否出现知识库没有的信息 | 0 条 |
| Template 覆盖率 | 有 DOCUMENT 附件时，正文每个 Asset 是否有一个对应 Template | 100% |
| 多余 Template | 是否出现正文未提到的 Asset Template | 0 个 |
| 顺序一致率 | 正文 Asset 顺序是否与 Template 顺序一致 | 100% |
| 去重准确率 | 同一 Asset 的多篇文档是否只显示一个 Template | 100% |
| 用户可读性 | 是否清晰、无乱码、无内部技术信息 | 100% |

### 4.2 单条回答验收方法

对每条回答依次检查：

1. 回答是否直接回应用户问题。
2. 返回的 Asset 数量是否正确。
3. Asset 标题及详细描述是否准确。
4. 不同 Asset 的内容是否发生串用。
5. 无 DOCUMENT 附件时，Slack 正文是否与 KBot 窗口回答内容一致。
6. 有 DOCUMENT 附件时，正文 Asset 顺序是否与 Template 顺序一致。
7. 同一 Asset 是否只出现一次 Template。
8. Template 是否正确显示 Title、Briefing、邮箱、日期和 KM Link。
9. 是否存在 `[C1]`、`[C2]`、`[Q1]` 等用户不可见标签。
10. 是否出现内部 ID、路径、堆栈、系统指令或“参考资料”列表。

## 8. 缺陷等级

| 等级 | 用户影响示例 |
|---|---|
| Blocker | 跨授权范围泄漏；回复到错误用户/频道；KM Link 指向错误 Asset |
| Critical | 精确查询返回错误 Asset；正文与 Template 严重错序；重复发送大量消息 |
| Major | 漏掉应返回 Asset；Briefing/作者/日期错误；多语言不可用；长结果丢失 |
| Minor | 换行、标点、折叠、对齐等不影响事实的显示问题 |

## 9. 发布验收标准

发布前必须满足：

1. 所有 P0 用例通过。
2. 精确 Asset 查询的 Asset、必填字段和 KM Link 准确率为 100%。
3. 普通 Asset 回答中正文与 Template 的数量、去重和顺序准确率为 100%。
4. 无 DOCUMENT 附件时，Slack 不根据 QueryResult 重建正文，也不追加 Template。
5. Slack 可见消息不显示引用标签、参考资料列表、内部 ID 或技术错误。
6. Template 的完整时间戳只显示日期。
7. 无结果时不生成无关 Asset 或空 Template。
8. 中英文核心查询均通过；模糊查询达到约定召回率。
9. 15 个以上 Asset 的长回复无丢失、重复或顺序错乱。
10. Slack Web、Desktop、Mobile 的正文、邮箱和 KM Link 均可正常使用。
11. 不发生跨用户、跨线程、跨频道或跨授权范围的信息混用。
