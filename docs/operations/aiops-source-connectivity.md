# 监控源异步连接检查

新增监控源、修改连接地址/凭据/配置，或点击“测试连接”时，不在 HTTP 请求和数据库行锁内访问监控服务。

1. 配置与 `SOURCE_CONNECTIVITY_CHECK_REQUESTED` Outbox 消息在同一事务提交。
2. 页面保存完成后关闭抽屉、显示“检查中”；手动测试接口返回 HTTP 202。
3. AIOps Worker 读取已提交配置和加密凭据，执行有超时限制的真实健康检查。
4. Worker 按检查请求 ID、配置版本及连通性版本条件回写结果；旧请求不能覆盖新配置。
5. 页面自动刷新至真实结果。超过刷新预算时提示稍后刷新，不把“等待后台处理”伪装成不可达。

新增源默认停用；连接配置变更也会先停用并清空旧能力快照。检查通过后需要用户明确启用，
不会把成功保存或 HTTP 202 视为已连通，也不会自动启用。只修改名称不触发检查或停用。

异步执行依赖正常运行的 AIOps Outbox Worker；只运行 API 无法消费检查消息。
发布时须同时加载 API/Worker 新代码与前端资产。检查失败会保留配置并记录稳定错误码，
不能因为后端网络缓慢让编辑表单持续“正在提交”。

## Loki 排查

Loki Source 填写查询根地址。健康检查访问 `/ready`，日志读取访问 `/loki/api/v1/query_range`。
只修改 App 中地址不会启动 Loki，也不会配置日志采集器。

- 先确认服务/容器确实存在、端口开放，再核验 readiness 和实际日志查询。
- App 在宿主机运行、Loki 端口发布至该宿主机时，才可使用 `127.0.0.1:3100`。
  App 在容器或远程服务器时，回环地址指向 App 所在运行环境，不能照搬。
- 单租户开发实例通常不填日志租户 ID；认证和租户头必须与真实 Loki 部署一致。
- 日志绑定必须与采集器实际写入的 job/target_key 等标签完全一致。
  Prometheus 标签更新不会自动更改已有 Loki 流或日志绑定。
- 观测栈通过唯一 `var/aiops-stack/aiops-stack.ini` 的 `[logs]` 配置启用，
  使用无参数 `scripts/aiops-stack` 部署；不能直接修改生成目录或从 App 假定日志采集已开启。

更新代码本身不会启动日志服务或改动运行中的源/绑定数据。日志部署、绑定校准和应用加载
必须分别执行并验收；不能把代码测试通过当作运行环境已恢复。
