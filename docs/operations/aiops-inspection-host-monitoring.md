# 巡检关联主机监控

数据库日常、周度巡检的“任务执行结束”和“必要检查完整”是不同状态。
必要检查仍由冻结的报告策略决定，不能把缺少 CPU、内存、文件系统样本的报告强制标成完整。

## 采集范围

巡检继续复用数据库实时总览取得数据库指标，同时按主机实时总览目录选择报告策略要求的主机指标。
指标标识、来源支持范围和阈值均来自现有版本化目录，不在巡检代码中另设阈值。

仅沿当前 Agent 版本已授权业务系统内、已确认的数据库 WORKLOAD → HOST 的 RUNS_ON 关系发现活跃主机。
计划已指定业务系统时，主机发现进一步限制在该系统，不扩展到 Agent 的其他系统。
主机来源必须在本次已授权来源集合中、已启用并具有 metric.query_range 能力，且绑定明确声明 HOST 资源定位符。
数据库监控定位符不能代替主机定位符，也不按 IP 或名称猜测关系。

每台关联主机的必要指标及候选绑定均进入冻结范围。
即便某台主机没有监控绑定，也须保留该主机的缺项，不能由另一台主机的正常样本代替。
超过有界关联范围时报告明确缺口，不任取其中几台后声称完整。
空间趋势原有的主机取证语义保持不变。

## 冻结与判读

Run 的监控快照保存 inspection_host_profile、required_host_metrics 和主机绑定的
inspection_host_context；关系版本、绑定版本、来源版本、精确指标定义和目录阈值随本次运行冻结。
正式报告保留主机 Profile 与必要主机指标范围；原始监控证据投影保留 binding_id。

日巡检仍使用冻结的当前快照窗口和样本时效，历史参考不能代替当前样本。
完整且可追溯的正常样本允许报告完成；超阈值可以“检查完成但存在异常”。
未授权、没有绑定、查询失败、主机空样本、过期样本或缺少计算溯源均保留未完成状态。
主机查询成功却无样本时，可报告监控盲区风险，但不能据此完成该主机的健康判断。
每次来源配额准入及后续历史结果复用均重新校验当前授权、承载关系和版本；撤销后不能继续查询。

## 变更边界

仅修改 AIOps 应用的监控采集、报告判读、仓储查询和授权校验，不修改数据库结构、
模型服务、Prompt、公共 API 或已冻结的历史报告。
历史版本不会因代码更新自动变成完整，需要在部署后重新执行巡检形成新的证据和报告。
