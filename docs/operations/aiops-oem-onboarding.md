# OEM 服务接入与业务系统数据库绑定

日期：2026-11-05

适用：KBot4、Ammolite Cube。状态：代码与本地回归完成，实验 OEM 只读联调通过；
尚未部署本次代码、重启应用或完成页面到真实业务系统落库的端到端验收。

## 职责边界

- 监控源只保存 OEM 服务地址和受管凭据，不选择数据库，不填写 GUID 或标准指标 JSON。
- 具体数据库在“业务系统 → 系统构成 → 数据库资源 → 监控映射”中选择。
- 一套 OEM Source 可供多个数据库资源引用，不为每个数据库重复创建 Source。
- 平台复用现有实例发现、短期候选引用、业务系统事务和 Source Binding，
  不新建第二套资源或绑定体系。初次接入不改变 Schema 或路由；
  已有资源编辑补齐了公共 DTO 与 OpenAPI 快照，不新增持久化表或路由。
- 初次接入不等于指标采样验收。后续已补充数据库/主机原生目录与数值监控面板，见
  [OEM 原生指标监控](aiops-oem-native-monitoring.md)；标准指标自动映射、文本历史、
  Exadata/ODA 及 Agent 指标扩展仍未交付。

## 操作流程

1. 新建 OEM 监控源，填写名称、官方 API 地址及只读账号凭据。
   Endpoint 例如 https://oem.example.com/em/api，也接受 /em。
   保持 TLS 验证，凭据保存后不回显。
2. 测试服务连接并启用监控源。服务连通不等于每种数据库插件、指标或关联硬件可用。
3. 在业务系统中添加数据库资源，先明确引擎、版本及 Oracle 容器范围，再选择 OEM。
4. 系统按引擎发现账号可见的已登记数据库目标。用户从候选中选择，不手填定位键。
   候选展示名称、真实目标类型对应的范围，以及可取得的数据库名、版本和主机。
5. OEM 不要求额外选择 Prometheus 主机 Label；RAC 各节点分别选择可核验的数据库实例。
6. 发布前按稳定 GUID 刷新短期候选引用；服务端在写入 Binding 前再次读取目标，
   复核引擎、身份和 Oracle 范围，再由调用方事务统一提交。
   草稿保存不证明绑定已经生效。

已有数据库同样在此页面编辑：选择当前要修改的监控映射，再切换 OEM，
发现并选择具体数据库，发布时更新原资源的绑定，不需要移除或重建数据库。
其他可修改字段也已与新增页对齐，参见[新增与编辑字段核对表](aiops-business-system-resource-edit.md)。

目录使用受控分页分批读取；浏览器不直连 OEM，也不能提交任意 Provider URL、查询或原始 GUID
替代候选引用。分页令牌循环、目录重复或预算耗尽会明确失败，不将截断结果冒充完整目录。
用户切换引擎或来源后必须重新选择候选；同名但 GUID 改变的目标不会自动替换原对象。

## 引擎与身份边界

当前发现器按明确登记的插件类型筛选，不从显示名称猜测数据库引擎：

| OEM 目标类型 | AIOps 引擎 | 当前边界 |
| --- | --- | --- |
| oracle_database | ORACLE | 读取 CDB 属性，区分 CDB 与非 CDB；RAC 节点还需核验实例编号 |
| oracle_pdb | ORACLE | 核验 IS_ROOT 与 PDB 名；CDB$ROOT 辅助目标不作为普通 PDB 候选 |
| mysql_database | MYSQL | 已登记解析和模拟回归；当前实验环境没有该插件目标，未完成真实联调 |
| 其他类型 | 不自动推断 | 未登记插件类型不冒充已支持；AIOps 有该引擎不等于 OEM 插件已适配 |

Oracle CDB 在 AIOps 公共合同中使用 CDB_ROOT；页面可显示“CDB”。
该定位边界不证明后续每个 OEM CDB 指标都能等价映射为 AIOps 指标，指标语义另行核验。
PDB 名、已观测数据库名及容器范围不一致时拒绝保存；RAC 集群汇总目标不冒充节点实例。

OEM 24ai 的 id/name/typeName 与既有 OEM targetId/targetName/targetType
统一为严格核验的目标身份；字段冲突或 GUID 不匹配即失败。
目录按 OEM 返回的 page 令牌续取，不以 offset 参数假装已经翻页。
只提取固定端点的有界令牌，不执行返回链接中的主机、路径或额外查询。

## 独立主机与容器配置

数据库候选与主机候选分开选择。在“系统构成”中添加物理服务器、虚拟机或容器，
选择 OEM 后点击“发现主机”，只列出账号可见、经过详情核验的 `host` 目标。
保存独立主机 GUID，不借用数据库 GUID，也不再要求手填标识。

勾选该主机承载的数据库建立明确的 `RUNS_ON` 关系；单实例加主机仍属于单实例架构。
OEM 的 `hostName` 若实际指容器，资源类型应为容器，而非物理服务器或虚拟机。
容器不能绑定宿主机的 Prometheus Node Exporter 身份。已有系统定向补配置时，
应核实实际 Docker 承载层级，复用已有宿主机；不能仅凭名称或 IP 自动合并。

资产绑定不证明所有指标有采样；OEM 主机原生数值指标已接入监控页面，ODA/Exadata 仍未实现。
配置和查看权限跟随业务系统，不因账号可见更多目标而自动关联或扩大 Agent 授权。

## 既有配置与授权

- 编辑 OEM 服务信息不会清空已有受管凭据或历史指标映射，也不会自动改写既有数据库绑定。
- 新建/显式修改 Source config 不再接受数据库定位字段或 standard_metric_mappings。
  已有指标解析逻辑保留，本轮不为新资源猜测默认指标映射。
- OEM 手工 SourceBindingCreate 以及直接修改绑定定位键/定位 JSON 均被拒绝；
  新绑定必须走已授权来源的实例发现与保存前复核。
- 沿用现有 Domain、Ammolite Tenant、操作者、候选过期、ETag、幂等和事务边界，
  不因 OEM 账号可见某目标就扩大当前用户或 Agent 的资源访问权。
- 未改变 OEM 用户权限、数据库账号、管理包许可、监控源实例或线上配置。
