# 聊天当前告警与历史告警筛选（2026-11-09）

## 问题与原因

用户在 2026-11-09 10:02:21（Asia/Shanghai）询问当前健康状态，回答却列出
10-21 等窗口外的旧告警，并把监控信号的 RESOLVED 显示为“已解决”。
线上开发日志确认对应 Turn Router 于 02:02:21 UTC 正常完成；
代码中的聊天告警查询没有时间条件，Ammolite 还没有状态条件，却使用“当前告警”标题。
监控接收流程只按各来源最新信号判断是否恢复，不代表 DBA 人工处理或验证完成。

## 行为

- CURRENT 默认只查最近 1 小时有入库观测且未恢复、未关闭的告警；
  用户指定时间时沿用 TurnPlan.time_range。窗口外旧待处理记录也不混入当前列表。
- HISTORY 用于用户明确要求的历史查询，默认最近 24 小时，可按时间、状态、严重程度及数量筛选。
  这里只按最近观测时间筛选已入库情境，状态是最新入库状态，不宣称还原历史时点状态。
- Router 接收结构化参数合同及参考时间，不按产品名、告警标题或提问关键词硬编码分流。
- 时间与状态条件在仓储分页、LIMIT 前执行，并参与签名游标，不能跨筛选条件续页。
- 回答展示实际筛选范围；零行只说明这些条件下没有匹配记录，不证明实时告警源无故障。
  截断时说明还有未展示记录，不宣称查询完整。
- 监控 RESOLVED 在聊天中显示“告警已恢复”，不修改 DBA 工作项或人工效果验证的“已解决”语义。
- 无数据库 Schema、Prompt 基线或管理员 Prompt 变更；不改写旧会话，不在服务器拉取或重启。
