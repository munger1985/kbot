# SQL 诊断证据与授权边界

更新日期：2026-10-28。本文描述本轮代码能力，不代表已部署或已通过真实数据库验收。
[SQL 诊断详细设计](../proposals/aiops-sql-diagnosis-detailed-design.md)仍是目标态，
[实施记录与发布检查](aiops-sql-diagnosis-implementation.md)区分已实现与尚待交付的切片。

## Oracle 授权声明

在 AIOps Target 编辑页按合同实际授权声明 Diagnostics Pack 和 Tuning Pack；
数据库参数、账号权限和连接成功都不能证明许可证有效。未确认 Diagnostics Pack
不得使用 AWR/ASH；SQL Monitor 同时要求两项声明。许可守卫继续适用于目录及动态查询。
普通当前游标、计划与对象观察不因未声明 Pack 而整体不可用。
AWR 窗口采用实际快照区间，不能默认固定一小时，也不能分摊成精确 15 分钟。

## Top SQL 的窗口和候选

默认窗口入口仍为最近 15 分钟、总耗时排序、10 条。明确列表入口不因历史会话分析过
某条 SQL 而自动进入该 SQL 的深入调查；窗口不可用时累计排名仅为独立参考，任务部分完成。
窗口已有可比较区间时不重复读取累计主表，当前活动与历史窗口是不同事实。

周期采集支持 BOUNDED_CANDIDATES 和 VISIBLE_SET 两种策略，默认仍不开启采集。
前者只读取有限累计候选；后者尝试读取当前凭据可见集合，但仍受 10–500 行上限、
超时和既有字节预算约束。触及上限、截断或来源不完整时不称集合读取完成；
即使读取完成也不是原子快照，更不保证捕获两次采集间已消失的 SQL。
模式、上限、可见范围和非原子性质保存在现有快照 JSON，无新增持久化列。
业务系统编辑页可修改，发布后生效；已上线系统仅查看，不自动启用或回填历史。

自采差分对齐到不晚于两个请求边界的最近快照；偏差上限使用配置的采集间隔。
结果显示请求/实际区间、边界偏差、EXACT / SAMPLE_ALIGNED / OUT_OF_TOLERANCE、
有效分段、候选范围和缺口，不插值、不把对齐区间当精确请求窗口。
已识别的重置/淘汰、计数回退、实例变化、源版本变化及缺采会截断对应差分。
未检测到重置不等于证明连续，单条重置后正增长仍可能无法识别。
平均耗时用耗时增量/次数增量；累计 max 和百分位数不能相减。
MySQL 显式 NULL Schema 与空字符串分别保留，PG 的库 OID、用户 OID、top_level 不隐式合并。
Oracle 自采语句保留已取得的计划哈希维度；完整 RAC/容器代次语义仍须真实验收。

## 选行、跨轮和授权

结果行的深入分析提交类型化 sql_diagnosis.selection_ref，不把 SQL 文本作为执行输入。
引用只定位不可变的 DBA_SUFFICIENCY 证据行，不授予权限；服务端校验用户、会话、
Agent 及其版本、Domain、Target 状态/版本/类型、当前访问授权、有效期和行哈希；
Ammolite 另外校验 Tenant。失败返回明确错误，不自动换 Target。
结构化选行可引用同一会话内非紧邻上一轮的历史结果；仍保留原采集时间和来源。

Target 逻辑标识和配置版本不能证明物理实例始终相同。跨轮历史事实不得被当作当前采样，
不能凭继承统计使当前充分性升级。未携带选行引用的自然语言追问，目前仍只继承紧邻
上一轮的有限 SQL 观测；完整多候选消歧和有界跨轮搜索尚未交付。

Query ID、计数和 Decimal 的新投影使用精确字符串，不先经 float；
PG 十进制 query_id 不使用 Oracle SQL ID 校验。原始证据和各维度分开保留。

## 多源调查、结论和方案

普通单 SQL 调查不再使用固定 Oracle 基线快捷返回；两端三库均进入现有完整调查器，
向规划器提供当前授权的工具/Playbook，按问题选择数据库、监控、日志等证据，
来源策略只是偏好，不再作为“监控不足才能查库”的门禁。
既有显式 Oracle SQL 健康检查入口仍可执行其登记的观察基线；它不是所有调查的必跑列表。

增加 SQL_EVIDENCE_BUNDLE.v1 和 SQL_DIAGNOSTIC_ASSESSMENT.v1：
保留字段、时间、语义、质量、行级引用和血缘，区分目标 SQL 与背景。
相近时点的已核验活动会话可与锁/事务行关联；该关联不证明其他时间的阻塞或对象访问路径。
模型按实际证据给判断、机制、替代原因和条件化措施，方案包含条件、风险、验证、停止/回滚
及审批要求。计划不是阻塞/事务/日志诊断的统一前置条件。

服务端校验结构、行/字段引用、来源可信级别和目标作用域，拒绝只用其他 SQL、
对象背景或模型推断自证目标 SQL 已确认原因。引用存在不能机械证明自然语言因果：
DBA 真实场景复核仍是发布门禁，不能把合同测试当作诊断准确率。
单 SQL 不重复 Top SQL 主表，不以 Finding 为空组织开场。
生成失败才降级为确定性证据摘要，并标记部分完成，不把摘要称为已完成根因诊断。

只读诊断可以输出待验证/待审批的变更草案，但草案不接执行器。
系统不会自动执行 EXPLAIN ANALYZE、用户 SQL、建索引、改参数或安装扩展。
PG 全局 stats_reset 不是单 SQL 的确定起点，plan_count=0 不代表没有计划，
对象级扫描统计不能单独归因于目标 SQL。

MySQL 补齐独立方言的长尾只读查询：专用策略、签名 Grant、Executor 再校验及只读事务，
仅允许授权策略内的目录/性能视图和函数；禁止业务表、DML、变量、文件、锁及多语句。
Oracle/PG 现有安全路径和 Oracle Pack 守卫保持有效。

## 时限与发布

普通交互 Turn 接收时冻结默认 90 秒绝对 deadline，模型路由、Run 和 Worker 沿用，
重规划为汇总默认预留 20 秒；预算可配置，预留必须小于总预算。
Worker 在剩余预算不足时不启动 Handler，超时等待取消清理；已归档的受控事实可在
截止事务内形成唯一 PARTIAL 回答，未取到事实则仍明确失败/过期。
Run Reconciler 对已有 Run 独立收敛；这不等于所有排队阶段均已实现独立截止扫描。
排队尚未创建 Run、WAITING_USER 预算恢复、跨进程底层查询终止与迟到回收，
仍需补足独立状态机及真实故障验收，不能据此承诺所有场景严格 90 秒完成。

Prompt 文件和开发同步的数据库基线统一保持 1.0.0；内容变化不会自动覆盖数据库中
已发布版本。部署时须定向同步并激活更新后的规划、评估 Prompt 及 aiops_agent.sql_diagnosis，
核验实际内容 Hash 和输出合同，不得以新增管理员版本代替开发同步。
只有用户经网页手工维护才增加版本号；开发同步不得覆盖手工版本、强制重置真实历史，
也不得直接运行全库初始化覆盖现有配置。历史运行保持原冻结材料，不冒充已套用新内容。
本轮没有新增表列、没有数据库侧变更，也没有自动部署或重启。
