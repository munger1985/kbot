[SQL 诊断详细设计](../proposals/aiops-sql-diagnosis-detailed-design.md)；
目标设计尚未实施，不改变本文所述现状。

2026-10-28 目标设计已按多源调查、假设检验、条件化解决方案和真实闭环验收重新修订；
包括扩大跨轮证据引用、补齐资源发现及全流程 deadline，均不能视为本文当前实现已具备。

## Oracle 授权声明

在 AIOps 的 Target 编辑页，核对合同后按实际授权勾选 Oracle Diagnostics Pack 和 Tuning Pack。
不勾选代表未知或未确认，AWR/ASH 不可用；SQL Monitor 同时要求两项声明。
数据库参数、账号权限和连接成功均不能证明许可证有效，系统不会自动核验合同。
声明保存在 Target 的 capabilities.entitlements 中，分别为
`ORACLE_DIAGNOSTICS_PACK`、`ORACLE_TUNING_PACK`。
声明变更影响后续冻结的诊断任务，新版本冻结的任务按其既有授权快照执行。
升级前已冻结的动态查询可能因策略快照变更而安全拒绝，需要重新发起。
普通 Oracle SQL 健康检查不包含 SQL Monitor；满足两项授权后可单独调用 SQL Monitor
相关工具，不因缺少授权阻断普通游标、计划及对象取证。

## Top SQL 与计划

周期 SQL 快照目前只采集累计排名的有限候选，两个可比较快照只能计算已采集候选
的增量排名，不能证明覆盖全部窗口热点；出现、淘汰、重置、采集缺失或窗口覆盖
不足时必须保留相应缺口。累计值、当前活动快照和已采集候选的窗口增量不能相互替代。

明确选择的列表功能只执行与该入口直接相关的只读计划，由服务端按证据类型生成
结果与说明，不因历史对话或模型补证要求切换到单对象调查。Top SQL 在窗口不可用时，
若当前能力允许，才读取同一 Target 的累计排名作为独立参考；累计排名不能关闭窗口
缺口或使本轮标为完整成功。窗口已有可比较区间时跳过累计参考。快照未启用或尚未
覆盖请求窗口时需要在 Target 采集配置中处理并等待后续数据，不可回填过去的窗口。
Oracle 的 AWR 仍受授权及实际快照区间约束，不因该参考查询自动获得使用许可。

PostgreSQL `pg_stat_statements_info.stats_reset` 是全局重置时间，不是单条 SQL
的确定起点；单条重置和淘汰也可能影响统计。`plan_count=0` 不代表没有执行计划，
需结合 `pg_stat_statements.track_planning` 和计划证据判断。对象索引目录查询仅返回
指定对象的可见元数据，不能证明索引在历史执行中被使用；零行也可能是权限或对象不可见。
为兼容 MySQL 8.0 早期版本，索引查询不返回函数索引表达式。
缺少业务 SLO、基线或实际计划时，不以平均耗时或示例估算计划断言是否异常或实际扫描方式。
系统不会自动执行 EXPLAIN ANALYZE、创建索引或更改目标库配置。

## 单 SQL 回答与历史证据

对于目标类型和 SQL 标识明确的 SINGLE_SQL_PERFORMANCE 任务，服务端按可信的结构化
语句统计生成摘要；不同数据库、用户、游标或其他统计维度分别展示，不从块命中、
对象级扫描或累计耗时直接推断某条 SQL 的扫描方式、根因或耗时异常。累计最大值
不能通过快照相减得到窗口最大值，需逐次执行记录或专门采样。缺少窗口覆盖、
实际计划或业务基线时保留相应限制，已有证据不等于可确认根因。

跨轮只继承同一会话紧邻上一轮、同域、用户、Agent 和 Target 的可验证原始
SQL 观测，并要求 Target 配置版本及数据库类型一致；匹配标识和已明确的身份维度。
同一逻辑 Target 仍可能发生实例切换，因此历史观测不能据此认定实际实例相同。
保留原采集时间并标为历史，不继承模型
结论，不以历史观测提高本轮充分性。Finding 仍保留用于诊断和审计，无 Finding
既不代表无问题，也无需在每次回答开场解释内部卡片机制。其他通用诊断仍由模型
生成，不能视作已具备单 SQL 摘要的确定性校验。

源码 Prompt 的更新不会自动覆盖数据库中已发布的版本；既有环境需按管理员的 Prompt
管理和受控同步流程启用新版。单 SQL 的确定性摘要不依赖 Prompt 文案更新，但识别
任务和其他模型生成的诊断内容仍依赖实际生效的规划与回答 Prompt。

自然语言功能匹配先依据问题及可信上下文预筛选业务系统和资源的数据库类型；范围存在多种数据库
类型时，只将同时支持这些类型的功能交给能力解析器。模型选到目录外、不适用或参数
校验失败的功能时回退通用路由，原问题保持不变，不能据此执行该功能。用户在界面
明确选择功能时仍严格验证数据库类型和参数，不走此回退。回退不保证自动识别出
单 SQL 标识或补齐所有身份参数，后续仍可能需要进一步取证或澄清。

## 调查收敛

`max_investigation_replans` 默认 2，`max_investigation_replan_seconds` 默认 180 秒，
用于决定是否启动新一轮补证规划；它们不是全流程的硬超时，不中断已进行的模型或
数据库调用。原有运行 deadline、模型超时和工具预算仍分别适用。预算耗尽后以已有证据
回答并保留缺口，不把重复 artifact 当成新信息；不同时点活动采样仍可提供新观测。
