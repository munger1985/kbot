### 2026-10-29 执行计划优先与明确诊断交付

- Oracle 仅有 SQL_ID 的续问在取得完整 DBID、实例、容器、子游标及计划身份后，
  通过正式目录、DAG、Grant 和 Executor 确定性续取缓存计划，省去一次机械模型评估和重规划。
  每轮自动续取最多四份游标计划，零行、失败或已执行不自动循环；不扩大权限，不依赖 AWR。
- 三库已有计划统一按节点树在主回答展示，保留对象、索引、优化器成本、估算行数及原生
  实际统计单位。身份或物理来源不匹配/不完整的材料不冒充目标计划；人工声明一致、缓存
  LAST 行源与生产代表参数实际执行仍严格区分。原始证据保留，不将成本当毫秒。
- PG 的 pg_stat_statements 和 MySQL Digest 不存储可按标识读取的历史计划。
  两端对话新增“补齐执行计划”，复用代表参数专用保护材料、独立审批及隔离估算执行器，
  或通过已有诊断附件入口上传计划 JSON。入口按需读取真实 Run，实际可用性仍由策略、
  权限、原 SQL 可重放性及材料预检决定；不猜绑定值、不自动 EXPLAIN ANALYZE。
- SQL 回答显示已有 summary，并通过本轮模型输入和规范 Prompt 要求：先给有边界结论，
  再解释计划与工作量/等待/资源关联及针对性措施。允许明确“观察范围未见明显异常，
  暂不建议变更”；缺证不能证明健康，不因缺计划否定锁阻塞等直接证据。
- 评估/重规划只发送一份 SQL Bundle 数据投影，保留行号、字段、来源、截断和口径；
  不缩减开放工具目录，不增加预算或模型输出上限。模型失败仍为 PARTIAL，保留计划表
  及同一统计行计算的平均耗时，不将证据画像包装为完成根因分析。

本增量无 DDL 或线上写入；更新规范 sql_diagnosis Prompt 内容，文件基准按平台约定仍为
1.0.0。开发数据库定向原地同步并激活同一基线，不新增版本；只有用户在网页手工维护
Prompt 时才按管理流程增加版本号，开发同步不得覆盖该类手工版本。
本轮交付要求也随模型输入发送，不能把本地文件修改说成线上 Prompt 已更新。
本地回归、构建不替代真实模型、绑定诊断凭据和三库业务场景验收；未部署、未重启。

## 不同 SQL 比较的代码闭环

同一已授权 Target/引擎内 2–4 个独立 SQL 请求可使用 SQL_COMPARISON 进入完整调查，
共享历史搜索和证据投影预算。逐请求/主体分别取证与诊断，缺项不整体丢弃；不能把
只分析其中一条、仅比较同标识内部主体或累计数值当作完成跨 SQL 窗口比较。
完成门禁要求全部请求完整、每主体已核验结论齐全，并有连接全部请求的比较判断。
两端表格从各自来源行取值，逐行时间/口径和原始选行引用不丢失；
多主体对象图冻结到调查/报告并逐图重放，案例/报告来源复核覆盖每份原始工具 Artifact。
无模型或字段校验失败仍为部分摘要。无 DDL、无线上权限/采集修改，未部署、重启或发布 Prompt。
