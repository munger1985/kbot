# 健康诊断的完成状态与空结果语义

## 完成状态

诊断完成表示冻结的检查目标已执行并形成可核验判断，不要求检查发现故障，也不要求
已执行处置。健康、异常是数据库运行判断，与任务完成或部分完成分别表达。

只读查询成功、结果未截断且零行，表示该查询在实际范围内没有匹配记录，例如未发现
阻塞、长事务或匹配的问题SQL。该项检查计为已完成，不新增证据缺口。
正常返回的空告警列表只能说明该来源当前查询范围内没有告警，不扩展为全部历史无告警。

监控没有有效采样、查询失败、权限不足、来源不可用、请求窗口未覆盖、结果截断或
模型回答未完成，仍按真实缺口处理，不能用“无数据”包装为正常。
权限访问探针的零行只说明探针结果，不支持没有业务活动的判断。

普通健康检查没有额外同库历史基线，不新增未完成目标。用户明确要求历史对比、
性能劣化、趋势或SLO验证时，仍须保留对应证据要求；不编造改善或劣化判断。

## 空结果的可核验引用

原始证据的 `rows=[]`、`row_count=0` 和列定义保持不变，不补造业务数据行。
模型视图为已核验、未截断的完整空结果提供 `empty_result_reference`。
通用诊断可引用以下结果元数据：

- `field="$result.row_count"`：原始结果的返回行数。
- `field="$result.captured_at"`：原始结果的实际采集时点。

上述引用的 `row_index=0` 是结果回执的定位约定，不表示存在第零行业务数据。
普通业务列仍须校验真实行号与列名。引用不能用于把查询失败、截断结果、人工材料或
无有效指标采样升级为正常检查，也不能作为虚构的业务指标、建议参数或计算输入。
正式记录的冻结和证据重放均须校验引用。

## 结论表达

使用DBA值班记录口吻，按实际需要说明检查对象、时段、主要观测、诊断判断与必要处置。
无异常时直接给出相应判断，不强行编造故障原因、优化方案或额外补证任务。
具体缺口只在影响对应判断的位置说明一次，不追加泛化免责声明。

例如，基于已采集的负载、等待与当前告警结果，可表述为：

> 2026-11-07 05:11–06:11 UTC，ERP（demo）ORCLPDB1 负载较低，
> 未见明显等待堆积，当前规则无告警。未发现需要立即处置的性能问题。

不因本题未要求的历史基线追加“当前窗口无异常不等于整体健康已确认”等反转式结尾。
