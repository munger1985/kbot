# 三引擎通用快捷入口对齐（2026-11-09）

## 产品合同

目录版本 2.3.0，共 26 项；Oracle 可见 26 项，PostgreSQL/MySQL 各 10 项。
十个通用入口：健康、当前性能、Top SQL、活跃 SQL、阻塞与长事务、空间趋势、单 SQL、备份恢复、主备复制、参数检查。
Oracle 原生报告及实施档案不向其他引擎开放。六个 Agent 能力查询入口沿用统一授权路由。

单 SQL 统一入口为 database.sql.performance，参数检查为 database.parameters.review；不保留旧 Oracle 别名。
旧目录提交必须刷新。表单按所选实例展示 SQL_ID、Query ID/OID/层级或 Digest/Schema；
层级等可选范围不预选猜测值。UI、自然语言冻结、资源解析及澄清后续均校验引擎身份。
PG 未给全统计主体先查询主体列表；完整主体保留 database_oid/user_oid/top_level。
MySQL 保留 Digest 与 Schema；后续计划采集只使用当前已核验语句文本及完整主体。
计划采集不执行原 SQL 或 ANALYZE，不猜业务参数；计划与原始行、估算/实际语义保持区分。

## 取证与输出

固定基线及业务章节见 application/conversation_starters/common.py。
PG 当前等待单独汇总；Oracle/MySQL 等待类及 PG/MySQL 吞吐计数为累计统计，不冒充窗口速率。
三库活动会话排除当前采集连接，限制到当前数据库或容器。
成功、未截断的零行是完成的检查；无采样、权限不足、失败与截断不按正常处理。
已知证据缺口先走授权只读补采；不能仅因上下文缺少执行计划便要求 DBA 人工提供。
输出使用实例名称、可读状态、合理精度及单位；流式正文保持追加，最终图表不撤回正文。

PG 复制覆盖发送端、接收端、本地回放及 Slot 保留量；备库不调用主库专属的 pg_current_wal_lsn()。
MySQL 覆盖 Receiver、Applier、Coordinator、Workers 的运行及错误记录。
最新完成事务提交至应用耗时、当前正在应用事务年龄分别命名；
不再使用原始源与直接源提交时间差冒充 lag_seconds。
最近事务耗时告警类型为 REPLICATION_APPLY_LATENCY，不再称为当前复制延迟。
旧错误记录不自动等同正在失败；空闲时距最后提交/回放的时间不作为复制积压。
空通道结合角色解释为未配置、不适用或未观测，不能直接认定复制健康。

## 图表与平台适配

两个项目的 common_profiles.v1.json 为相同的通用场景合同，规定候选指标、标题、槽位、顺序及数量。
空间趋势最多四图，已用、使用率、可用、最大容量分开；稳定上限仍可展示，无采样不补零。
采样覆盖率低于 80% 标记限制，不依据低覆盖图给出强趋势结论。
KBot 在监控事实生成与最终展示之间使用同样的槽位选择和 Finding 排序。
各项目保留自身巡检场景集成及监控取证基础设施，不因通用场景对齐改写巡检档案。
不做应用 Schema 修改；Prompt 文件基线保持 1.0.0，不覆盖网页维护版本。

## 验证边界

专项覆盖目录及三库参数校验、46 个入口与引擎组合的计划和正式工具参数、
主体发现、当前/累计口径、采集连接排除、复制 SQL/列合同、图表选择与正文保留。
真实目标只读取证核验与单 SQL 计划图交付单独执行；演示目标无复制通道，
不能据零行声称已经验收真实复制积压或主备故障场景。
