# MySQL 物理容量与预计写满时间修复（2026-11-09）

## 口径

`estimated_days_to_limit` 是只读证据计算结果，不是管理员手填配置。
MySQL 数据量（data_length + index_length）、表空间可复用空间和文件系统容量分别保留，不混算。
Oracle、PostgreSQL 已有数据库空间趋势入口不改为 MySQL 路径查询。

## 取证链路

1. MySQL 空间入口及结构化空间趋势计划主动执行 `db.storage.locations`，有界采集真实 datadir、InnoDB 文件路径及 server_uuid。权限不足、零行和截断保留真实回执。
2. 仅沿当前冻结 Agent 版本授权业务系统内、已确认 RUNS_ON 的 HOST/WORKLOAD 关系附加主机取证。沿用已授权的同一 Prometheus 来源，不按 IP、名称或全域硬件目录扩大权限。
3. 主机使用唯一 `aiops-stack.ini` 的可选 `storage_path:*` 配置登记部署时核实的容器 ID 和路径对应关系。网络隔离、无 Linux capabilities 的只读采集器重新核对当前容器 cgroup/mountinfo、主机设备与文件系统内路径，通过 Node Exporter textfile 发布带核验时间的标准映射。
4. Agent 按 server_uuid、数据库 locator、路径目录边界最长匹配和新鲜核验时间定位文件系统。默认数据卷和外部 DATA DIRECTORY 分卷处理，未匹配或歧义不任选根盘。当前映射不证明历史数据库路径一直不变。
5. 文件系统仅连接同目标、来源、绑定、版本、完整维度、单位、窗口和采样时点的用量与上限。容量变化、留存聚合不明、缺样本、截断、不增长或增长不持续时不伪造写满天数。仅明确要求预测时进行未来外推。
6. 查询前及报告/案例复用前重新检查现存关系和授权；撤权或关系版本变化后停止读取。
7. 模型输入明确区分逻辑库趋势与承载卷风险，只允许引用已定位卷。不能要求用户猜挂载点、指标名或手工填写预计天数。

## 配置和安全边界

- 仅需物理容量映射时启用可选 storage_path 配置；普通 host 安装不自动启用。
- 配置包含 database_target_key、server_uuid、完整 container_id、database_path、host_path，不含数据库密码。
- 容器重建导致 ID 变化时必须重新核实映射，不沿用旧容器目录声明。
- 采集器没有 Docker socket、网络端口、数据库凭据或写主机根目录的权限。
- 只读挂载已登记的目录和主机 proc 元数据；只读取 cgroup/mountinfo，不读取进程环境、命令行或业务文件内容。
- 映射过期、容器/设备不匹配、符号链接、未支持的嵌套挂载或枚举超限时不发布本轮映射。
- 不修改业务表、真实诊断历史或应用 Schema；Prompt 开发基线保持 1.0.0。
