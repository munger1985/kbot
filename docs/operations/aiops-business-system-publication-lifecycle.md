# 业务系统发布与运行生命周期

日期：2026-11-05

适用：KBot4、Ammolite Cube。业务语义一致，不改变 Oracle/PostgreSQL 的持久化结构。

## 用户入口

新增 Wizard 最后一步的“发布资源”是一次原子发布并上线：校验资源与拓扑、验证数据库连接、保存监控映射，并将业务系统及其活跃数据库的内部 Target 置为运行状态。任何一步失败，业务系统、资源、映射、状态、幂等回执和事件均在同一事务中回滚。

页面只提供“上线”“下线”“重新上线”，不增加数据库资源或内部 Target 的第二套启用/停用按钮。已归属业务系统的 Target 不允许通过独立的 Target 状态命令绕过业务系统生命周期；监控源和 Agent 自身的管理开关不在此规则范围内。

编辑已下线系统并发布资源只保存配置，不自动重新上线；重新上线必须由用户明确发起。

## 内部一致性

| 操作 | 业务系统 | 内部 Target |
| --- | --- | --- |
| 新增并发布 | ENABLED | 通过监控源与连接门禁后 ENABLED |
| 上线、重新上线 | ENABLED | 统一校验并同步 ENABLED |
| 下线 | DISABLED | 无其他上线系统引用的端点同步 DISABLED |
| 其他上线系统仍引用共享端点 | 当前系统 DISABLED | 保留共享 Target 的原有运行状态 |

同步只处理 ACTIVE 系统资源与 ACTIVE 资源。端点按稳定顺序加锁并刷新 ORM 身份映射；下线时在同一锁内检查相同租户/Domain 的其他上线引用，避免关闭共享端点。下线不删除资源、凭据、监控映射、拓扑或历史，也不关闭 Oracle/MySQL/PostgreSQL 数据库进程。

上线复用端点原有门禁：至少一个有效监控映射、所有有效映射引用已启用监控源；开启只读连接的端点须有最近两小时内的连接成功记录。连接健康与运行意图仍分开，后台连接失败不会把系统自动下线，也不自动赋予受控变更权限。

业务系统和 Target 状态事件通过相同 Outbox 事务记录。返回的数据库 target_row_version 来自同步后的投影，不能返回状态同步前的旧版本。重复发布使用现有幂等回执，不重复创建资源或事件。

## 现有系统处理

本修复不在服务启动、readiness 或读取摘要时修改历史数据，也不增加兼容读取或自动回填。此前“系统已上线但 Target 未同步”的系统，部署新版本后可通过正常的“下线 → 重新上线”完成状态同步，无需独立启用 Target；上线门禁不满足时明确拒绝并回滚。

代码提交不等于线上部署。本次不执行线上 DDL、直接改库、拉取或服务重启。

## Agent 工作范围与动作授权

编辑 Agent 更换或缩小业务系统范围时，若 PATCH 省略资源动作策略（包括显式 null），新版本只继承仍属于所选系统的 ACTIVE 关联、ACTIVE 资源的原有授权。移出范围或失活资源的旧授权在新版本撤销；仍被剩余系统引用的共享资源授权保留。不会把旧库动作权限转授给新库，也不会自动赋予执行凭据或变更权限。

显式提交资源动作策略时仍严格校验范围，启用或禁用的越界策略均返回 422；显式空数组撤销全部授权。有效授权仍须通过能力、目标执行开关、执行凭据、动作兼容性和对象范围门禁。

仅修改名称或状态时，若需要撤销失效授权，也创建新版本。历史版本的资源动作快照不变；读取摘要不清理授权，不直接改库或回填。部署后重新保存 Agent 才应用上述范围收缩。

## 验证边界

两仓的 test_business_system_publication_lifecycle.py 使用真实 SQLAlchemy 仓储、规范 Entity 和本地内存事务，覆盖发布、失败回滚、幂等、上下线、共享端点、版本投影及 Agent 监控/只读配置摘要。SQLite 不验证 Oracle/PG 的行锁并发；另对两种生产方言编译查询并检查空间条件和锁后刷新选项，不把编译验证描述成生产并发验收。

test_agent_action_authorization_scope.py 覆盖范围切换、共享资源、失活关联、显式授权拒绝与原有执行门禁。test_agent_action_authorization_transactions.py 使用真实 Agent/Policy 仓储与内存事务，验证新版本收缩授权、旧版本快照不变、显式越界拒绝及提交失败后的完整回滚。
