# 统一资源监控绑定与硬件接入

日期：2026-11-05。KBot4 与 Ammolite 使用相同产品语义。

## 模型与边界

业务系统关联资源，资源关联监控源；数据库 Target 不再承担主机身份或主机监控绑定。
绑定统一存储在 KBot 的 `KBOT_OPS_RESOURCE_SOURCE_BINDING` /
Ammolite 的 `aiops_resource_source_binding` 中，不为每种资源创建一张绑定表。

| 对象 | 负责内容 |
| --- | --- |
| ManagedResource | 资源 ID、类型、名称、责任组、资产属性及生命周期 |
| BusinessSystemResource | 资源属于哪个业务系统、展示层和排序 |
| DatabaseResource / Target | 数据库连接、凭据、引擎版本及诊断和执行能力 |
| ResourceSourceBinding | resource_id、监控源、定位键及定位 JSON、状态、版本、优先级和查询预算 |
| ResourceRelation | 数据库运行于主机、使用存储、依赖网络设备等显式关系 |

统一绑定的物理外键只有资源和监控源，不再保存 target_id。数据库接口所需的
target_id 由 DatabaseResource 关系只读投影获得，不存在旧绑定表兼容或双写。

权限继续跟业务系统：有系统访问权限即可访问其关联的活跃资源，不增设数据库、主机、
网络设备的资源类型 ACL。Agent 仍必须受已授权系统、能力、执行策略及审批边界约束。
看到某个监控源中的候选，不代表它已加入业务系统或已获授权。
本轮支持硬件配置与实时监控，不新增硬件 SQL 诊断或受控执行工具。

## 配置流程

1. 在业务系统的“系统构成”中添加数据库、物理服务器、虚拟机、存储或网络设备。
2. 数据库只选数据库候选；物理服务器和虚拟机独立选择 Prometheus，再发现、选择主机候选。
3. 在硬件抽屉勾选其关联数据库，分别建立 RUNS_ON、USES_STORAGE 或 DEPENDS_ON。
4. 在拓扑确认中查看硬件节点及连线，再发布。修改配置沿用系统先下线的规则。

硬件新增、回显和修改共用同一字段模型。候选引用由服务端签发，限定 Domain/Tenant、
操作人、监控源及有效期；发布前刷新引用，服务端保存前再次从 Provider 验证。
变更已有绑定需提交绑定 ID 和版本。拒绝把同一个主机定位重复创建为两个资源。
本阶段界面不提供跨系统复用已有硬件资源，也不提供删除已有主机绑定的操作。

存储和网络设备目前支持资产及拓扑，不提供专用采集或虚假的健康状态。
不能把监控源连接成功、资源配置完成、系统上线解释为真实资源健康。

## 指标拆分与实时监控

数据库总览只包含 DATABASE 指标，不再复制 host 或基于主机推算的 runtime 指标。
主机资源使用独立 host-overview：CPU、内存、文件系统、磁盘 IO、网络吞吐。
Prometheus 主机查询只使用主机自身绑定的定位键，不读取数据库 locator 中的 host_target_key。
同一主机承载多个数据库只保留一份主机身份，通过多个运行于关系表达。

实时监控按资源类型加载相应 Profile，不为硬件伪造数据库引擎或 Target。
主机当前不显示数据库专用诊断入口及未实现的历史均值基线。
无采样明确展示缺口，不按零或健康处理。每次查询核对已上线系统内活跃资源归属，
查询返回前复核源配置、绑定版本及归属；已撤销的资源不能返回采集中结果。
主机视图遵守实例数、Series、面板和响应字节预算，不复用旧授权状态的缓存。
Agent 配置摘要统计全部资源的监控，只统计数据库的只读及变更能力。

## Schema 与交付范围

Oracle 规范 DDL、ORM、Manifest、重建与验证 SQL 已同步为资源绑定模型；
PostgreSQL 规范由当前 ORM 和初始化实体注册生成。公共合同与 OpenAPI 同步更新。
本轮只改代码及规范工件，不迁移、回填、重建或修改已有数据库，不部署、不重启服务。
旧库不能直接运行新代码；实际部署前须另行安排 Schema 切换。
历史升级文件不作为本轮迁移入口，生成的重建 SQL 也没有执行。

OEM 指标扩展、ODA/Exadata 专用采集及硬件诊断编排留到下一阶段。
