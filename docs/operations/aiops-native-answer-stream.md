# 诊断正文原生流式交付

SQL 交互诊断与普通诊断使用同一次模型调用，同时返回原始 Markdown 正文和结构化诊断字段。
正文不再由完整检查点拼接分析、方案模板后拆片播放；前端收到增量即显示，不增加逐字播放等待。

## 交付边界

- 结构化调用仍采用 JSON Mode。模型先返回 `answer_markdown` 字符串，再提供其余诊断字段。
- 发给模型的 JSON Schema 同步将正文字段排在首位，避免继承合同的字段顺序与正文优先指令冲突；
  只调整展示顺序，不改变正式合同的必填项和证据校验。
- 流式解码只转发该字段，支持任意 UTF-8 网络分片、转义和 SSE；不展示 JSON、推理字段或元数据。
- 生成期间显示“生成中 · 证据核验中”。最终仍须通过主体、引用、参数、目标和审批约束。
- 既有有限校正最多两次；每次重新生成先用 `answer.delta.payload.reset=true` 清除上次草稿。
- 生成或核验失败时撤回临时正文，沿用已核验观测的安全降级，不把失败解释为数据库故障或健康。
- 页面回读到终态时清除临时正文，重新加载正式结果；取消时回收后台生成任务。
- 检查点保存正文及已流式输出的运行标识。同运行回答复用正文，不再额外调用模型或重播；
  新运行复用历史检查点时仍向新运行交付正文。
- 最终 `MARKDOWN` 块标注 `raw_model_output=true`，前端不做字典替换、裁剪或删除引用段。
  Markdown 仍经过既有安全渲染，不允许执行 HTML 注入。
- 分析、方案使用透明无边框排版。取证、图表、计划材料、补证和审批控件保持原职责。
- 计划可用性保留为补充材料控件的元数据，不再作为分析后的独立通用回复。

模型输出限制继续由 Model Serving 配置决定；本修改不硬编码技术 token 上限，不放宽数据库取证或变更授权。
后台报告仍依据正式调查记录，不把临时流式草稿作为事实来源。

## 健康诊断的输入与执行预算

- 证据评估不再重复读取图表配置和完整时序采样；保留表格原始行、精确值、必要计算口径、
  采样窗口、来源、身份边界、分页与质量标记。完整样本仍保存在正式证据中供重放。
- 原生值换算的单位、种类及换算语义按列共享；每行仍保留原行号、精确值、质量和原生来源。
  原生 HTML 报告不送模型重新解释，仍通过报告附件交付。
- 不需要用户澄清时，`clarification_question` 可省略；`ASK_USER` / `NEEDS_CLARIFICATION`
  仍必须同时出现并提供非空问题，不放宽安全校验。
- `aiops_agent.diagnosis.evidence_assessment_budget_seconds` 默认 15 秒，只限制普通证据评估阶段；
  同时服从全流程剩余工作期限。评估超时沿用确定性证据状态，把剩余时间留给正式分析。
- `aiops_agent.diagnosis.answer_finalize_reserve_seconds` 默认 3 秒，最终模型请求提前结束，
  为撤回未核验草稿、整理已有事实及保存正式结果留出时间；必须小于 `answer_reserve_seconds`。
- 普通诊断超时或模型校验失败时，逐项保留采集时点、行数、统计口径、警告和明确缺口。
  全流程截止时另展示每项最多 10 行的原始数值预览，完整行仍保留在证据中。
  空结果、截断、历史观测和只读探测均明确说明，不生成未经核验的健康或故障结论。

完整诊断的可信功能入口及 SQL 选择采用独立的 `diagnosis.diagnostic_turn_budget_seconds`，
默认 240 秒；普通问答仍默认 90 秒，已有期限不续期。模型依赖超时和剩余总期限仍同时有效。
监控重复数值读取同一结果行，身份采样时间副本只提供数量与首末实际时点，不证明连续覆盖；
完整原始证据仍用于服务端核验。详细变更与离线规模数据见 `aiops-health-diagnosis-delivery.md`。
不改变模型技术输出限制，不需要 DDL 或 Prompt 数据同步。

## 发布注意

两个项目须同步发布后端与对应前端。Prompt 文件基线保持 `1.0.0`：
`aiops_agent.sql_diagnosis` 与 `aiops_agent.diagnosis_answer_compose`。

数据库 Prompt 同步须先核对环境、来源和内容 Hash，只更新文件基线；
不得覆盖网页手工维护的激活版本、重写冻结运行或执行全库初始化。
只更新前端样式不能消除后端等待完整生成的时间。此代码修改本身不表示已同步线上 Prompt 或完成部署。
