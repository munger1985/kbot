## 处理缺口与修复

原动态模型合同只完成 SQL 专项校验及记录草案转换，最终记录冻结仍在模型
成功回执之后执行。目标清单、授权父调查、观测参数值和截断边界等后置校验
一旦失败，就直接丢弃本轮诊断，未进入已有的有限格式修正流程。

- 生成阶段的同一动态输出合同现在执行完整记录冻结校验，复用原有最多两次
  模型请求及剩余截止预算，不新增外层重生成循环。
- 模型明确接收结构化目标和父调查边界；沿用 SQL 证据不等于获得修订旧记录的授权。
- 校验仍拒绝增删目标、越权修订、伪造观测参数和没有适用范围的截断事实。
- 修正仍失败时保留已核验证据和仍有效的旧检查点，不伪装为诊断完成。
- 日志补充结构化校验位置、类型与错误消息；Pydantic 错误不打印原始输入或异常上下文，
  非结构化异常只记录类型，模型服务异常不重复记录可能包含上游内容的明细。
