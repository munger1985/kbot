# AIOps 运维知识库对齐：阶段 1 配置与审批

记录日期：2026-11-20。范围见[实施计划](aiops-knowledge-alignment-implementation-plan.md)和[阶段 0 基线](aiops-knowledge-alignment-stage-0.md)。KBot4 与 Ammolite 同步实施；本阶段只验证本地源码和离线行为，不代表上线或真实环境验收。

## 已实现

1. **建库与编辑。** 名称、说明可编辑；只保留可选的标签识别模型。更新省略 `tagging_model_id` 保持绑定，`null` 显式清空，UUID 替换。仅改元数据不查模型目录或重建索引。新建和改名按同一规则去重：KBot4 锁 Oracle Domain 行，Ammolite 按 Domain 获取 PostgreSQL 事务锁。移除手册库旧 `/models` 接口、客户端和对应页面调用；诊断案例的独立模型治理不变。
2. **只读能力。** 页面按已装配的解析、投影和检索方案展示原生解析、OCR、视觉补强、词法及实际启用的语义方向。用当前库的有效版本、发布指针、解析状态和精确的活动代次区分索引为空、未就绪、部分就绪、就绪、异常。默认纯词法方案不要求向量；未装配 OCR 不声称可识别扫描正文。没有通道运行证据时只标「已配置待验证」，不拿模型目录或 READY 代次冒充在线检索验证。
3. **上传与审批。** 标签模型或词表缺失只提示，不阻断待审资料登记。上传登记在库行锁下复核状态、幂等以及解析、投影、检索和实际表示绑定的方案摘要。批准进入标签处理前核验模型、可解析的 Prompt 版本和有效词表；任一不可用时保持待审。审批与冻结规格一起提交，包含模型身份和目录摘要、Prompt 版本与内容摘要、词表、文档版本集合和处理方案。
4. **执行与模型保护。** 标签执行和重试继续使用冻结规格，拒绝旧规格下的方案漂移；接纳标签前检查业务版本、文档、解析运行及投影代次。模型引用保留实际标签绑定、待处理或可重试的标签任务、当前装配的表示空间、有效发布代次及独立案例配置，不将旧手册库表单角色当成有效引用。不回填旧任务，不自动改写或删除旧索引，也未新增代次迁移管理入口。

模型运行的边界：Prompt 按不可变版本解析；模型按执行前后目录快照比对，变化时不采纳结果。现有 Model Serving 调用不是按提供方不可变版本寻址；目录未反映的远端模型替换不能靠此机制证明，需在最终验收中核实运行回执和版本能力。

## 离线验证

- KBot4：定向 Python 回归 **100 通过、40 子测试通过**，另有 Node 上传前端合同通过。
- Ammolite：定向 Python 回归 **102 通过、36 子测试通过**。
- 两仓完整 OpenAPI 运行时快照校验通过；Chromium 加载两套真实 UI 资源、拦截并模拟所有业务接口，共 **12 项通过**。覆盖只读能力、仅改名称、显式清空、无标签模型建库及原有卡片操作。
- KBot4 全量静态页面合同另有 9 项未通过，涉及 Agent 模型目录、业务系统页面、巡检、导航与页面清单，不属于本阶段知识库合同；阶段 1 相关编辑器断言和上传合同已单独通过。

使用各仓对应 Conda 环境、仓内 `packages/*/src` 与 `services/*/src` 路径运行。定向 Python 覆盖手册 CRUD/审批与上传、库状态、预览边界、标签任务重试、方案或索引不兼容、模型保护、BFF、阶段 0 合同及全量 OpenAPI；SQL 只编译和模拟 Repository 结果，未连接数据库。浏览器测试：`apps/portal-web/tests/aiops-knowledge-base-cards.spec.mjs`。

## 最终真实验收（留到阶段 4）

- 在分别获授权的 Oracle、PostgreSQL 验收环境复核工作域名称锁、重复提交、并发改名/上传、事务回滚和幂等；验证登记失败只由原暂存回收机制处理。
- 用真实模型目录、租户授权、Prompt 和词表验证审批门禁、模型或配置变化后重试、旧任务处置；不自动补写缺失的冻结规格。
- 用获授权的原生中文手册、表格、扫描件和图文检查实际解析、OCR、词法和可用语义方向。以真实处理/检索证据核对 UI 状态，测试新表示空间投影失败时旧发布代次仍保留，并验证经批准的新代次切换。
- 与阶段 2 的主命中／关联证据／覆盖缺口和阶段 3 的库删除保护一起作真实端到端验收。上线前单独评审存量任务、历史代次、服务协同顺序和回滚条件。

本阶段未执行真实数据库、真实模型调用、真实文档质量或部署验收；未执行 DDL、数据迁移、部署、重启、提交或推送。
