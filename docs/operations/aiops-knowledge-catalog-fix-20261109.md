# AIOps 已发布资料目录修复

## 问题与行为

2026-11-09 的 Ammolite 在线日志确认：资料盘点先查询全文索引实体，因
aiops_knowledge_index.document_id 缺失而失败，并将数据库驱动错误和 SQL 展示到聊天界面。
资料目录不应依赖正文检索、解析代次或回答模型。

两平台统一以下行为：

- KNOWLEDGE_QA 的 CATALOG 模式列出当前授权来源中的运维资料与历史诊断案例：
  标题、类别、当前发布版本，以及来自发布资料 Profile 的可继续提问主题。
- REPORT_CASE_QUERY 的 CATALOG 模式仅列出已发布历史诊断案例，不返回普通报告。
- 目录使用独立资产／版本查询，保留 Domain、知识库、来源类型、安全级别、目标、
  标签与其他范围条件。案例继续验证原始来源、当前授权、效果及发布投影。
- 目录按资产标识分页，输出前复核当前授权和精确发布版本；撤权或退役结果不输出。
  超出扫描预算或展示数量时明确提示，不冒称目录完整。
- 目录不读取正文索引，也不调用正文检索或回答模型；发布案例的来源检查不加载索引实体。
- 查询失败与没有资料分别展示。未知内部异常只向用户提供稳定业务错误，
  不将 SQLAlchemy 错误编号、驱动文本、SQL 或参数写入公开失败消息；详细异常保留服务日志。

## 验证与发布边界

新增目录入口、混合来源、单一来源、主题展示、权限变化、精确版本复核、稳定分页、
预算及异常隔离回归；仓储查询分别以 PostgreSQL 和 Oracle 方言编译，
确认不依赖知识索引表并保留原范围条件。

本修复没有修改数据库模型、执行 AIOps DDL、迁移旧索引或恢复旧 KC 路径。
它解决资料目录错误依赖全文索引的问题，不代表全文问答所需的新存储及索引已完成线上发布。
仓库 Prompt 基线保持 1.0.0；本次未写入线上 Prompt，也未部署或重启线上服务。
