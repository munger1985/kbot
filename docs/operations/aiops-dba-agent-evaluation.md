# DBA Agent 三库场景评测

多轮收口补充验收：先收口较晚轮，再重新选择较早轮形成新收口，报告必须采用最新登记的收口。
使最新收口来源失效后，报告须明确缺口而不是回退旧收口。同一原调查的 c1 被后续反驳、
c2 仍有效时，新报告及其案例只纳入 c2；人工重新带回 c1 或改写 c2 必须被来源门禁拒绝。
跨 Target 切换后，环境标签更新且其他目标的人工动作、验证结果和来源引用不残留。

本说明对应统一 DBA 设计的 S6 发布门禁。评测工具并未在本批对生产环境运行。
本地测试、确定性规则得分和模型裁判得分都不能单独证明诊断有效。

## 环境与授权

分别为 Oracle、PostgreSQL、MySQL 准备已授权的 Agent 和业务资源，
按数据集的 fixture_requirements 由独立人员核验真实状态。
故障注入、DDL、终止会话、采集开关和恢复演练必须使用隔离或明确批准的环境。
工具本身只提交诊断问题；任何审批/执行事件都构成发布阻断。
需要来源的 SQL 续查、报告或效果场景须传入真实、同域可读的 source-run-id，
它是首轮 Turn 的来源，不是顶层会话参数。

公共路径存在平台差异，必须明确指定：

| 平台 | api-path-prefix |
| --- | --- |
| KBot4 | /api/v1/apps/aiops |
| Ammolite | /api/v1/apps/aiops/domains/实际业务域编码/ops |

API 鉴权由实际部署配置决定，密钥通过环境注入，不能写进命令示例、真值文件或日志。
API、裁判和日志端点应由运维确认，不能直接把数据集或模型返回的 URL 当作端点。

## 独立场景真值

多轮直接收口新增生产服务与两端浏览器回归。真实验收须核对默认同目标范围、
显式轮次子集、单轮部分 Claim 被反证后的保留/排除，以及跨 Target 不混合。
分别在预览后、模型扫描中、KC 受理后和审批中撤销权限或更换原件，
核对不会继续上传/审批、精确 Revision 仍被登记并进入撤回/对账流程。
人工恢复不成为 VERIFIED，人工失败经验保留回执和归因限制；高安全级材料不降级。
会话报告须登记每个关联 Run 的原件，不附加已失效收口或覆盖后续反证。
相同提交不重复上传；不同人工内容形成新候选；并发返回不同外部 Revision 时
不允许丢弃受理对象。本地仓储/KC/模型替身和片段浏览器测试不证明真实并发或外部撤回。

执行中围栏新增 test_aiops_execution_fence.py：使用正式合同和服务接线核验原签名 Grant、
Run/Task/Target/资源回执、复核不消费或刷新授权、执行前/中/后拒绝、控制面失联、
外部取消竞态和 Driver 吞取消。任何失败均不得返回成功或提前释放共享配额。
test_aiops_mysql_query_cancellation.py 核验保留原连接所有权、同 server_uuid 围栏、
只取消自身查询、命令及原查询双回执、权限/网络/身份未知、查询自然结束并发及取样间隔唤醒。
PG 取消应等待原后端协议关闭，Oracle 超时和取消均应发原连接取消请求；
请求发送不等于确认终止。上述仍是本地替身，不是三库真实取消或孤儿 SQL 清零验收。
真实验收必须从独立连接核对原查询结束、不误伤旁路业务查询，并覆盖控制面失联、
Worker/Executor 分进程、进程退出和重启；失败/未知不能发新租约冒充已终止。
取消后的持久化终止回执与两端运行详情已接通，见实施状态中的“只读查询终止回执持久化”。
真实三库的底层终止与回执一致性仍待验收，不用 Executor 日志代替最终业务证据。

Run 内人工等待新增 test_aiops_run_wait_budget.py，用正式 Runtime/仓储/ORM 合同接线验证：
并行 RUNNING/READY/RETRY_WAIT 不暂停整 Run，纯人工等待才冻结剩余毫秒；
多个请求混合审批/补证时部分处理不丢失其余等待，重放/重建 Runtime 不刷新预算。
批准续跑不消耗失败重试次数，Worker、Heartbeat、凭据/监控准入共用剩余 Task 期限；
补充调查的独立耗时上限同样扣除持久化的纯人工暂停量，不扣并行执行时间，不重发轮数预算。
批准/拒绝/答复/跳过/到期/取消和迟到成功的边界分别验证。首个人工请求的一天上限不可延后。
发布前仍须以真实持久化数据库验证多进程竞争、重启/断网、授权变化和远端查询终止；
替身回归、DDL 工件和只读 Schema 检查不等于升级已执行或取消已终止远端 SQL。

持久化未来观察新增本地冻结/运行内核/三库签名执行回归：
仅在有效成功基线后事务性创建后台组，available_at 持久化等待、每点不重试、
前点结束后保留最小间隔；领取和兑换凭据之间撤权必须阻断秘密读取与数据库查询。
错过时点、截断、重复请求、已知物理身份变化、源哈希变化均不能生成假完成。

## 命令

先校验场景集，不连接任何目标：

```bash
python tests/evaluation/evaluate_aiops_dba_chat.py --validate-only
```

运行前由安全配置注入 KBOT_AIOPS_EVAL_BASE_URL、KBOT_AIOPS_EVAL_API_KEY、
KBOT_AIOPS_EVAL_AGENT_ID、AIOPS_EVAL_RESOURCE_ID 以及裁判的
KBOT_AIOPS_EVAL_JUDGE_URL、KBOT_AIOPS_EVAL_JUDGE_KEY、KBOT_AIOPS_EVAL_JUDGE_MODEL。
这些是沿用现有评测器的变量名，两仓相同。

```bash
python tests/evaluation/evaluate_aiops_dba_chat.py \
  --database-type POSTGRESQL \
  --api-path-prefix /api/v1/apps/aiops/domains/demo/ops \
  --ground-truth-file /已授权目录/postgresql-fixtures.json \
  --source-run-id 实际来源Run标识 \
  --report /已授权目录/postgresql-evaluation.json
```

KBot 使用对应 App 前缀；其他引擎分别使用 ORACLE、MYSQL 和各自真实资源。
仅运行部分场景时用 --case 指定数据集 case_id，不能把部分场景通过当作整套验收。

默认不猜测另一平台或旧部署的端点。

## 通过标准与归档

记录每个场景的资源、数据库、独立真值、Turn/Run、引用、禁止行为和评审覆盖。
安全失败、越权、未请求的执行、累计冒充窗口、错误 VERIFIED、
缺语义评审和未评审能力不能被平均分抵消。
诊断总耗时与包含裁判的评测耗时分开；并发 P95、取消后的目标库活动和预算
须另做真实负载试验，不能从单次耗时或本地替身推断。
报告只输出安全错误类别，不复制服务器原始错误正文。
最终验收还需浏览器走通回答、方案、报告、案例审核与适用/不适用复用，
经另行授权的执行效果、护栏和回退另留独立实测证据。

## 业务效果、自动验证与案例发布专项

1. 三库分别在授权环境启用周期快照，先形成至少两个可比快照。
   PG 目标凭据必须能读取 pg_control_system()；缺权限应明确失败，不自动 GRANT。
   Oracle 使用平台周期快照，不伪装 AWR 或绕过 Pack 许可。
2. 在诊断 Proposal 中选择真实窗口基线，冻结主要效果、业务输入负载、护栏、
   稳定期、观察期和停止条件。执行或审批后不得改写成功条件。
   未启用采集时，默认自动验证应拒绝，而不是暗中开启采集；可显式选择手动验证。
3. 仅经授权执行动作并完成只读复核。自动验证应留下固定时间窗口的 SCHEDULED，
   到期后自动生成真实窗口报告、复算、正式报告和通知；重复投递不重复生成报告。
   累计最大值不做差；负载下降、所选 SQL 缺失或覆盖不足不能算优化。
4. 分别验证实例切换/重启、凭据或 Target 版本变化、来源撤权、漏采及计数重置。
   失败必须可回看，不把失败当空成功；无关 SQL 淘汰不阻断完整的目标 SQL 信号。
   观察性改善保持 LIMITED，不作为隔离因果证明。
5. 会话提炼、人工修订及报告提炼均应先规则脱敏，再进行已配置模型的语义扫描。
   未发布 aiops_agent.case_semantic_redaction、未配置 parser_llm、超时或非法片段时，
   不允许向 KC 索引发送正文。审核发布时重验扫描后内容哈希及来源。
   真实模型需要独立的敏感文本漏报/误报样本，不能以替身测试代替。
6. 正向 VERIFIED 案例仍需独立完整验收；人工回执、观察性改善、报告 READY 或
   不同的前后引用不能自行升级。来源撤回或权限失效须阻断新检索并保留治理审计。
7. 用真实冻结计划分别生成无改善、退化、护栏失败、负载不可比和动作复核缺口报告，
   包括 READY 与 PARTIAL。均可基于有效原调查提炼候选；前两类失败/不利记录用于反例，
   不可比和缺证仅作参考；不得为通过门禁而将 COMPARISON 改成 CHAT 或篡改原始结果。
   “未达到改善条件”不等于“完全无效”，实测退化不自动证明措施造成退化。
8. 人工回执后形成独立窗口测量：正文同时展示人工来源、实测值、护栏、归因和缺口，
   不把人工动作变成平台执行，也不把独立测量吞成只有“人工反馈”。
9. 对失败经验和诊断参考分别完成真实语义扫描、人工发布与检索；扫描/索引期间使
   原执行回执失效，检查阻断发送或精确撤回。发布后使权威执行状态、窗口或授权失效，
   新检索须停止读取正文，后台须产生复核审计和确切撤回任务，接收方 ACK 独立验收。

本地全结果服务链门禁为 `test_aiops_effect_case_outcomes.py`；包含实际生产方法与
替身依赖，不替代上述真实执行、模型质量、持久化数据库和外部系统验收。

## 正式报告、人工收口与处置状态专项

报告提炼案例的生产服务专项另见 `test_aiops_report_case_extraction.py`。
修订来源专项另见 `test_aiops_report_source_revision.py`。真实验收还须：只改标题或
展示模板时，已审核案例保持可用；改写原因/措施章节、证据、范围或安全级时，
旧案例停止参与新检索且生成精确撤回任务。连续两次展示修订后再实质更正，应影响
更早版本的案例；实质更正后再改回，不恢复已知错误知识。展示修订期间撤权仍须拒绝。
部署后还需真实执行以下链路，不能仅查看合同字段或候选创建成功：

- 普通报告与受控效果报告分别提炼；核对原 Claim/动作/验证来源。普通参考、
  人工恢复、失败经验与已验证措施分别显示，候选索引成功不等于人工发布。
- 报告来源损坏、撤权或后续明确反证时，资格预检和实际提炼均拒绝；
  已有案例幂等命中也不能跳过复核。扫描期间报告更正后，不向 KC 发送旧正文。
- KC 受理或审批期间撤权，检查版本停止参与新检索、精确撤回任务及接收方 ACK；
  仅有任务状态不能声称外部撤回完成。审批连接中断后，对账须复用原 Revision 恢复。
- 人工修订保留未改写动作的人工来源、登记引用、验证方式和限制；
  不通过正文修订、恢复勾选或不同前后引用升级 VERIFIED。
- 完成人工审核发布，再用相似和不相似问题检索复用；核对范围、版本、
  引用权限、撤回和案例不能成为本次独立现场证据的边界。

新增本地门禁 `test_aiops_report_lifecycle.py`，并覆盖既有报告发布、动作比较和业务效果报告。
这些测试使用正式调查/回答合同和生产发布方法，仓储与数据库依赖仍为替身。
以下必须由用户在真实部署环境逐项验收，不以本地 PDF 字节或静态渲染代替浏览器验收：

先完成实施文档中的报告来源主键无损升级（Ammolite 报告专用对齐、KBot4 Schema 53）。
同一 Run 的多份来源有 SQLite 实际落库回归，PG/Oracle 仍需真实部署验收。

1. 完成一个无需确认根因的事实查询，生成单轮及会话报告：报告可以 READY，逐目标为已回答，
   但不伪造故障、根因或业务恢复。再选择部分完成的调查，须明确 PARTIAL 和未完成目标。
2. 先生成报告，再人工登记处置和恢复反馈，不新增聊天轮次，重新生成必须形成新版本。
   人工动作出现在处置章节，不变成建议；反馈明确为人工来源，不能授予 VERIFIED 案例资格。
3. 相同来源与模板重复生成，报告 ID/版本不变；真实来源更正或模板内容变化应生成新版本。
   原报告仍使用其冻结模板。PG/MySQL 精确 SQL 报告查重与发布须采用同一实际模板。
4. 经独立授权执行动作，只确认动作后置条件而没有可比业务窗口时，报告须同时显示
   “动作已达到”和“业务效果无法判断”，不能写成业务已恢复。形成可比测量后，继续分别
   检查症状、护栏和归因；观察性改善不能伪装随机或隔离因果证明。
5. 来源撤权、原始引用失效或完整性不符后，重复生成不得复用旧报告绕过复核。
   Web/PDF/Markdown 的目标、处置、验证与限制一致；比较报告可追溯原执行回执及其 Run。

本专项不关闭案例语义脱敏、人工审核发布、真实 KC 撤回及后续复用的独立验收。

## Zabbix 长尾证据专项

有界续取专项入口：test_aiops_source_pagination.py。覆盖相同秒/纳秒多条记录、
精确首尾分数秒、原始大整数、脱敏后身份保留、响应变化及后页失败保留前页、
页数/行数/字节边界、取消传播、冻结预算复核、重复动作门禁，以及正式回答到
报告/案例的原始来源重放。两端执行过程区分数据库游标与来源原生续取。
真实 Zabbix/Loki 服务仍需按部署版本复核排序、边界、迟到数据、来源保留及重试；
分页耗尽不是一致快照或监控历史覆盖证明。无安全分页的来源目录不声称已遍历全量。

数值历史仍使用 metric.query_range；文本/日志另需来源和绑定的 item.history。
核对 Host、Item、原始类型、时间范围、行数与字节预算。超过结果上限必须标截断，
60 天请求不能因取回少量历史就声称完整覆盖；没有历史不自动改用趋势数据。
文本及日志只能作为数据，不能改变系统指令或授权。取证事实与外部源响应均应保留
原始哈希、版本、真实时间；不将日志等级、文本数字或存储类型误推成计数器。
