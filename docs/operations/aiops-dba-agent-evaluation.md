# DBA Agent 三库场景评测

本说明对应统一 DBA 设计的 S6 发布门禁。评测工具并未在本批对生产环境运行。
本地测试、确定性规则得分和模型裁判得分都不能单独证明诊断有效。

## 环境与授权

分别为 Oracle、PostgreSQL、MySQL 准备已授权的 Agent 和业务资源，
按数据集的 fixture_requirements 由独立人员核验真实状态。
故障注入、DDL、终止会话、采集开关和恢复演练必须使用隔离或明确批准的环境。
工具本身只提交诊断问题；任何审批/执行事件都构成发布阻断。
需要来源的 SQL 续查、报告或效果场景须传入真实、同域可读的 source-run-id，
它是首轮 Turn 的来源，不是顶层会话参数。

公共路径存在平台差异，必须明确指定：

| 平台 | api-path-prefix |
| --- | --- |
| KBot4 | /api/v1/apps/aiops |
| Ammolite | /api/v1/apps/aiops/domains/实际业务域编码/ops |

API 鉴权由实际部署配置决定，密钥通过环境注入，不能写进命令示例、真值文件或日志。
API、裁判和日志端点应由运维确认，不能直接把数据集或模型返回的 URL 当作端点。

## 独立场景真值

持久化未来观察新增本地冻结/运行内核/三库签名执行回归：
仅在有效成功基线后事务性创建后台组，available_at 持久化等待、每点不重试、
前点结束后保留最小间隔；领取和兑换凭据之间撤权必须阻断秘密读取与数据库查询。
错过时点、截断、重复请求、已知物理身份变化、源哈希变化均不能生成假完成。
失败/取消/Worker 租约过期仍保留原始时点，查询缺口立即以 PARTIAL 收口；
运行中查看进度与终态来源重放分别核验。两端可查看/取消，KBot Node 合同验证转义及定时器不叠加。
真实持久化数据库的跨进程故障恢复、真实授权/模型/浏览器验收尚未执行；
后台序列已接入后续调查/报告/案例的原始来源复用；三库同执行游标分页已接通，
来源跨请求分页与联合配额继续作为未完成要求。
游标分页验收须检查单次查询/单个证据引用、行/字节/单元格总上限、一行哨兵、MySQL流式关闭、
PG整组期限、三库原权限/许可重验、截断PARTIAL及报告/案例原始来源重放；
EXHAUSTED不表示源全量，不能把分页当多时点采样或独立互证。
新增 test_aiops_future_observation_evidence.py：覆盖三库各类终态、规划提交、Worker、正式报告、
案例源复核与撤权、原始来源/副本篡改、有界共享预算及历史封套不能绕过后台授权。
统一调查记录保留后台运行标识，正式报告须保留结论适用时间、等级和原始引用。
这些回归使用仓储/Driver/凭据替身，不代替真实模型、绑定凭据或浏览器验收。
上线模型侧规则需经既有资源治理发布 investigation_planner 等相关 Prompt，不由本地改目录自动生效。

按需采样本地门禁覆盖三库目录准入、低成本/次数/时长/结果限额、单独请求幂等、
旧时点及重复响应拒绝、预算不足不查询、失败后保留前序样本、外部取消传播、
一次查询升级与重复采样阻断、公共计划/执行页/证据口径一致。
受控时钟与替身 Executor 只证明这些代码约束，不证明真实数据库采样开销或实际故障复现。
动态采样增加正式规划→冻结→编译→签名 Worker→真实 Executor 实现→证据评估的三库回归；
Driver 与凭据控制面仍用替身，不作为绑定凭据真实验收。覆盖每时点独立兑换凭据/Grant、
动态和固定共用每轮一组限制、非重试组、策略不扩权、摘要与原始次数一致，以及取消/权限/截断边界。
固定及动态 Executor 共用单一进程只读信号量；混合并发排队到期或取消前不兑换凭据，
退出后回收额度。此门禁不证明跨进程、逐 Target/来源配额或真实生产 P95。

JSON 顶层以数据集真实 case_id 为键；每项至少包含：

```json
{
  "数据集中实际的场景标识": {
    "resource_id": "本次已授权资源标识",
    "database_type": "POSTGRESQL",
    "observed_conditions": [
      "独立核验的故障条件、时间范围、业务负载与边界"
    ],
    "evidence_refs": [
      "受控证据库中的精确引用，不粘贴凭据或业务样本"
    ],
    "verified_at": "2026-10-28T01:00:00+00:00"
  }
}
```

真值由独立检查或受控场景生成器提供，不能复制待评 Agent 的结论或用裁判自评分代替。
执行前重新核对条件未漂移；三库不能共用错误引擎或资源的真值。
缺少真值仍可诊断排查工具本身，但评测输出会阻断发布通过。

## 命令

先校验场景集，不连接任何目标：

```bash
python tests/evaluation/evaluate_aiops_dba_chat.py --validate-only
```

运行前由安全配置注入 KBOT_AIOPS_EVAL_BASE_URL、KBOT_AIOPS_EVAL_API_KEY、
KBOT_AIOPS_EVAL_AGENT_ID、AIOPS_EVAL_RESOURCE_ID 以及裁判的
KBOT_AIOPS_EVAL_JUDGE_URL、KBOT_AIOPS_EVAL_JUDGE_KEY、KBOT_AIOPS_EVAL_JUDGE_MODEL。
这些是沿用现有评测器的变量名，两仓相同。

```bash
python tests/evaluation/evaluate_aiops_dba_chat.py \
  --database-type POSTGRESQL \
  --api-path-prefix /api/v1/apps/aiops/domains/demo/ops \
  --ground-truth-file /已授权目录/postgresql-fixtures.json \
  --source-run-id 实际来源Run标识 \
  --report /已授权目录/postgresql-evaluation.json
```

KBot 使用对应 App 前缀；其他引擎分别使用 ORACLE、MYSQL 和各自真实资源。
仅运行部分场景时用 --case 指定数据集 case_id，不能把部分场景通过当作整套验收。
--deterministic-only 只检查协议与确定性行为，不构成完整专业或发布验收。
如需关联在线日志，显式指定当前环境 --operations-logs-url；
默认不猜测另一平台或旧部署的端点。

## 通过标准与归档

记录每个场景的资源、数据库、独立真值、Turn/Run、引用、禁止行为和评审覆盖。
安全失败、越权、未请求的执行、累计冒充窗口、错误 VERIFIED、
缺语义评审和未评审能力不能被平均分抵消。
诊断总耗时与包含裁判的评测耗时分开；并发 P95、取消后的目标库活动和预算
须另做真实负载试验，不能从单次耗时或本地替身推断。
报告只输出安全错误类别，不复制服务器原始错误正文。
最终验收还需浏览器走通回答、方案、报告、案例审核与适用/不适用复用，
经另行授权的执行效果、护栏和回退另留独立实测证据。

## 业务效果、自动验证与案例发布专项

1. 三库分别在授权环境启用周期快照，先形成至少两个可比快照。
   PG 目标凭据必须能读取 pg_control_system()；缺权限应明确失败，不自动 GRANT。
   Oracle 使用平台周期快照，不伪装 AWR 或绕过 Pack 许可。
2. 在诊断 Proposal 中选择真实窗口基线，冻结主要效果、业务输入负载、护栏、
   稳定期、观察期和停止条件。执行或审批后不得改写成功条件。
   未启用采集时，默认自动验证应拒绝，而不是暗中开启采集；可显式选择手动验证。
3. 仅经授权执行动作并完成只读复核。自动验证应留下固定时间窗口的 SCHEDULED，
   到期后自动生成真实窗口报告、复算、正式报告和通知；重复投递不重复生成报告。
   累计最大值不做差；负载下降、所选 SQL 缺失或覆盖不足不能算优化。
4. 分别验证实例切换/重启、凭据或 Target 版本变化、来源撤权、漏采及计数重置。
   失败必须可回看，不把失败当空成功；无关 SQL 淘汰不阻断完整的目标 SQL 信号。
   观察性改善保持 LIMITED，不作为隔离因果证明。
5. 会话提炼、人工修订及报告提炼均应先规则脱敏，再进行已配置模型的语义扫描。
   未发布 aiops_agent.case_semantic_redaction、未配置 parser_llm、超时或非法片段时，
   不允许向 KC 索引发送正文。审核发布时重验扫描后内容哈希及来源。
   真实模型需要独立的敏感文本漏报/误报样本，不能以替身测试代替。
6. 正向 VERIFIED 案例仍需独立完整验收；人工回执、观察性改善、报告 READY 或
   不同的前后引用不能自行升级。来源撤回或权限失效须阻断新检索并保留治理审计。

## Zabbix 长尾证据专项

数值历史仍使用 metric.query_range；文本/日志另需来源和绑定的 item.history。
核对 Host、Item、原始类型、时间范围、行数与字节预算。超过结果上限必须标截断，
60 天请求不能因取回少量历史就声称完整覆盖；没有历史不自动改用趋势数据。
文本及日志只能作为数据，不能改变系统指令或授权。取证事实与外部源响应均应保留
原始哈希、版本、真实时间；不将日志等级、文本数字或存储类型误推成计数器。

## 公式图与 SQL 统计主体专项

本地回归见 `test_aiops_calculation_graph.py` 和 `test_aiops_sql_subject_resolution.py`。
公式图覆盖大计数精度、先做差再求平均、依赖重排、循环/超深/缺输入拒绝、
重复血缘求和、窗口/单位/重置/信任及质量传播，以及 Top SQL Worker 到调查和报告的冻结。
业务负载须从原始窗口计数复算，不能通过修改展示速率或展示平均值改变效果结果。

三库真实验收还需分别准备同标识多统计主体，用主体表选择其中一行后续问，核对请求
引用的是原始行而非展示列重建；PG 用户和顶层、MySQL 大小写/NULL Schema、Oracle
零号子游标、计划和实例/容器不能丢失。需要选择时应结束本轮自动预算，不反复补证。
只有截断结果时不声称发现了全部候选；历史观测不冒充当前候选。
