# 数据库能力与业务系统混合资源

日期：2026-11-06。

## MES Top SQL 规划失败

线上 08:18:32 的 Turn 在能力兼容性校验处失败，尚未执行目标库查询。
只读核对确认，MES 业务系统包含 PostgreSQL 数据库和虚拟机。
原校验遍历所有系统资源，把虚拟机缺少的数据库类型转换为空字符串，
随后误判 Top SQL 能力不支持该资源。该错误不是 PostgreSQL 不支持 Top SQL。

## 修复边界

- 数据库能力兼容性只检查 `resource_type_key=DATABASE` 的资源。
- 主机、虚拟机及其他非数据库资源仍保留在公开范围和内部资源目录中，
  不删除拓扑上下文，不扩大 Agent 授权，也不为其创建数据库诊断任务。
- 数据库类型缺失或不受能力支持时仍拒绝，不将空类型视为通配符。
- 校验集中在已解析范围的执行路由，首次规划和用户澄清恢复使用同一规则。
- 本修复不改变 Top N 参数、结果排序、数据采集、Prompt 或数据库 Schema。

## 回归与上线

聚焦测试位于 `tests/unit/aiops_agent/test_aiops_turn_application.py`：
覆盖 PostgreSQL/MySQL/Oracle 与多种非数据库资源的混合系统、
“MES系统top5 sql”的条数参数冻结、只向数据库创建 Run、
不兼容及未知数据库类型拒绝，以及澄清恢复的相同校验。

代码部署并重启受影响的 AIOps Worker 后，重新提问创建新轮次。
