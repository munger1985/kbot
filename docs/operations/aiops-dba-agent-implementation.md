## 2026-10-28 三库视图及同义词的原生依赖取证

新增固定版本工具 db.sql.object_dependencies，必须提供精确 Schema/对象名；
默认40行、最多200行、256 KiB、10秒，使用现有签名 Grant、当前凭据、共享准入、
持续执行围栏和取消链，不提供任意 SQL 或新权限。工具卡及单 SQL 候选集合均已接入，
可按问题需要对已核实的下一对象继续取证，不要求每次诊断都展开全部对象。
目录合同显式区分 TOP_N 与 BOUNDED_ENUMERATION；本工具采用后者。
Executor 在达到请求或默认 limit 时保守标明可能截断及 ENUMERATION_LIMIT_REACHED，
不声称一定还有记录，也不把未读取额外行当作枚举完成；不改变 Top N 排名的请求语义。

PG 读取 pg_rewrite/pg_depend 中视图与物化视图的本地直接依赖；
MySQL 读取 VIEW_TABLE_USAGE（该目录要求 MySQL 8.0.13+），缺目录或权限时保留缺口；
Oracle 读取 ALL_DEPENDENCIES 的视图依赖及 ALL_SYNONYMS 的精确同义词引用，
不猜默认 Schema/PUBLIC 名称解析顺序。远端引用仅标识 REMOTE，不输出 DB Link 地址或跨库追查。
不读取业务行，不执行视图、用户 SQL、EXPLAIN 或配置变更。

SQL_OBJECT_GRAPH.v1 新增原生视图依赖、同义词引用及目录名称匹配关系。
源与目标按字段端点区分，不能因为共用目录行而串接错误对象；
仅保留指定 SQL 可达分量，循环去重，最多四层依赖、128条关系，
超过深度、行数、字节或关系预算显式截断。每一跳都核对原语句观测的
物理范围、时间及可得启动代次，不能通过连续近时点中转扩大时间覆盖。
依赖目标可接入既有表、分区和索引目录，但名称匹配不保证 DDL 期间对象不变，
也不证明运行时扫描、视图内联、物化刷新或单 SQL 根因。

关系随回答调查冻结，报告和案例重新计算，再回查同 Run 原始工具 Artifact；
目录行、图、身份、来源信任或 Run 被篡改不能通过。缺权限、缺记录、缺身份及
零行不作为“没有依赖/没有访问”的证据；PG 固定系统对象的依赖可能不记入 pg_depend，
静态目录也不能还原 PL/SQL 动态 SQL、运行时生成对象或代表绑定参数。

## 2026-10-28 只读查询终止回执持久化及两端运行详情

继续第⑥项，新增内部 `readonly-executions:report-termination`，独立
`aiops.readonly.report` 服务作用域；原租约的随机秘密及期限证明只允许追加
生命周期记录，不构成执行授权，不接受调用方自报 Run/Task/Target。
控制面先查原租约定位 Run，再按 Run→Lease 锁序重新核验来源、目标、令牌哈希及期限，
并核对固定诊断或按需调查冻结的数据库类型。允许取消/过期后的迟到回执，
不恢复任务、不延长预算、不兑换凭据、不修改租约释放状态。

每租约一份不可变 `DBA_READONLY_TERMINATION.v1` Artifact 及 USER 事件，同事务提交；
相同内容幂等，冲突内容拒绝。记录不含 SQL、凭据、连接号、原始 token 或 DSN。
信任级别为 SYSTEM，来源标记 EXECUTOR_REPORTED，类型为 EXECUTION_LIFECYCLE，
不能冒充 SOURCE_VERIFIED SQL 根因证据或已验证成功案例。

Driver 采用请求隔离的上下文收集器；MySQL 自有子任务继承同一次收集器，
不同请求不串回执。执行端在清理后有界回传，同内容可重试一次，不重试数据库取消。
Oracle cancel 只记“已请求”；PG 已断开的连接不能产生新的协议关闭确认；
MySQL 仍要求同实例、自有连接、取消命令回执及原查询结束。
原取消/异常不会因回传失败改为成功，取消路径不提前归还配额。

控制面以既有持久化租约为底账；回传未到达、Executor 崩溃或网络失联时，
终态/到期的未释放租约显示“终止状态未知”，绝不因额度到期回收而宣称查询已停止。
这不是执行端离线可靠队列，不能保证故障时观察回执必然送达；缺失保持未知，
真实多进程回传丢失/恢复验收仍属第⑥项。

运行详情在原有 Domain 校验后有界读取最近50条数据库租约及回执，
明确标示截断；不会把秘密回执放入公共响应。Ammolite Portal 与 KBot 运行详情
均区分租约有效、连接已清理、取消已请求、协议确认及未知，终态有迟到回执时
最多自动刷新3次，并保留手动刷新。该状态不混入诊断结果和报告。

## 2026-10-28 执行中持续授权围栏与自有查询取消

本增量继续第⑥项，不将停止 Worker 的 HTTP 请求等同于数据库端已停止查询。

- 控制面新增内部 readonly-executions:check，要求独立 aiops.readonly.check 服务作用域，
  请求只有原签名 Grant 和资源回执；不接受调用方自报 Run/Task/Target 身份。
  固定与动态只读 Grant 均严格验签及检查 audience/期限，不能使用变更 Grant。
- 凭据签发与执行中复核共用同一个持久化授权检查：Run→Task→Target 固定锁序，

## 2026-10-28 三库受控动态查询的有界游标分页

  新案例、人工修订及报告提炼均在索引前执行规则和语义扫描，失败不入索引。
  保存模型/Prompt 与输入输出哈希；发布重验正文哈希，仍需人工审核。
  正向 VERIFIED 候选生产链见后文；真实语义模型及发布/复用质量验收未完成。
- S6：执行两仓本地回归、跨仓语义、架构、OpenAPI 与前端构建。
  沿用现有 DBA 评测器扩展为 28 个场景（Oracle 16、PG/MySQL 各 13 个适用项，含共享场景），
  使用现行 resource context，不再把 Target ID 作为公共会话参数；分别运行三库，不混跑错误引擎场景。
  安全失败、禁止行为和未评审能力一票否决；缺语义评审或独立场景真值时阻断发布通过。
  独立真值由隔离/已批准环境核验，包含资源、引擎、条件、证据引用和核验时间，不能以模型自评分代替。
  真实数据库/模型/浏览器、经批准处置后的效果、并发 P95 和故障注入未执行，
  不以替身测试或构建通过冒充上线验收。
  评测请求按现行 ConversationStart 嵌套合同构造，使用实际公共路径前缀；
  Ammolite 的域级 ops 路径和 KBot App 路径分别验证，不用同一硬编码 URL。
  固定目录/动态查询执行器的排队、凭据与执行共享 Grant 绝对期限，
  Grant 同时不超过 Run deadline；到期等待者不领取凭据、不进入 Driver，
  即使 Driver 吞取消并迟到返回也不采纳结果。外部取消原样传播，
  PostgreSQL 显式管理只读事务，取消立即 terminate，不等待上下文自动回滚；
  Oracle 失败/取消不再次等待回滚，调用 cancel 后关闭独占连接，
  正常回滚及断开各有 1 秒清理宽限。清理失败不会产生成功的效果证明。
  此项是本地回归，不等于已完成三库生产取消/并发验收或证明取消后远端立即无活动。

## 已接通的业务链路

| 环节 | 本批代码行为 | 仍需注意 |
| --- | --- | --- |
| 普通诊断 | 模型提交严格 Claim：对象、时间、事实/解释/原因、支持/反证字段、替代解释与限制；服务端校验行/字段和信任 | 引用有效不等于自动证明因果；尚无通用身份关联和时间适配引擎 |
| SQL 诊断 | 先执行原 SQL 专项身份与证据校验，再投影为同一调查记录 | 非直接事实保守保留为解释，不从自由正文猜出“已确认原因” |
| 回答 | 先校验、冻结，再确定性渲染与推送正文；模型失败保留证据并输出部分结论 | 直接 Top N 仍用确定性列表，不被历史单 SQL 问题劫持；专项降级画像未冒充完成诊断 |
| 报告 | 从冻结记录无损投影分析、方案及引用；旧正文原样保留，不反向制造 Claim；空正文/缺引用不默认为 READY | 多轮按时间保留；没有修订关联时不取历史最高等级拼成根因 |
| 会话案例候选 | 最新结构化调查中有可追溯有效事实或支持判断即可提炼诊断参考，不再要求 CONFIRMED 或先有正式报告 | 校验记录与 Run/Target 一致；最新记录撤回、仅假设或缺失时不倒查旧肯定结论 |
| 人工收口与报告提炼 | 人工材料仍是 USER_PROVIDED/USER_REPORTED；READY、恢复勾选、不同前后引用不能自动产生 VERIFIED | 新效果报告可追溯且可复算，LIMITED 归因不自动授予正向 VERIFIED 用途 |
| 权限与支持强度 | 配置只读通道不再推定 Oracle 任意字典权限、PG/MySQL 视图或变更能力；模型 DIRECT 与来源数量不自动确认根因 | 只读目录允许 UNKNOWN 访问候选；商业许可硬门禁不变，实际访问由目标库反馈 |
| 指标发现 | `monitor.discover_metrics` 从规划、冻结、任务到 Prometheus Adapter、证据和后续规划接通 | 只有显式授权的绑定可用；不是开放全局指标目录 |

## 指标目录发现的启用与限制

Prometheus Adapter 新增 `metric.discover`。管理员须按既有诊断源/绑定治理流程，
在来源 `declared_capabilities` 声明该能力，并在目标绑定
`capability_scope.capabilities` 中显式限定授权；
本批不自动修改旧配置，也不暗示“升级后所有绑定自动启用”。
它与 `metric.query_range` 是不同能力；后续数值查询仍需已有查询授权。

定位只来自已冻结绑定，不接受模型指定 URL、任意 selector 或其他 Target。
数据库范围使用精确的 instance/target_key 定位；主机范围只使用已绑定 host_target_key。
返回指标名与标签名，不返回标签值；通过目标限定 targets/metadata 读取类型/help/单位，
不可核验或冲突时保持 UNKNOWN/CONFLICT，不猜单位。

每轮最多一个发现动作，各授权绑定独立限额；窗口 60–3600 秒、默认 900 秒；
默认 50、最多 100 个指标，
处理最多 1000 条系列、每指标最多 128 个标签名；生产执行响应默认上限 256 KiB。
达到目录上限或源警告标截断；字节超限、无权限或来源失败形成缺口，不当空成功。
目录证明请求窗口曾可见，不证明当前有采样，更不是性能数值。

## 业务效果验证操作与来源要求

当前诊断结果中的 Proposal 卡片展开“业务效果验证”（需管理变更权限且为原调查操作者）。
先从平台已采集的周期快照生成当前 Target 的窗口报告，选择真实基线和可得指标，
至少配置主要效果、护栏、负载可比性及停止条件，再冻结计划。
只能在审批或执行前冻结，之后不能通过改条件把失败改成成功。
默认勾选自动验证时，必须已有启用的周期快照；动作复核完成后后台等待观察窗口，
自动生成报告。也可在冻结前选择手动验证，之后选择新的窗口报告和该 Proposal 的
动作只读复核，点击复算并查看正式报告。复核来自独立验证 Run，而非只查原诊断 Run。
原生指标按指标族、代码、维度及核验单位区分；指定 SQL 保留库、用户、顶层及可得计划身份，
不把同一 query_id/SQL_ID 的不同统计主体混为一条。

该入口不会执行变更，不安装扩展、不授予目标库权限，也不自动开启采集。
  自动任务状态与错误类别在同一入口回看；无额外接口或新表。
动作复核沿用 `action-effect.v1`；业务效果使用严格的冻结合同及 `business-effect.v1`，
不能混用、追加任意字段或事后调整条件。
Oracle 的工作负载/差异报告明确为平台周期快照（非 AWR），未增加 Oracle 活动报告或冒充 ASH。
PostgreSQL 新增只读 `db.postgresql.workload.identity`，使用本轮 pg_control_system()
system_identifier、数据库 OID 与 pg_postmaster_start_time() 核验身份。
目标凭据缺相应权限时记录明确缺口，不回退旧能力探测值，不自动 GRANT。
MySQL 同样只使用本轮 server_uuid/Uptime；实例、重置/淘汰、版本和单位变化、
失败/漏采快照均不得被串接成成功窗口。没有已采集历史就不能生成过去的窗口。

效果、症状、护栏与归因分别保存。业务量下降、缺失 SQL、窗口不完整不能当作优化；
逐 SQL/负载/原生指标保存有效覆盖时间，采样时长用 Decimal 累加。
所选信号缺少任一时段阻断比较；无关 SQL 淘汰或指标缺样本不抹去完整信号。
来源绑定未变但 Agent 当前已移除该来源权限时，同样拒绝复用旧证据。
已观测到 ADVERSE 或护栏退化不能被其他缺口覆盖。
人工执行回执保留 USER_PROVIDED，即使后续指标由系统读取也不变成 Agent 自动执行。
观察性结果最多为 LIMITED 归因，仍不能直接发布 VERIFIED_* 成功案例。
正式报告保存计划、基线、之后窗口、复核、回执、比较结果六类来源、冻结模板及可读数值，
复算可重复进行但不覆盖历史报告；读取和重放都重验授权与哈希。
同 Target 的本人窗口报告可跨 Agent 复用，但必须重验 Target 版本及当前 Agent 权限；
其他诊断证据仍按原 Agent/Run 边界，不扩大机器主体的 Agent 白名单。

## 本轮按需短时采样入口与边界

规划器可以在声明 sampling_policy 的固定或三库受控动态数据库工具上设置 sampling，明确证据需求和判断作用。
同轮最多一组、2–4 次；前次完成后至少等待 2–10 秒，每次收紧为 5 秒、200 行、128 KiB，
整组最多 60 秒且不超过任务租约与 Run 期限。每次请求单独幂等，整组不自动重试。
单次失败/截断、重复请求、无效采集时间或预算不足即停止，已完成的原始证据不会被最后缺口覆盖。
执行计划与两端页面展示次数和间隔，完成事件及每条证据保留实际完成数和历史窗口边界；
后续调查和正式报告沿用这些观测，不把多个同源采样当成独立互证。
一次查询可升级为一组采样；已经调度的采样不能通过改次数/间隔绕过跨轮防重复。
本能力不启用周期采集、不写目标库、不生成过去窗口，
也不自动把原始累计值当增量。效果自动报告的数据源仍是已启用的周期快照。
三库动态采样沿用原 AST、对象/函数及许可策略；不接纳 EXPLAIN 语句或需要审批的查询。
固定和动态共用采样执行器与整轮一组上限，每个时点独立签名、请求幂等、当前凭据兑换；
身份不匹配、旧时间、重复请求、权限变化、截断或预算不足即停止。正式结果重放验证摘要、
原始观测次数和状态一致，不能将部分完成包装成成功。此增量不关闭第⑤项剩余范围。
Executor 启动时将同一个只读信号量注入固定与动态服务，普通查询、每次采样及后台调用
不再分别占满 readonly_concurrency；排队仍受 Grant 绝对期限约束，排队到期/取消不领凭据。

## 只读查询访问观测与短期拒绝缓存

## SQL 与表、分区、索引及计划对象的可重放关系

新增内部 SQL_OBJECT_GRAPH.v1，先沿本轮统计主体消歧，再从可信 SQL 文本的 AST
提取显式 Schema/表名，连接已核验物理数据库范围内的原生对象目录。

MySQL 保留 server_uuid，Schema 名称不在未知大小写规则下自行折叠；
Oracle 保留 DBID/容器，Root 的 GV$SQL 缺 CON_ID 时不假定游标来自当前容器。
对象名遵循 PG/Oracle 引号语义；不猜 search_path、默认 Schema 或截断 SQL 的余文。
不同启动代次、超过五分钟、历史材料、用户材料和身份未知的观测不拼接为关系。

分区，根名称冲突或根行缺失不猜归属。只保留指定 SQL 可达的对象分量，
