## 本批分阶段结果（代码与真实验收分开）

- S1：同会话重新授权父版本；逐目标完成状态；跨多轮以 Artifact + claim_id
  追踪有效判断、反驳和替代，回答/报告共享冻结记录。最多重验 16 个历史 Artifact、
  128 条历史判断，超出不隐式继承；新时点不能自动驳回不同阶段的旧事实。
- S2：精确整数/Decimal 传输与有界高精度计算，保存公式、输入、单位和质量。
  最大值/分位数不相减；缺失不补零；重置、身份、版本或单位变化拒绝差分。
  窗口平均耗时使用总耗时/执行次数。未知原生计数器映射仍保守合组，
  `NATIVE_ORIGIN_COARSE` 不是已完成计数器级血缘。
  监控采样和摘要同样保留高精度十进制值，按时间取最新采样；多系列同一时点相互矛盾时
  不任取一个值充当 last。执行器的采集开始时间不包含信号量排队等待。
- S3：Prometheus 目标限定 series + targets/metadata；元数据越界整批拒绝，冲突保留未知。
  Zabbix 真实 host.get/item.get/history.get 已从规划、冻结、Worker 接入后续诊断证据，
  长尾 Item 不要求新增 Profile；存储数值类型不推定 counter/gauge。
  原生历史窗口支持最多 60 天，仍限定最多 1000 条和响应字节，不自动替换成 trend 聚合。
  文本/日志 Item 额外要求来源和绑定显式授权 `item.history`；只授予数值权限不会扩大为日志读取。
  日志保留时间、来源、等级和事件号；证据投影保留样本类型，不能把文本当数值计算。
  响应流读取途中执行字节限制，连接探测 5 分钟后不再作为当前可用保证。
  探测发现能力不扩大配置授权；历史复用重验绑定版本、来源配置和当前 Agent 范围。
- S4：统一记录产生 Oracle/PG/MySQL 环境化处置审阅稿，参数逐字段核验，
  未知参数阻断、SQL 草案不授予执行权。修正“动作后置条件满足 = 业务恢复”的旧映射。
  Workload 对比核对实例身份/启动代次/来源版本，不同长度窗口比较每秒负载和每次代价，
  不直接比较总量。新增入口以真实窗口报告复算冻结的业务负载、主要效果和护栏，
  生成带版本与完整来源的正式报告，报告可从结果入口回看并沿用站内通知和 Outbox；
  现在可在执行前冻结自动验证；动作只读复核完成后，经事务 Outbox 等待稳定期和
  观察窗口，读取已启用周期采集形成的新窗口、复算并发布报告。
  窗口预留采集对齐余量和入库宽限，实际覆盖不足仍失败；不启用采集、不变更目标库。
  自动任务幂等、有限重试、失败可回看；不会将排队或投递成功当作验证成功。
  对照归因与生产实测未完成。
- S5：诊断参考、已验证解决、已验证优化、失败经验四种用途；人工收口不升级信任。
  案例入索引前脱敏，发布需人工审阅；已验证用途必须再次核验受控比较及执行来源，
  不能只信任 profile 标记。发布和检索重验来源，KC 返回正文后再核对发布状态、版本与权限。
  同会话后续明确反驳/替代会阻断受影响案例的新检索，不改写历史产物。
  后台每次复核一个已发布案例，5 分钟检查间隔、按最久未检查轮转；这个间隔不是
  全局完成时延承诺，来源/反证在读路径上仍立即重验。失效版本回到 REVIEW_REQUIRED，
  清除发布指针，并原子留下 SOURCE_INVALIDATED 审计；能够定位来源 Run 时通知原维护人，
  通知不含已撤权正文。没有可定位 Run 时仍暂停并留审计，不伪造通知成功。
  两端案例详情新增复用反馈：精确版本、适用性、检查价值、报告的措施效果、可选本人 Run；
  反馈幂等、脱敏、标记 USER_PROVIDED/USER_REPORTED，不改发布状态或验证等级。
  新案例、人工修订及报告提炼均在索引前执行规则和语义扫描，失败不入索引。
  保存模型/Prompt 与输入输出哈希；发布重验正文哈希，仍需人工审核。
  正向 VERIFIED 案例链及真实语义模型质量验收未完成。
- S6：执行两仓本地回归、跨仓语义、架构、OpenAPI 与前端构建。
  沿用现有 DBA 评测器扩展为 28 个场景（Oracle 16、PG/MySQL 各 13 个适用项，含共享场景），
  使用现行 resource context，不再把 Target ID 作为公共会话参数；分别运行三库，不混跑错误引擎场景。
  安全失败、禁止行为和未评审能力一票否决；缺语义评审或独立场景真值时阻断发布通过。
  独立真值由隔离/已批准环境核验，包含资源、引擎、条件、证据引用和核验时间，不能以模型自评分代替。
  真实数据库/模型/浏览器、经批准处置后的效果、并发 P95 和故障注入未执行，
  不以替身测试或构建通过冒充上线验收。
  评测请求按现行 ConversationStart 嵌套合同构造，使用实际公共路径前缀；
  Ammolite 的域级 ops 路径和 KBot App 路径分别验证，不用同一硬编码 URL。
  固定目录/动态查询执行器的排队、凭据与执行共享 Grant 绝对期限，
  Grant 同时不超过 Run deadline；到期等待者不领取凭据、不进入 Driver，
  即使 Driver 吞取消并迟到返回也不采纳结果。外部取消原样传播，
  PostgreSQL 显式管理只读事务，取消立即 terminate，不等待上下文自动回滚；
  Oracle 失败/取消不再次等待回滚，调用 cancel 后关闭独占连接，
  正常回滚及断开各有 1 秒清理宽限。清理失败不会产生成功的效果证明。
  此项是本地回归，不等于已完成三库生产取消/并发验收或证明取消后远端立即无活动。

## 已接通的业务链路

| 环节 | 本批代码行为 | 仍需注意 |
| --- | --- | --- |
| 普通诊断 | 模型提交严格 Claim：对象、时间、事实/解释/原因、支持/反证字段、替代解释与限制；服务端校验行/字段和信任 | 引用有效不等于自动证明因果；尚无通用身份关联和时间适配引擎 |
| SQL 诊断 | 先执行原 SQL 专项身份与证据校验，再投影为同一调查记录 | 非直接事实保守保留为解释，不从自由正文猜出“已确认原因” |
| 回答 | 先校验、冻结，再确定性渲染与推送正文；模型失败保留证据并输出部分结论 | 直接 Top N 仍用确定性列表，不被历史单 SQL 问题劫持；专项降级画像未冒充完成诊断 |
| 报告 | 从冻结记录无损投影分析、方案及引用；旧正文原样保留，不反向制造 Claim；空正文/缺引用不默认为 READY | 多轮按时间保留；没有修订关联时不取历史最高等级拼成根因 |
| 会话案例候选 | 最新结构化调查中有可追溯有效事实或支持判断即可提炼诊断参考，不再要求 CONFIRMED 或先有正式报告 | 校验记录与 Run/Target 一致；最新记录撤回、仅假设或缺失时不倒查旧肯定结论 |
| 人工收口与报告提炼 | 人工材料仍是 USER_PROVIDED/USER_REPORTED；READY、恢复勾选、不同前后引用不能自动产生 VERIFIED | 新效果报告可追溯且可复算，LIMITED 归因不自动授予正向 VERIFIED 用途 |
| 权限与支持强度 | 配置只读通道不再推定 Oracle 任意字典权限、PG/MySQL 视图或变更能力；模型 DIRECT 与来源数量不自动确认根因 | 只读目录允许 UNKNOWN 访问候选；商业许可硬门禁不变，实际访问由目标库反馈 |
| 指标发现 | `monitor.discover_metrics` 从规划、冻结、任务到 Prometheus Adapter、证据和后续规划接通 | 只有显式授权的绑定可用；不是开放全局指标目录 |

## 持久化和合同边界

新增严格内部合同 `DBA_DIAGNOSTIC_ASSESSMENT.v1` 和 `DBA_INVESTIGATION_RECORD.v1`。
记录嵌入已有 `AIOPS_TURN_RESULT.v1.investigation_record`，由现有不可变 Artifact
保存，不新增表或运行时 Schema 自检；复用反馈增加两端公共/内部路由及 OpenAPI，
没有为调查记录另建外部接口。独立问题从 revision=1 开始；
服务端重新授权上一轮冻结结果，且模型显式继续同一调查时，连续增加 revision，
以确切 Artifact/哈希关联父版本。授权、Target 版本或来源变化会阻止继承。
修订必须同对象、同时间阶段；反驳必须有本轮证据，不按相似文本自动合并。
普通诊断和 SQL 专项共用逐目标状态，顶层完成度由冻结后的全部目标决定。
报告当前视图排除显式被修订的旧判断及关联建议，历史版本和修订关系仍可追溯。
execution/verification 引用现可关联冻结业务计划及窗口实测；周期快照自动验证不代表因果实验。

记录冻结原问题、Run/Task/Target、观测身份/时间/口径/信任、判断、建议和本轮目标状态。
报告再次校验证据集合与封套。人工材料不会因报告、审核或案例提炼升级为现场观测。
同源证据未知映射时按目标保守归组；严格差分原语与有界公式图已进入窗口 SQL
证据、调查/报告及效果复算，尚未完成原生计数器级映射与跨源物理身份图。

两平台的必要实现差异保留：Ammolite UUID 与 KBot 字符串标识、各自数据库/UoW、
Portal 与静态 AIOps 页面；业务语义一致。无需本批线上 DDL。

## 指标目录发现的启用与限制

Prometheus Adapter 新增 `metric.discover`。管理员须按既有诊断源/绑定治理流程，
在来源 `declared_capabilities` 声明该能力，并在目标绑定
`capability_scope.capabilities` 中显式限定授权；
本批不自动修改旧配置，也不暗示“升级后所有绑定自动启用”。
它与 `metric.query_range` 是不同能力；后续数值查询仍需已有查询授权。

定位只来自已冻结绑定，不接受模型指定 URL、任意 selector 或其他 Target。
数据库范围使用精确的 instance/target_key 定位；主机范围只使用已绑定 host_target_key。
返回指标名与标签名，不返回标签值；通过目标限定 targets/metadata 读取类型/help/单位，
不可核验或冲突时保持 UNKNOWN/CONFLICT，不猜单位。

每轮最多一个发现动作，各授权绑定独立限额；窗口 60–3600 秒、默认 900 秒；
默认 50、最多 100 个指标，
处理最多 1000 条系列、每指标最多 128 个标签名；生产执行响应默认上限 256 KiB。
达到目录上限或源警告标截断；字节超限、无权限或来源失败形成缺口，不当空成功。
目录证明请求窗口曾可见，不证明当前有采样，更不是性能数值。

## 未交付的设计范围

- 多目标物理身份关联与语义质量验收；S1 不声称按文本可自动证明同一故障阶段。
- 原生计数器细粒度映射、跨源物理身份关联、对象级权限探测缓存；
  已有公式图不等于任意分布/趋势计算或未核验跨源单位换算全部可用。
- OEM 按真实部署版本的目录/长尾查询；Zabbix 未提供任意趋势聚合或无限分页。
- 周期采集之外的按需追加采样、控制实验或隔离归因、三库生产实测及正向 VERIFIED 案例全链。
- 真实语义模型漏报/误报验收，以及跨系统外部订阅者的撤回传播；
  当前已实现 Registry 后台暂停与站内通知，不等于任何外部消费者都会主动刷新缓存。
- 真实三库/模型/UI验收与并发、取消、预算、P95 时延验证。

这些缺口对应设计 P0 的剩余部分及 P1/P2；不能将“已能生成带引用的回答”
等同于“所有 DBA 问题均可诊断并解决”。

## 业务效果验证操作与来源要求

当前诊断结果中的 Proposal 卡片展开“业务效果验证”（需管理变更权限且为原调查操作者）。
先从平台已采集的周期快照生成当前 Target 的窗口报告，选择真实基线和可得指标，
至少配置主要效果、护栏、负载可比性及停止条件，再冻结计划。
只能在审批或执行前冻结，之后不能通过改条件把失败改成成功。
默认勾选自动验证时，必须已有启用的周期快照；动作复核完成后后台等待观察窗口，
自动生成报告。也可在冻结前选择手动验证，之后选择新的窗口报告和该 Proposal 的
动作只读复核，点击复算并查看正式报告。复核来自独立验证 Run，而非只查原诊断 Run。
原生指标按指标族、代码、维度及核验单位区分；指定 SQL 保留库、用户、顶层及可得计划身份，
不把同一 query_id/SQL_ID 的不同统计主体混为一条。

该入口不会执行变更，不安装扩展、不授予目标库权限，也不自动开启采集。
自动任务状态与错误类别在同一入口回看；无额外接口或新表。
动作复核沿用 `action-effect.v1`；业务效果使用严格的冻结合同及 `business-effect.v1`，
不能混用、追加任意字段或事后调整条件。
Oracle 的工作负载/差异报告明确为平台周期快照（非 AWR），未增加 Oracle 活动报告或冒充 ASH。
PostgreSQL 新增只读 `db.postgresql.workload.identity`，使用本轮 pg_control_system()
system_identifier、数据库 OID 与 pg_postmaster_start_time() 核验身份。
目标凭据缺相应权限时记录明确缺口，不回退旧能力探测值，不自动 GRANT。
MySQL 同样只使用本轮 server_uuid/Uptime；实例、重置/淘汰、版本和单位变化、
失败/漏采快照均不得被串接成成功窗口。没有已采集历史就不能生成过去的窗口。

效果、症状、护栏与归因分别保存。业务量下降、缺失 SQL、窗口不完整不能当作优化；
逐 SQL/负载/原生指标保存有效覆盖时间，采样时长用 Decimal 累加。
所选信号缺少任一时段阻断比较；无关 SQL 淘汰或指标缺样本不抹去完整信号。
来源绑定未变但 Agent 当前已移除该来源权限时，同样拒绝复用旧证据。
已观测到 ADVERSE 或护栏退化不能被其他缺口覆盖。
人工执行回执保留 USER_PROVIDED，即使后续指标由系统读取也不变成 Agent 自动执行。
观察性结果最多为 LIMITED 归因，仍不能直接发布 VERIFIED_* 成功案例。
正式报告保存计划、基线、之后窗口、复核、回执、比较结果六类来源、冻结模板及可读数值，
复算可重复进行但不覆盖历史报告；读取和重放都重验授权与哈希。
同 Target 的本人窗口报告可跨 Agent 复用，但必须重验 Target 版本及当前 Agent 权限；
其他诊断证据仍按原 Agent/Run 边界，不扩大机器主体的 Agent 白名单。

## 继续完成全设计所需的外部条件

OEM 长尾适配需要真实部署版本、已授权目录接口及响应样本，不能猜测版本接口。
跨源物理身份与细粒度计数器血缘需要实际 Exporter/监控绑定的映射证据，不能由指标同名推定。
外部消费者撤回传播需要订阅者合同、接收方及交付确认机制；
只发站内通知不能当作外部缓存已清除。
真实三库、真实模型、浏览器、受控执行/回退及并发验收需要明确隔离环境与操作授权；
不得因“继续实现”而对线上自动做 DDL、故障注入、改权限、发布 Prompt 或重启。
这些条件以及上列本地未交付能力全部闭合前，整体设计仍为未完成。
