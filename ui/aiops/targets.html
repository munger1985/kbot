运维目标

管理数据库目标的监控、只读诊断和人工审批后受控变更边界。

通过业务系统新增成员

新增运维目标

步骤 01

目标身份与责任归属

先明确数据库身份、重要级与责任组，后续工作项将按责任归属路由。
仅列出已完成端到端验证并绑定固定诊断 SQL 的版本。
工作项按运维目标的责任归属路由；Agent 只定义可运维范围。

步骤 02

监控接入

绑定监控源和稳定 Label，Target 必须至少保留一条有效映射。

监控源与 Label 映射

Target 必须至少绑定一条有效监控映射；Agent 会从 Target 自动继承监控能力。

必填
尚未绑定监控源
填写监控系统中唯一标识当前数据库的值。

数据库 Label（必选）

选择监控源后发现数据库候选。

主机 Label（Prometheus 必选）

发现后选择数据库所在主机。

步骤 03

数据库接入

选择仅监控、只读诊断或受控执行；所有凭据保存后均不回显。

数据库访问与变更边界

Target 默认仅使用监控证据；数据库写操作必须在这里显式开启。

仅监控
Service Name 只负责路由连接，不能据此推断 CDB 或 PDB。
连接检查会核验实际容器，范围不一致时禁止启用。
填写预期 PDB Name；系统会与实际 CON_NAME 比对。

Oracle Pack 授权声明

请核实合同后声明；数据库权限或参数不代表已获许可。AWR/ASH 需要 Diagnostics Pack，SQL Monitor 还需要 Tuning Pack。

历史 SQL 快照

启用后周期采集只读统计，历史 Top SQL 至少需要两次有效快照。Oracle 使用 V$SQLSTATS，不使用 AWR。

诊断凭据仅通过 Main API 提交给 AIOps 加密凭据存储，列表和详情不会返回密码明文。

运维记忆

维护已确认的 ASM 磁盘组、数据文件路径和表空间放置策略。
