# KBot AIOps 数据库运维手册

本文档是 AIOps 固定知识库的基础手册，适用于 Oracle、MySQL 和 PostgreSQL。诊断结论必须以目标数据库的实时证据为准；手册用于解释证据、规划检查顺序和约束变更风险，不能替代现场数据。

## 通用处置原则

1. 先确认影响范围、开始时间、业务症状和最近变更，再执行技术诊断。
2. 首轮只执行只读检查。任何 DDL、DML、会话终止、参数修改、主备切换或服务重启都必须形成变更建议，并经过策略和人工审批。
3. 保存查询时间窗口、实例、数据库、会话、SQL 标识和监控来源，使证据可以复现。
4. 区分相关性和因果性。单个高值指标只能形成线索，根因需要等待事件、资源饱和、执行计划、日志或变更记录相互印证。
5. 处置后必须验证业务指标、数据库指标、错误日志和持续时间，并记录回滚条件。

## 故障分级

- P1：数据库不可用、核心业务全面失败、数据安全或一致性存在现实风险。
- P2：关键业务明显降级、连接或延迟持续恶化，但仍有可用路径。
- P3：局部性能下降、容量风险、非核心功能异常。
- P4：趋势告警、配置建议和日常巡检发现。

## 通用诊断顺序

### 可用性与连接

- 验证监听端口、DNS、TLS、认证和连接池错误，区分网络拒绝、超时、账号锁定和数据库拒绝。
- 检查实例状态、主备角色、只读状态、恢复状态和最近启动时间。
- 对连接数达到上限的场景，确认连接来源、空闲连接、泄漏趋势和连接池配置，禁止直接提高上限掩盖泄漏。

### 负载与等待

- 对齐 CPU、内存、存储延迟、网络、数据库吞吐和活动会话时间线。
- 识别主要等待类别、阻塞链和热点对象；不要只按 SQL 总耗时排序。
- 比较故障窗口与正常基线，区分负载增长、执行效率下降和基础设施抖动。

### SQL 与执行计划

- 记录 SQL 标识、执行次数、平均及尾延迟、逻辑读、物理读、返回行数和计划版本。
- 检查统计信息变化、绑定变量选择性、索引可用性、计划漂移和并行度变化。
- 优化建议必须说明适用条件、预期收益、风险、回滚和验证方法。

### 存储与容量

- 同时检查数据库空间、文件系统、临时空间、事务日志和归档空间。
- 容量预测使用增长速率和业务周期，不能只根据当前百分比判断。
- 空间告警处置前确认自动扩展、最大文件大小、存储配额和备份保留策略。

## Oracle

- 可用性：监听器、实例状态、PDB 打开模式、Data Guard 角色及应用延迟。
- 性能：AWR/ASH 或实时活动会话、等待事件、阻塞链、SQL Monitor、执行计划和对象统计信息。
- 容量：表空间、临时表空间、UNDO、FRA、归档日志和 ASM Disk Group。
- 日志：Alert Log、监听日志和相关 Trace。ORA 错误需保留错误码、时间、容器、实例和邻近上下文。
- 高风险动作：`ALTER SYSTEM`、终止会话、切换日志或主备、数据文件操作和补丁操作必须审批。

## MySQL

- 可用性：实例状态、连接错误、复制拓扑、只读状态和 Group Replication/InnoDB Cluster 状态。
- 性能：Performance Schema、慢查询、等待事件、锁等待、Buffer Pool、临时表和执行计划。
- 容量：数据目录、二进制日志、Relay Log、Undo、临时目录和表增长。
- 复制：延迟需结合事务队列、并行复制、网络和大事务判断，不能只看 Seconds_Behind_Source。
- 高风险动作：`KILL`、参数持久化、复制重配、日志清理和在线 DDL 必须审批。

## PostgreSQL

- 可用性：实例状态、连接槽位、恢复状态、复制槽、WAL 接收和回放延迟。
- 性能：`pg_stat_activity`、`pg_stat_statements`、锁等待、缓冲命中、临时文件、检查点和执行计划。
- 容量：数据目录、WAL、表及索引膨胀、复制槽保留和临时空间。
- 维护：评估 Autovacuum、冻结年龄、无效元组和统计信息；禁止在高峰期直接执行不可控的 `VACUUM FULL`。
- 高风险动作：终止后端、参数重载或重启、复制槽删除、主备切换和结构变更必须审批。

## Alert Log 与日志证据

- 日志通过 Loki 等诊断源进入 AIOps，不直接把服务器文件路径暴露给 Agent。
- 原始日志保留在日志系统；AIOps 保存时间窗、标签、查询条件、内容哈希和受限摘要。
- 同一错误重复出现时应聚合计数和持续时间，同时保留首次、最近一次和状态恢复事件。
- 密码、Token、连接串、个人信息和业务数据必须在进入模型前脱敏。

## 变更和验证模板

每个变更建议至少包含：目标、前置条件、命令预览、影响范围、风险等级、回滚步骤、验证查询、授权有效期和证据引用。执行完成后比较变更前后业务错误率、响应时间、数据库等待、资源使用和日志错误；验证失败立即停止后续动作并执行回滚或升级人工处理。

## 日常巡检

- 检查实例和复制可用性、备份新鲜度、恢复可验证性、容量趋势、错误日志和证书期限。
- 检查高延迟 SQL、阻塞、失败任务、长事务、统计信息与维护任务。
- 巡检报告区分事实、风险、建议和待补充证据，不把推测写成已确认故障。
